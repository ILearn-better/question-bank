## 二、可复现的搭建步骤

```bash
cd question-bank
```

## 三、本次遇到的坑（重点）

### 坑 #1 · pip 直连 PyPI 会「静默卡死」——最耗时间的一个

**现象**：`pip install -r requirements.txt` 跑了 **12 分钟，0 个包落地，日志全空**。看起来像在下载，实则什么都没发生。

**原因**：本机所有网络走本地代理（`HTTP_PROXY=http://127.0.0.1:<port>`），pip 直连 PyPI 被拖死。
加 `--no-cache-dir` 反而更慢（失去缓存复用）。

**解法**：换清华镜像。同一份 `requirements.txt`，**1 分 7 秒装完**。

```bash
./.venv/Scripts/python.exe -m pip install -r requirements.txt \
    -i https://pypi.tuna.tsinghua.edu.cn/simple --progress-bar off > .pip_install.log 2>&1
```

> 例外：装 Paddle 系（`paddlepaddle` / `paddleocr`）时清华源**没有**这两个包，
> 必须走官方源 `-i https://www.paddlepaddle.org.cn/packages/stable/cpu/`。

### 坑 #2 · 别把 pip 输出管到 `tail`

**现象**：`pip install ... | tail -25` 中间完全看不到进展，一度让人误以为命令挂死。

**原因**：管道会把输出缓冲到**命令结束**才吐出来。

**解法**：重定向到日志文件，需要时 `cat` / `tail` 日志文件本身。

```bash
... > .pip_install.log 2>&1     # 然后随时 cat .pip_install.log 看进展
```

### 坑 #3 · 没有 `.venv` 时，双击 bat 必卡

**现象**：新机器直接双击 `启动拾课.bat`，停在一句「没找到虚拟环境，先照 README 装依赖」。

**原因**：bat 写死 `backend\.venv\Scripts\python.exe`；而 README 原来的「手动启动」段只写了 `pip install -r requirements.txt`，**漏了建 venv 这一步**。

**解法**：① 按上面步骤建 venv；② 已在 `README.md` 补了「新机器首次准备：创建虚拟环境」小节，避免后人再踩。

### 坑 #4 · 验证 venv 是否生效，别查进程映像路径

**现象**：用 `QueryFullProcessImageName` / WMI 查服务进程的 `ExecutablePath`，显示的是**基础解释器**路径（如 `...\python\versions\3.13.12\python.exe`），看不出 venv，容易误判成「venv 没生效」。

**原因**：Windows 下 `.venv\Scripts\python.exe` 只是个**启动器**，实际转交给基础解释器运行。这是正常现象，不是故障。

**解法**：让 venv 的解释器**自报** `sys.prefix`。

```bash
./.venv/Scripts/python.exe -c "import sys; print(sys.prefix)"   # 期望输出项目 .venv 路径
```

### 坑 #5 · `backend/` 下 `import alembic` 是假阳性

**现象**：在 `backend/` 目录下执行 `python -c "import alembic"` 居然成功，误以为依赖已装好。

**原因**：`backend/alembic/` 是**迁移目录**，被 Python 当成命名空间包顶替了真正的 `alembic` 库。

**解法**：验证依赖时**把工作目录换到项目外**（或用 `sys.path.insert` 显式指定），再测。

```bash
cd <项目外> && <项目>/backend/.venv/Scripts/python.exe -c "import alembic; print(alembic.__file__)"
```

### 坑 #6 · 本机删除文件的手段全部静默失效（通用陷阱）

| 手段 | 实测结果 |
|---|---|
| bash `rm` / `rm -v` | 返回 exit 0，但**不删任何文件、也不报错**（shim 是空实现） |
| PowerShell `Remove-Item` | 整个 PowerShell 工具本机**已不可用**：调用直接 exit 1 且无任何输出 |
| `wmic` | 被安全策略**硬拦**：`PROGRAM BLOCKED BY SECURITY POLICY`，不可重试、不可绕过 |

**唯一可靠做法**：写临时 `.py` 用 `os.remove` / `shutil.rmtree`，跑完把自己也删掉。

```python
import os, shutil
for f in ('temp1.py', 'temp2.log'):
    if os.path.exists(f): os.remove(f); print('removed:', f)
if os.path.isdir('somedir'): shutil.rmtree('somedir'); print('removed dir: somedir')
```

### 坑 #7 · 多层引号的 `python -c` 一律改写成 .py 文件

**现象**：Git Bash 里 `python -c "...\"...\"..."` 这种嵌套引号极易解析失败，尤其带 JSON 或中文路径时。

**解法**：直接把逻辑写成临时 `.py` 文件再执行，比调试转义省事。用完按坑 #6 的方式删。

## 四、通用结论（可迁移到本机任何项目）

1. **装依赖永远带国内镜像**，并重定向到日志文件而不是 `tail`。
2. **删文件写 Python**，不要用 `rm` / PowerShell。
3. **验证 venv 用 `sys.prefix`**，不要查进程路径。
4. **复杂命令写 `.py` 文件**，不要硬堆引号。

> 以上通用条目已固化为用户级技能 `local-env-traps`，本机任意项目遇到同类现象可直接套用。
