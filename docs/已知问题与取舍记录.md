# 已知问题与取舍记录

> 这份文件只干一件事：把**已经查清、评估过、然后决定不做**的问题记下来。
> 目的不是记账，是**避免重复讨论** —— 下次有人（包括 AI）再提同一个问题，
> 先看这里有没有结论，别从头再分析一遍。
>
> 与之配套的两类文件：
> - 想做但还没排期的功能 → 各自的「方案（想法记录）」文档（如 `学生作业上传与评分方案.md`）
> - 每个问题**当时的实测证据**要写进结论里，否则过几个月没人敢信这个判断

---

## 记录格式

```
### 问题一句话
- 影响：最坏会怎样，量级多大
- 现状：YYYY-MM-DD 实测（怎么测的、结果）
- 判断：做 / 不做，一句话理由
- 如果将来要做：第一条该走什么路（不是完整方案，是「从哪下手最划算」）
```

### 反馈配图会留下「没主的文件」（2026-09-28）

**问题**：反馈弹窗里的配图是**先落盘、后登记**——贴图时文件立刻写进
`students/<学生>/<日期>/`，但数据库里要等点了「保存反馈」才有引用。
所以「贴了图 → 没保存 → 弹窗没了」会留下一张谁也找不到主人的图。

**影响**：很小。最坏就是几十 KB 的图躺在硬盘上，界面看不见、资料清单里也没有，
只有翻文件夹才会发现。不影响任何功能，不占用户注意力。

**现状（2026-09-28 实测，扫全库比对磁盘）**：

- 学生归档目录下**孤儿文件 0 个**。
- 全 `uploads/` 有 27 个「全库搜不到」的文件，逐个看过都不是这个问题：
  6 个 `*_反馈.txt` / `*_作业.txt` 快照（**故意不入库**，见下）、
  20 个 `pages/`（PDF 页渲染缓存，按需重建）、
  10 个 `crops/`（框选截图，属于录题模块，其中有 3 张 0 KB 的坏上传）。
- 会漏的具体路径：**F5 刷新、关标签页、崩溃/断电**。
  取消 / × / Esc 都有人管（`FeedbackDialog.js` 的 `onBeforeUnmount` 会删掉刚贴的图）；
  但那几条删除请求是异步不等待的，卸载后立刻关标签页也可能被掐断。

⚠️ **将来任何「扫孤立文件」的逻辑都必须放过 `*_反馈.txt` / `*_作业.txt`。**
这两种快照是**故意不写数据库**的（见 `3cf5ec5`），做白名单式删除时漏了它们，
删掉的就是用户自己的档案。反过来说：**不认识的目录/文件名一律放过**，宁可不删。

**判断：不做。** 0 次发生、要凑齐「贴图 + 不保存 + 顺手 F5」、后果只是占地方；
而两个候选方案都各有代价（见下），收益撑不起改动。

**评估过但否掉的两个方案**：

1. **推迟落盘**（贴图只显示浏览器本地 `blob:` 地址，点保存时才真上传）
   —— 能根治，让中间态根本不存在，还能顺手删掉关窗清理那两段代码。
   否掉的理由：要改保存流程（先传图、再 PUT 反馈），而「图传成功、存反馈失败」会引入
   一个**新的**孤儿窗口；为一个小问题把风险挪进主流程，不划算。
2. **启动时扫孤儿**（扫 `students/`，列出「磁盘有、库里没有」的，设置页点一下才清）
   —— 能兜住历史与将来的所有写入路径。否掉的理由：要养一套**删文件**的逻辑，
   还带上面那个「必须放过 txt 快照」的暗礁；现在一个孤儿都没有，属于自找风险。

**如果将来要做**：先上最便宜的那一步 —— 在 `pagehide` / `beforeunload` 时用
`navigator.sendBeacon()` 把「还没保存的图」的 URL 发出去删。不用等异步请求返回，
浏览器负责送达，5 行左右，挡住最常见的 F5 与关标签页两种情况。
真攒出量了（比如翻文件夹发现十几张没主的图）再谈推迟落盘。
