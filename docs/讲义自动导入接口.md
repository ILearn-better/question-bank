# 讲义自动导入：给 agent 调用的接口

> 目标：**把一份讲义交给 agent，它自己跑完录入 → 检查 → 问题处理 → 无误入库。**
> 人在界面上做同样的事要点十几次，这里是一条命令。

已实现（2026-10-23）。代码：`backend/app/services/auto_import.py`（编排）、
`backend/app/routers/auto.py`（接口）、`backend/auto_import_cli.py`（命令行）。

---

## 一、最省事的用法：命令行一条

```bash
cd backend

# 看看有哪些体系可选（第一次用先跑这个）
.venv/Scripts/python.exe auto_import_cli.py --list-curricula

# 交给它，等到跑完
.venv/Scripts/python.exe auto_import_cli.py 讲义.pdf --curriculum 国内高中数学

# 只处理前 20 页
.venv/Scripts/python.exe auto_import_cli.py 讲义.docx -c cn-senior-math --pages 1-20
```

结束时会打印一份摘要：

```
==================================================================
讲义：讲义.pdf
体系：国内高中数学
页数：44/44   用时：1820 秒
结果：共 87 条 → 已入库 79，待人工 6，跳过 2

--- 需要你看一眼的 6 条 ---
  第 12  页  第 4   条  要配图，但这页有几处图形，判不出哪一处是本题的
  ...
处理完再执行：python auto_import_cli.py --resume <task_id>
==================================================================
```

### 退出码（这就是结果，脚本直接看它）

| 码 | 含义 | 该怎么接 |
|---|---|---|
| **0** | 全部入库，没有遗留 | 继续下一份 |
| **2** | 跑完了，但有几条要人看 | 停下来找人，报告里有直达链接 |
| **1** | 失败（服务没起 / 文件不认 / 后台出错） | 看 stderr |

「跑完了但有 5 条要人看」和「跑完了干净」在自动化里是完全不同的结局，所以分成 2 和 0，
而不是让调用方去解析 JSON。

## 二、HTTP 接口（agent / 其它程序用）

服务默认 `http://127.0.0.1:8000`（`SHIKE_BASE` 可覆盖）。

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/auto/curricula` | 可选体系。**第一步调它** —— 体系是必填的 |
| POST | `/api/auto/import-path` | **推荐**。传本机路径，立刻返回 task_id |
| POST | `/api/auto/import` | 同上，但走 multipart 上传 |
| GET | `/api/auto/imports/{id}` | **轮询这个**。`done=true` 就停 |
| POST | `/api/auto/imports/{id}/resume` | 人处理完之后，补入库（不重新识别） |
| GET | `/api/auto/imports` | 历史任务列表 |

```bash
# ① 起任务
curl -X POST http://127.0.0.1:8000/api/auto/import-path \
  -H "Content-Type: application/json" \
  -d '{"path":"D:/讲义/第三章.pdf","curriculum":"cn-senior-math","pages":"all"}'
# → {"id":"83b5d9425968","status":"queued","done":false,...}

# ② 轮询（一般 5 秒一次）
curl http://127.0.0.1:8000/api/auto/imports/83b5d9425968
# → {"status":"done","done":true,"ok":true,"counts":{...},"report":{...}}
```

`curriculum` 认三种写法：`3`（id）、`cn-senior-math`（code）、`国内高中数学`（名称）。
认不出时返回 422 并**列出可选项** —— 刻意不做「自动判断体系」：
一份卷子一套体系，猜错是整批知识点挂到错误的树上，而那种错不报错、只在出卷时发现。

`pages` 不传 = 全部页。支持 `1-30,35`（中文逗号也认）。

## 三、报告怎么读（`report` 字段）

```jsonc
{
  "counts": {"total": 87, "approved": 79, "needs_human": 6, "skipped": 2},
  "reasons": {"figure_ambiguous": 4, "no_content": 2},
  "needs_human": [
    {
      "item_id": "c93b3005cb44",
      "page_no": 12, "seq": 4,
      "reason": "figure_repair_failed",
      "message": "这页有 14 处图形候选，挑不出唯一说得通的那一处",
      "open":      "/batch.html?job=034f4e492489",                       // 人能点
      "fix_with":  "POST /api/batches/items/c93b3005cb44/figure-crop",   // agent 能调
      "candidates":"GET /api/batches/items/c93b3005cb44/figure-candidates"
    }
  ],
  "skipped": [ /* 模型这页确实没读出题，连人都不必看 */ ],
  "approved_question_ids": ["c409d85df13e", "..."],   // 入库的题目 id，可直接引用
  "next": "6 条需要处理：打开 /batch.html?job=... 逐条看；处理完再调 .../resume 收尾入库。"
}
```

`next` 就是给 agent 的下一步指令，不用它自己拼。

## 四、什么会自动入库，什么会留给人

**自动入库只收零疑点的条目**（拿不准就不入库 —— 错题会一路印到发给学生的卷子上；
而「少入库一条」老师看报告就知道是哪条）：

| 情况 | 处理 |
|---|---|
| 有配图且无怀疑标记 | ✅ 直接入库 |
| 明确不需要配图 | ✅ 直接入库 |
| 配图定位不到 → 已裁「整题原貌图」 | ✅ 直接入库（出卷按图片印） |
| 配图框是模型估的 / 和别的题抢同一处 / 跨页 | 🔧 先自动重裁，修好再入库 |
| 要配图但没图 | 🔧 先自动重裁 |
| 同一页有 2 处以上图形候选，挑不出唯一的那处 | 🙋 留给人看（**不猜**） |
| 题干空 / 模型返回的不是 JSON / 整页识别失败 | ⏭️ 跳过（模型这页确实没读出题） |

**自动重裁的判据**（`auto_import.pick_candidate`，纯函数、可单测）：

- 有原框：某个候选**包住**原框且面积 ≤3 倍 → 取最贴的那个（这是在修框，不是换图）
- 有原框：与某候选 IoU ≥ 0.6 → 同一处
- 有原框：与所有候选都不搭 → **放弃**（模型指错了位置，不替它猜）
- 没原框：只有候选**恰好一处**才选
- 跨页：本页有候选就只在本页挑；本页没有才看下一页，且下一页仍要唯一

一句话：**宁可不配，不能配错。** 配错了图会印到卷子上，少一张图老师一眼能看见。

## 五、几个会自动处理掉的事

- **超过 30 页**：`MAX_PAGES=30` 是单次识别上限（=AI 请求次数）。
  44 页会**自动拆两批**并串行跑，`auto_tasks.job_ids` 里是多条 job，报告里合并计数。
  agent 不需要自己分批。
- **Word 转页图**：`.docx` 要先导出 PDF。这个在**提交时就预检**（慢几秒），
  而不是等后台跑到第一页才报错 —— 否则 agent 等半天只拿到一句「读不到文档页面」。
- **文件会复制进 `data/uploads/`**：原文件不动。否则老师哪天移动了桌面上的讲义，
  库里的题就全变成「读不到原卷」。
- **事后补入库**：老师框完图调 `resume`，**不重新识别**（那要重花 AI 调用），
  只重扫条目、能过的入库。重复调是安全的（已入库的不会重复入库）。

## 六、给 agent 的提示词（复制粘贴就能用）

> 把这份讲义录入题库：`<文件路径>`
>
> 步骤：
> 1. `python backend/auto_import_cli.py --list-curricula` 看有哪些体系，**问我选哪个**
>    （不要自己猜 —— 猜错整批知识点会挂错树）
> 2. 跑 `python backend/auto_import_cli.py "<文件路径>" --curriculum <我选的> --json`
> 3. 看退出码：`0` 报告我入库了多少条；`2` 把 `report.needs_human` 逐条念给我
>    （页号、题号、原因），并告诉我审核页链接；`1` 把错误原样贴出来
> 4. 我处理完之后，再跑 `--resume <task_id>` 收尾，把最终数字告诉我

要点：`--json` 输出的是完整报告；`--status <task_id>` 可以随时查进度；
一份讲义要跑十几到几十分钟（44 页约 30 分钟），别用短超时。

## 七、实现要点（给改代码的人）

```
① 录入   batch_page.create_page_job + run_page_job        （识别，已有）
② 检查   batch_page.plan_page_figures                     （配图分配，识别时已算好）
③ 修图   routers/batches.crop_item_figure                 （**唯一**配图写入路径）
④ 入库   batch_import.approve_item                        （**唯一**入库路径）
```

`auto_import` 是**编排层**，不加任何新的识别/裁剪能力，只做三件事：
串流程、记阶段、写报告。

⚠️ ③④ 必须**调用**既有函数，不能重写一份。重写的后果不是报错，是漂 ——
「旧图按引用计数回收」「整题兜底图连带撤掉」「整题兜底要 `render_prefer=image`」
这些副作用漏一处就静默丢图。

⚠️ `DOUBT_FIGURE_FLAGS`（哪些配图标记算「还可疑」）的唯一出处是
`services/batch_page.py`，审核页、自动导入都从那里取。
前端 `batch.html` 的 `figTierOf` 是 JS 没法共享，靠 `frontend/batch_fig_check.js` 比对
—— 两边不同步会出现「界面说可放心、自动导入却不肯入库」这种自相矛盾。

## 八、测试

```bash
cd backend
.venv/Scripts/python.exe test_auto_import.py       # 48 项判据（不连库、不调 AI）
```

守的是「哪条能自动入库」这个最容易判错的地方。做过破坏性验证：
把「整题兜底」的判断挪到怀疑标记之后、多处候选时不再放弃、页范围写错静默当全部
—— 三处全被对应断言抓住。
