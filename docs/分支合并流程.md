# 分支合并流程（dev → main）

> 2026-10-28 定。以后说「合并 dev」都按这个顺序走，**不要跳步**。

## 一句话

**远端 dev → 本地 dev → 跑通 → 本地 main → 跑通 → 推送远端 main**

## 五个步骤

### 1. 拉远端 dev 到本地 dev

```bash
git checkout dev
git fetch origin --prune
git merge --ff-only origin/dev     # 落后就快进；分支已分叉时用 git merge origin/dev
git merge main                     # 如果 dev 还缺 main 上的修复，先补齐再测
```

### 2. 在本地 dev 上跑通

- 起两个服务（见下方「起服务」）
- 跑**全部**测试脚本（`test_visual.py` / `test_scanned.py` 除外 —— 它们往真库写数据且不清理）
- **全绿**才进入下一步；红了先修，不要带着红灯合并

### 3. 合并到本地 main

```bash
git checkout main
git merge --no-ff dev -F _commitmsg.txt
```

> 提交信息写文件再用 `-F`，别用 `-m` 传长中文（编码容易坏）。

### 4. 在本地 main 上再跑通

- ⚠️ **先重启 8000**：合并只改文件，已在跑的 uvicorn 还是旧代码，拿它跑测试等于没测
- 再跑一遍全套

### 5. 推送远端 main

```bash
git push origin main
```

如果第 1 步时在 dev 上产生了本地提交（例如修测试），记得 `git push origin dev`。

## 每一步都别省的检查

| 时机 | 检查 |
|---|---|
| 动手前 | `git status --short --branch` 确认**当前分支**（曾误在 dev 上操作） |
| 合并前 | `git merge-tree --write-tree --name-only A B` 只读试算冲突 |
| 合并前 | 看 `backend/requirements.txt` 与 `backend/alembic/versions/` 的 diff |
| 跑测试前 | 清环境变量（见下） |
| 跑完测试 | 对账：关键表计数跑前跑后一致 |

## 起服务

```powershell
# 8000：真库（先确认端口空闲，旧进程要停掉）
cd backend
.\.venv\Scripts\python.exe -m uvicorn main:app --host 127.0.0.1 --port 8000

# 8001：隔离库 + 隔离数据目录（路径写死在测试里，不能改）
$d = "$env:TEMP\notes_scratch"
$env:SHIKE_DATA_DIR = $d
$env:SHIKE_DB_PATH  = "$d\notes.db"
.\.venv\Scripts\python.exe -m uvicorn main:app --host 127.0.0.1 --port 8001
```

## 跑测试的规矩

```powershell
# 必须先清 —— PowerShell 是持久会话，之前设的 SHIKE_* 会被继承，
# 症状是测试把图造到 scratch、服务却读 backend/data，4 个接口测试集体假红
Remove-Item Env:SHIKE_DATA_DIR, Env:SHIKE_DB_PATH -ErrorAction SilentlyContinue

cd backend
$skip = @("test_visual.py","test_scanned.py")
Get-ChildItem "test_*.py" | Where-Object { $skip -notcontains $_.Name } |
  ForEach-Object { .\.venv\Scripts\python.exe $_.Name; if ($LASTEXITCODE -ne 0) { "FAIL $_" } }
```

- **不要用 pytest** 收集：这些是自跑脚本（模块级 `raise SystemExit`），pytest 会 INTERNALERROR
- 判据是**退出码**，不是输出里有没有 ✅
- 脚本数量会随 dev 增长，用 `Get-ChildItem test_*.py` 自动发现

## 判断服务是否活着

看端口，不要信终端状态（工具终端被回收后进程可能仍在跑）：

```powershell
Get-NetTCPConnection -LocalPort 8000 -State Listen
```

## 收尾

- 关掉 8001；8000 保留运行（用户日常用）
- 清临时目录：`%TEMP%\notes_scratch`、`%TEMP%\shike_*_scratch` 等
- 确认 `8000` 跑的是**合并后的新代码**（必要时重启一次）
