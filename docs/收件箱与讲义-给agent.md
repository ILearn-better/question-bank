# 收件箱与讲义：给 agent 的两份约定

> 这份文档的读者是 **agent**（以及以后回来查的自己），不是老师。
> 网页上（`题库文件` 那一页）刻意**只留「同步 / 导出」两个按钮** ——
> 收件箱怎么用、讲义怎么起头，都是 agent 要照着做的事，摆在界面上只会让老师
> 以为「拖进去还得点一下」。
>
> 用户 2026-11-23 的原话：「这个部分，不是给前端用的不用放前端，是给 ai 用的。」

---

## 一、收件箱（把卷子 / 别人转出来的 md 变成题目）

目录：`<vault>/收件箱/`（`vault.INBOX`）。两个归档子目录：`_已处理/`、`_失败/`。

| 丢进去的东西 | 走哪条路 | 花不花 AI 额度 | 之后源文件 |
|---|---|---|---|
| `.pdf` / `.docx` / `.png` … | **必须先放进以体系命名的子目录**：`收件箱/cn-senior-math/x.pdf` | 花（整页识别，一页一次） | 跑完挪进 `_已处理/` |
| 插件转出来的 `.md` | 放哪儿都行（不用子目录），知识点来自 frontmatter | **不花**（纯本地解析，几毫秒） | 进去题 → `_已处理/`；一道没进去 → `_失败/` |

为什么 PDF 必须认子目录：体系决定知识点挂哪棵树，猜错了**不会报错**，
只在出卷时发现「知识点全对不上」。所以宁可报一句「挪进子目录」。

**后台每 20 秒自己跑一轮**（`vault_inbox.POLL_SECONDS`），不用谁去点。
要立刻跑、或要看队列，用接口：

```bash
# 一眼看：待处理的文件 / 正在识别的任务 / 可用的体系
curl -s --noproxy '*' http://127.0.0.1:8000/api/vault/inbox

# 别等了，现在跑一轮（status 里已有的文件不会重来）
curl -s --noproxy '*' -X POST http://127.0.0.1:8000/api/vault/inbox/run
```

`SHIKE_VAULT_INBOX=0` 会关掉后台轮询（测试里就这么干的）。

⚠️ **讲义（`shike: lecture`）进了收件箱也不会被搬走**：它是一篇要留着的笔记，
不是待拆的卷子。`_ingest_one` 只回一句「留着不用搬，点同步」。
（以前不挡这一条，讲义会被按 `---` 切段，把知识部分也切进题干。）

## 二、讲义 md：一份笔记里既写知识、又放题目

老师 2026-11-23 的需求：「划分知识和题目部分，知识部分不会被题库识别，
能够正常将题目导入题库……既能够在笔记中显示，也能将其中题目导入题库。」

模板在 `<vault>/讲义/讲义模板（照这个写）.md`（`POST /api/vault/seed-template` 生成，
已经存在就不覆盖）。格式定义在 `services/vault.py` 的「讲义（知识 + 题目）」一节。

```markdown
---
shike: lecture                  ← 唯一判据。没有这一行，这篇就是普通笔记，一个字符都不扫
knowledge: [棱柱的结构特征]      ← 可选：整篇的默认知识点（题块没有自己的字段，全继承）
tags: [讲义]
---

## 知识点

### 一、棱柱                       ← 二级/三级标题随便写，都在 `## 题目` 之前，永不解析

## 题目                          ← 题目小节起点（也认 练习 / 习题 / 例题 / Exercises / Problems）

### 题目 1                        ← 每道题 = 一个三级标题；标题文字**不进题干**
<!-- shike_id: xxxxxxxxxxxx -->   ← 首次同步自动写回，是这段的身份，别手改
题干……

#### 答案
B

### 题目 2
……
## 小结                          ← 再出现一级/二级标题 → 题目小节到此结束
```

四条必须记住的规则：

1. **只有 `shike: lecture` 的 md 会被这样扫描。** 显式声明，不嗅探 ——
   「正文里有 `## 答案` 就当题」会把老师自己的笔记吸进题库，那是不可逆的。
2. **`## 题目` 之前的内容一个字符都不解析。** 这就是「知识部分不会被识别」的实现。
3. **题内允许 `#### 答案` / `#### 解析`，也认 `### 答案`**（`ANS_HEAD` 现在收 2~4 级）。
4. **块里的 HTML 注释在解析前整段去掉。** 老师在注释里写「这里该配图」不会被印到卷子上，
   注释里当例子写的 `![](<../附件/图.png>)` 也不会变成一次「找不到图片」的告警。

### 讲义里的题住哪儿

`questions.note_path`（迁移 0041）而不是 `md_path`：

- **不在 `题库/` 另写一份**：同一道题两份正文，之后谁盖谁全看顺序；
  所以 `pending_export` 会跳过这些题（讲义文件真没了才退回普通导出）。
- **网页改题只重写那一段**（`_sync_back_note`）。整篇重写会把老师的知识部分全冲掉。
- 幂等靠块里那行 `<!-- shike_id: xxx -->`：没有就新建并写回，有就更新，
  块指纹（`md_hash` = 去掉注释后的块的 sha256）没变就什么都不做。

### 报告长什么样

`POST /api/vault/scan` 的返回里，讲义单独一栏（`report["lectures"]`，一篇一条）：

```json
{"path": "讲义/第一讲.md", "created": [{"unit": 1, "id": "…", "title": "…"}],
 "updated": [], "unchanged": 2, "skipped": [], "warnings": [], "errors": [], "stamped": 2}
```

`unit` 是第几段（从 1 数），报错要按段说 —— 「第 3 段写着和别段同一个 shike_id」
比「这篇讲义同步失败」有用得多。

## 三、两条路的分工（选错就白干一遍）

| 想做的事 | 用哪个 |
|---|---|
| 卷子 / 别的格式 → 题目 md 文件，老师自己改完再同步 | `shike-question-md` skill（`doc_to_md.py`） |
| 直接把卷子录进题库（识别完就入库） | 收件箱 / `shike-ingest` / `auto_import_cli.py` |
| 自己写讲义，知识 + 题目放一起，题目顺带进题库 | **本格式**（`shike: lecture`） |
| 文档 → 普通笔记 | `shike-doc` skill |

前置检查永远是这三条：

```bash
curl -s --noproxy '*' http://127.0.0.1:8000/api/vault          # vault 在哪、有几篇题/讲义
curl -s --noproxy '*' http://127.0.0.1:8000/api/vault/inbox     # 收件箱有没有东西卡着
curl -s --noproxy '*' -X POST http://127.0.0.1:8000/api/vault/scan   # 同步（会改库，先看日志）
```

⚠️ 本机常年挂着代理：探 `127.0.0.1` 要 `--noproxy '*'`，否则会被送进代理返 502，
看起来像服务坏了。
