# PDF 版面识别 / 题目切分方案调研

> 调研时间：2026-09-24。价格与版本以官方页面为准（文中标注了哪些是本次核实过的、哪些是估算）。
> 结论面向本项目的实际形态：**单机、Windows、中文数学卷子、每月几百页、有 RTX 4050 6GB**。

## 0. 先分清两件事，否则选型一定跑偏

| | 版面分析（Layout Analysis） | 题目切分（Question Segmentation） |
|---|---|---|
| 输出 | 页面上的**区域框**：正文段落 / 标题 / 表格 / 图片 / **公式** / 页眉页脚 / 页码 + 阅读顺序 | 一道道**题目**的边界（第 1 题到第 2 题之间） |
| 现成模型 | 很多，成熟、便宜 | **没有现成的**，通用模型不认「题号」这个概念 |
| 对本项目的价值 | 给出「哪里是图、哪里是公式、哪里是表格、阅读顺序怎么走」 | 必须自己用规则拼出来 |

**关键认知**：版面分析**不等于**题目切分。DocLayNet / PubLayNet 那套标签里根本没有「题目」，
它们的 `text` 可能是一整块含 3 道题的正文。想要题目边界，只有两条路：

1. **文本层规则**（本项目现在的做法，也是最快的）：用 PDF 自带的文字层，正则抓题号
   （`1.` `2、` `（3）` `第4题`），配合坐标判断换列、换页、缩进。**不花钱、不联网、毫秒级**。
2. **版面框 + 规则**：先用模型把「正文块 / 图片 / 表格 / 公式」分开，再在正文块内部按题号切。
   价值在于：图不再被当成文字、公式能单独识别成 LaTeX、跨栏/跨页能靠阅读顺序接回来。

本项目的现状是「两条线手工标记 + 不识别文字」，等于把切分完全交给人工。**真正的增量价值
不是让模型来切题，而是让模型补上「图 / 表格 / 公式」这三类信息**，以及处理扫描件。

## 1. 三类方案总览

| 类别 | 代表 | 花钱 | 中文数学卷子 | 隐私 | 集成难度 |
|---|---|---|---|---|---|
| **本地开源** | PP-StructureV3、MinerU、DocLayout-YOLO | 0 元（自备算力） | ★★★★ 训练集里就有中文试卷 | 数据不出本机 | 中（装环境、下模型） |
| **云 API** | Azure Document Intelligence、Google Document AI、AWS Textract、Mathpix | 按页计费 | ★★★ 公式多为英文场景 | 卷子上传第三方 | 低（一个 HTTP 调用） |
| **多模态大模型** | Gemini Flash-Lite、Qwen-VL、GPT/Gemini 直读页面图 | 按 token，**极便宜** | ★★★★ 端到端效果最好 | 同上 | 低（发一张图 + 提示词） |

**我的建议：本地 PP-StructureV3 为主，Gemini Flash-Lite 作为兜底/对照。**理由见 §4。

## 2. 本地开源方案（重点）

### 2.1 PP-StructureV3（百度 PaddleOCR）—— 最贴合本场景

本次核实（官方文档）：整个流水线拆成 7 个模块，可按需开关：

| 模块 | 默认 | 说明 |
|---|---|---|
| 版面检测 | 开 | 23 类：文档标题 / 段落标题 / 正文 / 页码 / 摘要 / 目录 / 参考文献 / 脚注 / 页眉 / 页脚 / 算法 / **公式** / 公式编号 / 图片 / 图注 / 表格 / 表注 / 印章 / 图标题 / 图 / 页眉图 / 页脚图 / 侧栏文字 |
| 通用 OCR | 开 | PP-OCRv5，覆盖 简中/繁中/英/日/韩 + 手写、竖排、拼音、生僻字 |
| 表格识别 | 开 | SLANeXt（有线/无线表分开训练）+ RT-DETR 单元格检测 |
| **公式识别** | 开 | PP-FormulaNet_plus-M/L：**支持中文公式**，Zh-BLEU 89.8 / 90.6，输出 LaTeX |
| 图表解析 | 关 | 图表 → 表格（多模态小模型） |
| 印章识别 | 关 | 场景不符，关掉 |
| 图像预处理 | 关 | 方向分类 + 扭曲矫正 |

版面模型可选档位（**注意 CPU 那一列，这是本项目最关心的**）：

| 模型 | mAP | GPU | **CPU** | 体积 | 训练数据 |
|---|---|---|---|---|---|
| PP-DocLayout-S | 70.9 | 11.5ms | **18.5ms** | 4.8MB | 中英文论文/杂志/合同/书/**试卷** |
| PP-DocLayout-M | 75.2 | 13.0ms | **43ms** | 22.6MB | 同上 |
| PP-DocLayout-L | 90.4 | 33.6ms | 503ms | 124MB | 同上 |
| PP-DocLayout_plus-L | 83.2 | 53ms | 635ms | 126MB | 同上，多语言版面 |
| PP-DocBlockLayout | 95.9 | 34.6ms | 506ms | 124MB | 只输出「块」，用于阅读顺序 |

**这份表格里最值钱的信息是：训练集里明确包含「试卷（exams）」。** 这正好是我们的场景。
另外 `PP-DocLayout-S` 只有 4.8MB、CPU 18.5ms/页，几乎不要钱就能跑起来。

其他关键能力（都已核实）：

- **阅读顺序**：结果里的 `parsing_res_list` 就是按阅读顺序排好的，每个块带 `block_bbox` /
  `block_label` / `block_content` / `block_order`——**多栏卷子不用自己排序**。
- **跨页续接**：markdown 结果里有 `page_continuation_flags`（首页/末页元素是否段落边界），
  这对「一道题跨两页」是直接可用的信号。
- **导出**：`save_to_json` / `save_to_markdown` / `save_to_word` / `save_to_html`，PDF 输入逐页处理。
- **可当服务跑**：`POST /layout-parsing`，请求体是 base64 文件或 URL，返回结构同上。
  对本项目意味着：不用把 PaddleOCR 装进 FastAPI 的 venv，**另起一个进程/服务，后端一发一收**。
- **许可证**：Apache-2.0。可商用。
- **硬件**：CPU 可跑（但慢，整条流水线含 OCR/表格/公式，一页几秒级）；
  GPU 会舒服很多——**你这台 4050 6GB 足够**（模型总量约 1–2GB，装 F 盘，C 盘只剩 19GB）。

### 2.2 MinerU 4.0（上海 AI Lab opendatalab）

本次核实：已到 4.0，有 4 个解析档位 `flash / basic / standard / advanced`，并且带本地文档库
和 agent 接口。资源要求（官方表格）：

| 档位 | 模型 | 下载量 | 最低内存 | 加速器 |
|---|---|---|---|---|
| basic | ONNX | ~0.8GB | 2GB | **纯 CPU 可用** |
| standard / advanced | ONNX + llama.cpp | ~2GB | 8GB | CPU 可用，**推荐 Vulkan**（你的 4050 能吃到） |

- 输入支持 PDF/图片/Word/PPT/Excel/EPUB/OFD/HTML 等，输出 Markdown / HTML / **LaTeX** / **DOCX** / PDF
- 有 block 级定位（`doc:xxx/page:4/block:7`），可以只读某一块
- 许可证：**MinerU Open Source License（Apache 2.0 + 附加条件）**——商用前要读那几条附加条件
- 它是「整篇文档 → 结构化文本」的路线，**不做题目切分**；适合当作「把整份卷子转成 Markdown」的前置

### 2.3 DocLayout-YOLO（opendatalab）

- YOLO-v10 改的**纯版面检测**模型，`pip install doclayout-yolo` 即可用；DocLayNet 上 AP50 93.0
- 推理快，CPU 也能接受（1024 输入，CPU 秒级）；模型只有几十 MB
- **只给框和类别，不含 OCR、不含公式**。适合「我只要框，文字我自己从 PDF 文本层拿」这种组合
- 许可证 Apache-2.0（代码）/ 需看具体权重

### 2.4 其他值得知道的名字

| 项目 | 一句话 | 许可/成本 | 对你合适吗 |
|---|---|---|---|
| **Surya 2**（Datalab） | 单个 650M VLM 同时做版面+OCR+表格，中文 82.5%，公式直接给 KaTeX 兼容 LaTeX；vllm(GPU) 或 llama.cpp(CPU/Apple) | 代码 Apache-2.0，**权重是改过的 OpenRAIL-M：研究/个人/营收 <500 万美元 免费** | 效果好，商用要买授权；CPU 吞吐较慢（官方 Mac 实测 ~0.1 页/s） |
| **olmOCR 2**（AI2） | 7B VLM，PDF→干净 Markdown，Apache-2.0 全宽松，官方称自托管 <$200/百万页 | 自托管需 ≥12GB 显存（你的 6GB 不够）；或走外部推理商 | 偏英文文档，中文数学不占优 |
| **Marker** | PDF→Markdown 老牌方案，内置 Surya | GPL/商用限制看版本 | 一般 |
| **GROBID** | 学术论文结构化（标题/章节/参考文献） | Apache-2.0 | 场景不符（卷子不是论文） |

## 3. 云 API

### 3.1 通用文档智能（Azure / Google / AWS）

三家都有「版面分析」预置模型，返回区域框 + 阅读顺序 + 表格，价格量级都差不多
（**本次未能打开它们的定价页，以下为量级参考，落定前请以官网为准**）：

- Azure AI Document Intelligence：`Read` 约 $1.5/千页，`Layout` 约 $10/千页
- Google Document AI：OCR 约 $1.5/千页，Layout Parser 约 $10/千页
- AWS Textract：纯文字约 $1.5/千页，AnalyzeDocument（含版面/表格）约 $50/千页（贵得多）

**结论：对本项目不划算。** 500 页/月的量级，Azure/Google 的 Layout 大约 ¥35–40/月，
不是钱的问题，而是：公式识别弱（数学卷子是重灾区）、数据要上传、还要配云账号鉴权。
只有在「不想在本机装任何东西」时才考虑。

### 3.2 Mathpix —— 公式最强，但不是版面方案

Mathpix 的 Convert API 在**数学公式 → LaTeX**这一项上长期是标杆，也支持整页转 Markdown，
对数学老师天然友好。缺点：按页订阅制、**它不解决题目切分**、数据要上传。
（定价页同样是动态渲染，本次没抓到，以官网为准。）

## 4. 多模态大模型直读页面（最便宜的「端到端」路线）

非常实用，因为：**你不用训练、不用装环境、改需求就是改提示词**。

|---|---|---|---|
| Gemini 2.5 Flash-Lite | **$0.10**（文本/图/视频） | $0.40 | 最便宜的一档 |
| Gemini 3.1 Flash-Lite | $0.25 | $1.50 | |
| Gemini 3.5 Flash-Lite | $0.30 | $2.50 | |

- **Batch API 再打 5 折**，非实时场景（批量整理历史卷子）直接用

- 其他家同类：Qwen-VL 系列（可本地部署，中文强）、GPT-4.1/o 系列、Claude

## 5. 落到本项目：建议的三步走

### 第 1 步（先做，收益最大）：把手上的文本层用尽
现在录题页是「两条线手工标记、不识别文字」。其实**PDF 有文字层时根本不用 OCR**：
`PyMuPDF` 已经能把每行文字的 bbox 和文本都给出来（项目里 `adapters/pdf.py` 的
`page_lines()` 就在做这件事），拿它 + 题号正则就能自动**预切**题目，
人工只做「确认 / 微调」，不做「从零划」。

> 一句话：**先把「自动预切 + 人工确认」做出来，比引入任何模型都值钱。**

### 第 2 步（补短板）：用 PP-StructureV3 补「图 / 表格 / 公式」
文本层给不了三样东西：图片区域、表格结构、公式的 LaTeX。这三样正好是 PP-StructureV3 的强项：

- 跑成一个**独立本地服务**（`POST /layout-parsing`），后端需要时调用；
  这样不会把 Paddle 那一堆依赖塞进现有 venv，坏了也不影响别处
- 只用它的**版面检测 + 公式识别**两个模块（关掉印章、图表、表格），速度能省一大半
- 版面模型先用 `PP-DocLayout-M`（22MB／CPU 43ms）起步，不够准再换 `plus-L`
- 结果落到 `questions` 表：公式存 LaTeX 进 `content`，图存现成的 crops 目录

### 第 3 步（兜底）：扫描件 / 手机拍的作业，走 Gemini Flash-Lite
没有文字层的扫描件、家长拍的作业照片，用本地 OCR 也能做，但版面经常很野（歪、阴影、手写）。
这种「长尾」交给 VLM 更省事，成本可以忽略。隐私上注意：**上传前先问用户**（本项目一直是
「数据存在本机」的定位，这是产品承诺，别默默破坏）。

## 6. 风险与注意事项

1. **不要把「版面模型」当成「题目切分器」**——这是最容易走弯路的地方，通用模型的标签里没有题目。
2. **中文公式**是分水岭：PP-FormulaNet_plus-M/L 有中文公式能力；Azure/GCP 这套基本指望不上。
3. **许可证**要逐个看：PP-StructureV3 = Apache-2.0（最省心）；MinerU = Apache-2.0 + 附加条件；
   Surya 权重 = OpenRAIL-M（营收门槛）。自己用没问题，将来交付同行要看清楚。
4. **显存/磁盘**：你的 4050 只有 6GB，C 盘只剩 19GB。模型一律装 F 盘（544GB），
   Paddle 用 FP16 跑，别开 TensorRT（CUDA 版本匹配很折腾）。
5. **别为了「上模型」牺牲现在的确定性**：现有「手工两条线」虽然累，但**结果是准的**。
   引入自动切分必须保留人工确认环节，不能一步到位改成全自动。
6. **依赖隔离**：Paddle/ONNX/vLLM 这些都很重，务必独立进程或独立 venv，
   别污染现在这个跑得好好的后端环境。

## 7. 建议先做的一个实验（半天内可出结论）

拿**你手上那份 10 页的《认识特殊平行四边形》**做样本，对比三条路线在同一页上的表现：

| 路线 | 要测什么 |
|---|---|
| A. 现在：PyMuPDF 文本层 + 题号正则 | 自动预切准确率（能不能切出 10 页里的全部题目） |
| B. PP-StructureV3（版面+公式，CPU 与 GPU 各跑一次） | 图/表格/公式有没有框出来；公式 LaTeX 对不对；CPU 单页耗时 |
| C. Gemini 2.5 Flash-Lite 直读页面图 | 端到端切题 + 公式 LaTeX 的准确率、单页成本 |

评价标准只有一个：**「预切结果直接能用、不需要人工改的比例」**。
如果 A 的准确率已经很高（数学卷子题号很规整，通常是的），那 B/C 只在「图/公式」上补位即可，
不必上大动干戈的自动切题。
