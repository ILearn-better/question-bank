## 0. 一句话结论

**作业和课堂是两件事，别塞进同一套维度里。** 课堂评的是「这节课他表现如何」，
作业评的是「他自己独立做题的质量如何」——后者才是家长真正焦虑的东西，也是老师最难自证的。

技术上它比看起来便宜：**上传走现成的文件管线，打分照抄能力评分那套，归档复用现有的
「学生 / 上课日期」目录**。真正需要先想清楚的是三件事：

1. **维度选哪几个**（老师会不会嫌麻烦，直接决定这个功能会不会被用起来）；
2. **「没交」怎么记**（用 0 分记会把雷达图和平均分一起带偏）；
3. **AI 不许给分**（下面的「边界」一节 —— 这是本方案最容易做错的地方）。

**结论（🤔）：不需要新的上传通道、也不需要新的归档布局。** 真正要新增的只有三样：
一张**作业维度表**（对标 `ability_dims`）、一张**作业评分表**（对标 `ability_scores`）、
以及反馈上的两个字段（作业状态 + 批改备注）。作业比课堂多的那个东西就是**交没交** —— 
把它记在反馈上就够了，不必再抽一个「作业」实体（理由见第 4 节）。

## 2. 建议的维度（提案，需确认）

选维度的标准是我自己定的三条：**老师一眼能判断**（不用翻旧记录）、**不同维度之间不重复**、
**能指导下一步动作**（打完分知道该让他干什么）。太抽象的（如「思维能力」）不要，
一节课作业看不出结论，打完分也不知道该做什么。

| 维度 | 看什么 | 为什么值得单独一栏 |
|---|---|---|
| **完成度** | 做没做全、有没有漏题/大段空白 | 最高频、最客观的观察。漏做和做错是两种问题，补救方式完全不同 |
| **正确率** | 结果对错（可与题量一起看） | 最直观，也是家长最先问的 |
| **过程与规范** | 步骤是否完整、书写与卷面 | 数学上「答案对而过程跳步」是 DSE/中高考的**真实失分点**，必须单独看见 |
| **独立完成** | 是否自己做的（与答案一字不差、步骤跳跃但全对、课上同类题不会） | 老师最容易忽略、但直接决定「正确率」这一栏可不可信 |
| **订正与复盘** | 上次错题改没改、是否只改答案不写过程 | 唯一一个**跨次**才看得出效果的维度，也是本系统「按薄弱点出题」的入口 |

**关于「按时交」：建议不做成维度，做成状态。** 🤔 理由是性质不同 ——
按时/迟交/未交是**事实**，完成度/规范是**判断**。事实用字段记（可统计、可用于筛「谁老不交」），
判断用 1-5 星打。两者混在一张雷达图上，会让人分不清哪个是客观的。

**规模建议：5 项、1-5 星、允许只打其中几项**（与能力评分完全一致）。
一口气 8 项以上老师就会跳着打，数据反而更差。

## 3. 「没交作业」必须是一等状态，不是 0 分

这是我认为最容易做错、后果最难发现的一处 —— **用 0 分记「没交」，雷达图和趋势会一起失真**：
一次没交就把平均值拽下去，看起来像「这孩子两周内退步了」，而事实是他那天生病没写。
更糟的是这数据会长久留在 `ability_scores` 里影响「上次 vs 本次」的对比。

所以：

- 作业的**状态**只有四种：留空（这节不用记）/ `submitted`（已交）/ `late`（迟交）/ `missing`（未交）
  - 🤔 刻意不设 `assigned`（已布置未交）这个状态：老师是在**写反馈那一刻**回顾作业的，
    「布置了还没收」根本不是那个时刻会出现的情形 —— 那时候他压根不会去点这一块。
    多个状态就多一堆没人选的分支，到时候还得想「它到底算不算分母」
- **只有 `submitted` / `late` 才打分**；`missing` 不计入任何平均与雷达
- 界面上「未交」要显眼（家长沟通里这是必须提的事），但**不假装它是个低分**

## 4. 数据结构（迁移 `0013`，✅ 已在本机库上跑过）

```text
homeworks                    ✅ 已实现（0013）
  id / owner_id / student_id / lesson_id(唯一) / status / note / created_at / updated_at
  status: submitted（已交）/ late（迟交）/ missing（未交）
  ⚠️ **「没布置 / 不用记」= 没有这一行**，不存空状态 ——
     省掉「空状态算不算分母、要不要显示」这种没人想得清的问题

homework_dims                ✅ 已实现（0013，独立于 ability_dims —— 用户要的「分开」）
  id / owner_id / name / curriculum_id / sort_order / active
  预置 5 条：完成度 / 正确率 / 过程与规范 / 独立完成 / 订正与复盘
  ⚠️ 照 ability_dims 的做法 —— 在**迁移里 `op.bulk_insert` 一次性写入**（0004 就是这么种下
     那 5 个课堂维度的）✅，而不要用 feedback_templates 那种「每次启动按名字补缺」：
     维度是老师可改可停用的，补缺式的种子会把他删掉的维度又装回来

homework_scores              ✅ 已实现（0013，构造与 ability_scores 完全对齐）
  id / owner_id / homework_id / student_id / dim_id / score(1-5) / created_at
  只存真正打过的分（缺项 = 没这张行，**不要存 0**）
  ⚠️ 保存作业时：**带了 scores 字段就整组替换**（空列表 = 清空），未交（missing）时
     不写分且清掉旧分。实现时踩过一次：「先按常规 add、再 delete」会出现
     「未交 + 4 分」并存 —— 批量 delete 走 SQL、刚 add 的对象还在 session 里，
     先后不像直觉可靠；改成未交那一支**根本不 add**，顺序问题就不存在了

lesson_files.role            ✅ 已实现（0013）：material | homework
  → 上传、抽文字、归档、失败原因、删除清理全部沿用现有管线，一行都不改
  → 作业原件与讲义、反馈 txt 落在同一个「学生 / 上课日期」目录里 ✅
  → ⚠️ **两份清单互相看不见**；AI 润色取材料时也显式排掉 homework ——
     作业照片正是最容易被模型拿去做评价的东西，而打分是老师的事
```

**关于「该不该单独建一张 `homeworks` 表」**：我最初写的是单独建，后来按用户②
把它去掉了（当时推导是「入口在反馈里、一格一条，不必再抽一个实体」）；
用户④把入口改成并列按钮后，那个推导不成立，**实体又回来了**（见「修订记录」）。
从这段反复里得到的一条经验：**粒度的结论依赖于入口的位置** —— 
入口一变，数据模型跟着变，所以两者要放在一起看，不能分两次定。
仍然成立的部分：**不要求「一课多份」**，一格一条沿用至今。

**为什么不直接给 `ability_scores` 加个 `kind` 列**：那样能让趋势/导出代码全复用，
但**每一条现有查询都必须记得加 `kind='class'` 过滤**，漏一处就是课堂分和作业分混进
同一张雷达图 —— 这种错很隐蔽，而收益只是少写几张表的查询。
现在是「**分开建表，但字段与构造方式与 `ability_scores` 对齐**」：查询、雷达、
「本次 vs 上次」的代码可以照拄，同时不可能混。

## 5. 在哪里交：写反馈**旁边**的一个并列按钮（用户后来改的，✅ 已实现）

用户④：「开始在该反馈旁边建『交作业』」。所以入口**不是**反馈弹窗里的一块，
而是学生页「上课记录」里、跟在「写反馈 / 改反馈」后面的一个「交作业 / 改作业」按钮。

弹窗里的顺序（就是老师的操作顺序，与最初设想一致，只是位置挪了）：

1. **状态**：已交 / 迟交 / 未交 —— 没布置作业就直接关掉，什么都不会留下
2. **作业原件**：拍照 / PDF / Word，0 到多份 —— **可选**
3. **五个维度点星**：只在「已交 / 迟交」时出现（选未交就不显示打分）
4. **批改备注**：自由文本，可以只写一句

🔴 **评价不以文件为前提**（用户② 明确要求）。老师常常是当面看过纸质作业、或者凭印象写的，
没文件就不传 —— 不能因为「没上传」就挡住打分。上传只是「留个底 / 以后回看 / 给 AI 读字」，
不是打分的前置条件。界面上也不要把上传做成必填或强提示。✅ 已实现成这样。

学生页现在是**两张雷达图**：能力表现（课堂）、作业情况（作业）。分开两张，
不把两套不同维度硬画进同一张图。✅

⚠️ 两边**互不依赖**：可能只有作业没反馈（比如先收了作业、隔天再写反馈），反之亦然。
所以时间轴上两行分别说「尚未写反馈」与「这次作业还没记」，不会用一个去推另一个。

## 6. 边界：AI 不许给作业打分

这条是硬约束，直接沿用现有提示词第 7 条的思路 ✅：

> 材料只能用来核实「讲了什么/布置了什么」，**绝不能从材料推断学生表现**。

作业场景下要更严格，因为「作业照片」看起来最像「可以据此评价孩子」。明确写清：

- **打分是老师的事**。AI 最多做两件事：① 把作业里的字读出来（`file_text` 已经在做）
  ② 整理老师的批改备注成通顺的话。
- **绝不生成「完成度 3 分」这类建议分数。** 图片作业连题目都读不全，
  凭笔迹/涂改推断「粗心」是伪科学，而且会顺着老师的措辞偏好编，一旦被当真就是误导家长。
- 若以后要做「批改建议」，必须是**显式触发**、且界面写清「仅供参考、不自动写库」。

## 7. 与已有两条线的接口

- **家长报告（现在的导出）**：作业维度进不进 doc，是导出时的选项，不要默认塞进去 ——
  「作业」和「课堂」一起念给家长听，重点会散。🤔 建议家长稿里只在「作业情况」栏目里点名
  1-2 个维度 + 状态，完整雷达留在系统里。
- **学生记忆 / 学生 Agent（见 `学生记忆与Agent方案.md`）**：那份文档里说
  「`ability_scores` 是唯一可量化的趋势数据」。**作业评分补上了第二类趋势数据，而且更接近
  家长关心的「他自己会不会做」**。将来做画像时，「作业 vs 课堂」的**差距**本身就是一条
  高价值信息（课堂会、作业不会 → 依赖提示；课堂不会、作业全对 → 值得单独问一句）。
- **题库 / 知识树**：错题如果能标知识点，就能接上「按薄弱点出题」那条杀手锏。
  🤔 这是这个功能最有价值的延伸，但属于第二阶段，不要一上来就做。
