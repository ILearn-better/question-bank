## 3. 设计

### 3.1 公式转 LaTeX（已选：AI 视觉模型）

**§3.1.1 为什么这条路线合适**

项目已经有一套能用的 AI 接入层（`services/ai_polish.py`）：OpenAI 兼容协议、7 家服务商预设、
设置页可配、`SHIKE_AI_*` 环境变量可覆盖、密钥脱敏返回、错误消息可直读。
公式识别**只多需要一个「能看图的模型」**——基础设施零改造，只加一个配置段和一次请求。

**§3.1.2 模型选择（已实测确定：就用 `deepseek-flash`）**

2026-10-05 实测结论：**DeepSeek 的 `deepseek-flash` 本身就支持图片输入**
（`/v1/models` 返回 `"input_modalities": ["text","image"]`，1M 上下文），
润色与公式识别**一个模型全包** —— 原本准备的智谱 GLM-4V 等方案都不需要了。

| 模型 | 图片输入 | 用途 |
|---|---|---|
| `deepseek-flash` | ✅ | 润色 + 公式识别，主力 |
| `deepseek-v4-pro` | ❌ 纯文本 | 纯文本任务可用 |

若将来它的视觉能力不够用，按以下顺序退（都是 OpenAI 兼容协议，换配置即可）：

| 服务商 | 视觉模型 | 费用 |
|---|---|---|
| 智谱 GLM | `glm-4v-flash` | 免费档 |
| 阿里百炼 | `qwen-vl-max` / `qwen-vl-plus` | 按量 |
| 硅基流动 | `Qwen/Qwen2.5-VL-72B-Instruct` | 按量 |
| 本机 Ollama | `qwen2.5vl:7b` | 免费离线（6GB 显存偏紧） |

**配置形态（简化）**：**不做**独立的「公式识别」配置段，直接复用现有 AI 配置
（`ai_settings` / `SHIKE_AI_*`）—— 一个 base_url + model + key 就够。
⚠️ 顺带修掉一个失效预设：`ai_polish.py` 里 DeepSeek 原本写的 `deepseek-chat` /
`deepseek-reasoner` **已不在模型列表里**，已更新为 `deepseek-flash` / `deepseek-v4-pro`。

**§3.1.3 识别流程（三级降级，逐级交代原因）**

```
题目区域（已裁好的高清图）
   ↓ ① 先试「文本层直取」——有文字层且不含图片对象时，直接把文字发出去让模型转 LaTeX
   ↓    优点：token 少、快、准（文字层本身没识别误差）
   ↓ ② 文本层缺失/含公式图片 → 把区域截图（3 倍分辨率，已有管线）发给视觉模型
   ↓ ③ 模型不可用/失败 → 保留原图 + 标记 flags，交人工处理，绝不丢题
```

关键约束（沿用项目既有立场）：
- **识别结果一律是「草稿」，必须经人工确认才入库**（与 §3.2 的待审队列天然合流）
- **原图永久保留**（`questions.image` 已有字段）——视觉事实源不能因为「识别出来了」就丢掉
- 模型返回的 LaTeX 一律走 KaTeX 校验（`katex.renderToString` 同一个引擎），
  渲染失败的标 `flags: ["latex_invalid"]`，界面上标红提示

**§3.1.4 导出 PDF 的断点怎么补**

PyMuPDF 不渲染 LaTeX，三条路：

| 方案 | 做法 | 评价 |
|---|---|---|
| **A. 公式转图**（推荐） | 用 matplotlib `mathtext` 把公式渲染成透明 PNG，再 `insert_image` | 项目图表本来就偏好 matplotlib；mathtext 覆盖初高中绝大部分公式。⚠️ 不支持 AMS 环境（`align`、`cases` 等），需降级为图片 |
| B. 改为浏览器打印 | 前端已有「预览 / 打印」，让用户从 HTML 走浏览器打印成 PDF | 渲染质量最好，但改变了用户操作习惯，且要**去掉**现在的 PDF 导出按钮 |
| C. 保持现状 | 公式印成 `$…$` 原文 | 不可接受 |

建议 **A 为主**，并在公式超纲（mathtext 报错）时**明确提示**「这道题的公式无法转图，
建议用 HTML 预览打印」，而不是悄悄印成源码。

**§3.1.5 实测记录（2026-10-05，已跑过，不是推测）**

| 测试 | 结果 |
|---|---|
| 样例卷某一页（PDF 转 150dpi PNG）→ 抄录 | ✅ 题干、题号、选项全对，公式自动带上 `$…$` |
| 6 道复杂公式（嵌套分式+根式 / 定积分 / 无穷级数 / 对数分式 / 三角） | ✅ **6/6 全对**，与出题时的原始 LaTeX 等价 |
| `reasoning_effort` 对成本的影响 | 不传：4097 tokens（其中推理 3912）；传 `low`：**402 tokens（推理 175）**，准确率不变 |

三个必须记住的实现约束（都是踩出来的）：

1. **参数名是 `reasoning_effort`，不是 `effort`。** 实测传 `effort: "low"` 被**静默忽略**
   （token 反而略升），只有 `reasoning_effort` 生效。
2. **`max_tokens` 要给足（≥2000）。** 不传 `reasoning_effort` 且 `max_tokens=2000` 时，
   **推理会占满预算、正文返回空字符串**，且**没有任何报错** —— 这是最难查的一类失败。
   配 `reasoning_effort: "low"` 后 2000 就够。
3. **正文在 `choices[0].message.content`，推理在**同级的 **`reasoning_content`**。
   取错字段会拿到一长串"我在思考"而不是结果。

**成本量级**：一页试卷一次调用约 1000 prompt + 400 completion（low effort）。
一份 20 页卷子约 3 万 tokens 级别，**成本可忽略**；瓶颈在耗时而非钱。

**§3.1.6 真实卷复核（2026-10-05 当天补测，P0 由此关闭）**

样本取自用户资料库 `教育/` 空间，已落到 `samples/2025真题/`（**有版权，已加 .gitignore，不入仓库**）：

| 文件 | 页数 | 类型 | 说明 |
|---|---|---|---|
| 精品解析：2025年高考全国一卷数学真题（原卷版）.pdf | 5 | 电子版，**有文字层** | 学科网导出版 |
| 精品解析：2025年高考全国一卷数学真题（原卷版）.docx | — | Word | 同上 |
| 精品解析：2025年高考全国一卷数学真题（解析版）.docx | — | Word，31 MB | 带解析 |
| 2025 P1.pdf | 24 | **扫描件，无文字层** | **DSE 数学必修 Paper 1** |
| 2025 P2.pdf | 15 | **扫描件，无文字层** | **DSE 数学必修 Paper 2** |

三条关键实测结论：

1. **⚠️ 电子版的"文字层"对公式是废的 —— 这条推翻了原方案里的「文本层优先」路线。**
   高考卷 PDF 有文字层，但公式被拆成散落的单字符：`x²+(y+2)²=r²(r>0)` 提取出来是
   `2 / 2 / 2 / ( / 2) / ( / 0) / x / y / r / r` —— **字符顺序全乱，正负号丢失，无法还原**。
   用超清裁剪逐字核对原图后确认：原式就是 `x^2+(y+2)^2=r^2(r>0)`，
   **视觉模型给的重建结果完全一致**。解析版 docx 里段落文本同样是空的（公式是内嵌对象）。
   → **结论：哪怕电子版也直接走视觉模型，不要写「文本层优先」那套正则。省掉整个 P0 的复杂度。**

2. **英文卷的版面形态已确认（原方案 P6 的未知项）。** DSE Paper 1 是 **Question-Answer Book**：
   单栏、题号 `3.` 顶格、子问 `(a) (b)` 缩进三格、分值 `(3 marks)` **右对齐在题末**；
   每道题下面有**大片作答横线**（占页面 60% 以上），还有竖排的
   "Answers written in the margins will not be marked." 和条形码框。
   → 两个直接影响预切的事实：
   - 现有中文预切正则 `^\s*\d{1,3}\s*[.、．]` **也能吃 DSE 的 `3.`**，这点比预想好；
   - 但**不能靠"空白即分隔"切**，否则会把作答横线当成题目内容切进去。**只能按题号锚点切**，
     并且在识别前**主动丢弃题号以下的作答区**（视觉模型实测已能自己忽略横线和条形码，见下条）。
   - Paper 1 没有选项；Paper 2 是纯选择题。两者题号规则不同，需分别定参数。

3. **扫描件识别质量：实测通过。** DSE Paper 1 第 3 页（610 KB PNG）整页转录 ——
   题号、`(a)(b)` 子问、变量斜体、坐标 `(4,−2)`、`90^\circ`、`(3 marks)` **全部正确**；
   且**自动忽略了作答横线、条形码框、页眉页脚**，没有把空白区当内容吐出来。
   耗时 2.9s / 443 output tokens（`reasoning_effort: low`）。
   中文卷那页 8 道题一次读完：4.6s / 916 tokens，公式（根式、对数、圆锥曲线、立体几何）
   全部重建正确，连题干里的表格也转成了 Markdown 表。
   → **印刷体扫描件不需要额外的 OCR 前置**，可以直送视觉模型。

**仍未验证**：手写体；低分辨率/歪斜/带装订影的劣质扫描件。

**§3.1.7 落地结果（2026-10-05 已实施）**

比设计时想的更省：**AI 接入层的协议一行没改，只多了一个 body 字段。**

| 文件 | 内容 |
|---|---|
| `app/services/vision.py` | **新增**。两个模式（`question` 题干 / `formula` 纯公式）、图片预处理、提示词 |
| `app/routers/ai.py` | **新增**。AI 的配置 / 测试 / 识别接口统一到这里（原在 `feedbacks.py`；**路径不变，前端零改动**） |
| `app/services/ai_polish.py` | `chat_url` / `post_json` / `extract_content` 三个工具函数改为公共名 —— 识别与润色共用同一套 HTTP 细节 |
| `app/routers/feedbacks.py` | 移除已迁走的 AI 接口，只留「用 AI 润色这篇反馈」 |
| `frontend/entry.html` | 录题页加「🤖 AI 识别（转 LaTeX）」按钮 + 可编辑的待确认面板 |
| `backend/test_vision.py` | **新增**。纯函数自检（不联网）；`--real` 可选跑真题验证 |
| `requirements.txt` | 加 `Pillow`（送模型前压图） |

**四处与设计不同的决定**：

1. **图片先在前端转 base64，接口不收 URL。** 设计时想的是「传 `/api/crops/x.png`
   让后端自己读文件」，实现时改掉了：图可能还没落盘（老师刚框选、题还没保存），
   而让后端反查「URL → 磁盘文件」也只是多一处会错的地方。
   前端多走一步 `fetch → FileReader`，后端就完全不关心图从哪来。

2. **不做独立的「视觉模型」配置段。** 原计划让设置页多一组输入框（润色用便宜的、
   识图用免费的）。实测 `deepseek-flash` 一个模型两件事都干得好，所以**共用同一份配置** ——
   设置页因此少一半要填的框。真需要分家时再加。

3. **`questions.stem_format` 仍然不用。** 识别结果统一走 `$...$` 约定，
   下游 KaTeX 自动渲染、Word 导出自动转 OMML —— 这些都不读 `stem_format`。
   给一个没有消费方的字段赋值，只会让人以为它有用。

4. **`formula` 模式只给 API，前端按钮统一用 `question`。** 补答案时图里常混着文字步骤
   （「由题意得…」），纯公式模式会把它们丢掉。

**实测数据**（`test_vision.py --real`，DSE Paper 1 第 3 页）：

```
原图 458 KB → 送模型前压到长边 1600 / JPEG q85
耗时 2.2s    prompt=1374  completion=280
输出：Let $m$ and $n$ be two numbers. The sum of $2m$ and $3n$ is $999$ …
      The coordinates of the point $A$ are $(4,-2)$. $A$ is rotated clockwise
      about the origin $O$ through $90^\circ$ to $B$.  (a) … (b) …
```

`completion=280` 是本次实施里最值得记的一个数：**同一张图在加优化前是 4097**。
差别只在于传了 `reasoning_effort: "low"` —— 不传的话推理会吃掉 95% 的输出预算。

**边界与不做**：

- ❌ **识别结果不自动入库。** 结果落在一个可编辑面板里，老师点「替换 / 追加」才写进表单。
  理由与润色一致：识别偶尔会看错一个手写字母或正负号，悄悄替他决定了，
  错误的那个符号会一路印到发给学生的卷子上，而他直到发卷才发现。
- ❌ **本次不做「整页批量切题」。** 那是 P3 的活 —— 需要一个返回结构化多题数组的
  `page` 模式，并且要真实调参（分页、跨页题、作答区剔除）。本次只做单题与纯公式。
- ⚠️ **`reasoning_effort` 是 DeepSeek 特有参数**，别的服务商可能回 400「未知参数」。
  代码里做了自动降级：错误信息里提到该参数就去掉它重试一次 —— 宁可多花一点推理预算，
  也不能让整条链路因为一个「省钱的开关」而不可用。
- ⚠️ **提示词里 LaTeX 的反斜杠必须写双份**（`\\frac`）。写成单份的话 `\f` 会被 Python
  解释成换页符、`\t` 成制表符，提示词送到模型手里已面目全非，而模型照样有输出 ——
  `test_vision.py` 专门盯这一条。

### 3.2 批量导入与人工审核（已选：单份 + 多份都要）

> ⚠️ **本节是原设计稿，实际落地的形态见 §3.8** —— 表名、条目字段、内容来源（文字层 vs 全图）、
> 切题粒度都有变化，逐条差异与理由记在 §3.8 的「与 §3.2 原计划的差异」表里。
> 本节保留下来是为了记住**为什么**要走「待审队列与正式题库分离」这条路。

**§3.2.1 核心设计：待审队列与正式题库分离**

`docs/外部方案吸收建议.md` §5.2 已经定过一条判断：**不要把「待审核」变成所有题目的必经状态**，
否则个人教师会背上一个「待审积压」的心理负担。本次需求把批量导入做进来了，
所以采用那个文档里建议的形态 —— **状态流做成入口相关**：

```
手动录入路径（现状，完全不动）      批量导入路径（新增）
切分 → 保存                          上传多份 → 后台排队 → 机器拆题+识别
  ↓                                    ↓
直接进 questions                    写入 import_items（待审）
（永远是「已确认可用」的题）           ↓
                                    审核工作台逐条过 → 通过才写入 questions
                                                    → 驳回留档，不污染题库
```

**为什么用独立表而不是给 `questions` 加 `status` 字段**：
- `questions` 表语义保持纯粹（「已确认可用的题」），下游（出卷/作业/反馈/笔记插题）
  **一行都不用改**；
- 驳回的、识别失败的脏数据**永远不会进入题库**；
- 批量导入失败（文件损坏、模型超限）时只影响 `import_items`，不留下半截题目。

**§3.2.2 新增表**

```
import_jobs        批量导入任务
  id / status(queued|running|done|failed|partial) / total / done / failed
  error / created_at / finished_at / owner_id

import_items       待审条目
  id / job_id / document_id(?)
  page_no / crop_rect(JSON) / source_image(相对路径)
  raw_text            文本层原文
  ai_latex            模型出的 LaTeX（草稿）
  final_latex         人工修订后的最终版
  confidence          high | medium | low        ← 吸收对方方案的元数据
  flags               JSON 数组：latex_invalid / no_text_layer / image_only
                            / empty_stem / page_break_suspect
  status              pending | approved | rejected
  question_id         通过后指向生成的 questions 行
  created_at / reviewed_at
```

`confidence` 与 `flags` 是 `docs/外部方案吸收建议.md` §4.1 认定「最值钱」的元数据，
本次因为有了真·机器识别，**从「建议做」升级为「必须做」**——没有它，老师面对几百条待审
无从判断先看哪条。

**§3.2.3 后台任务**

现有技术栈是 FastAPI + SQLite，**不引入 Celery/Redis**（对单机自用是过度设计）。
做法：`import_jobs` 表 + 一个 `threading.Thread` 消费者（或 FastAPI `BackgroundTasks`），
进度写库、前端轮询。

⚠️ **SQLite 并发写注意**：批量识别会长时间占用线程，必须确保
每次写入是短事务；必要时开 WAL（库现在已有 `-wal` / `-shm` 文件，说明 WAL 已启用）。

**§3.2.4 审核工作台（前端）**

一屏一条，左图右文，三个动作：

```
┌────────────────┬──────────────────────────┐
│                │  识别结果（可编辑）        │
│   原题截图      │  ┌──────────────────────┐ │
│  （3 倍高清）   │  │ $f(x)=x^2+2x-3$      │ │ ← KaTeX 实时预览
│                │  └──────────────────────┘ │
│                │  [原文] / [预览] 切换      │
│                │  置信度: ● 高  ⚠ 无文字层   │
├────────────────┴──────────────────────────┤
│  [通过并下一条] [通过并编辑] [驳回] [跳过]    │
│  键盘: Enter 通过 / E 编辑 / X 驳回 / ← →   │
└───────────────────────────────────────────┘
```

**键盘优先**是要点：几百条靠鼠标点是折磨，`Enter` 连过是效率的核心。
左上角常驻「仅看需检查的（confidence≠high）」，一键过滤掉机器有把握的。

### 3.3 卷种样式（已选：样式 + 分区结构 + 自动凑题）

**§3.3.1 设计立场：模版 = 一组 opts 预设**

`docs/出卷模版方案.md` §2 已经点明：`build_html / build_docx / build_pdf` 三个渲染器
**共用同一个 `opts` dict`**，所以「模版」最自然的落点就是「一组 opts 预设」——
**渲染层不需要认识「模版」这个概念**，导入接口也保持向后兼容（不选模版 = 现在的行为）。

**§3.3.2 新增表 `paper_templates`**

```
paper_templates
  id / name / kind(gaokao|zhongkao|dse|alevel|custom)
  opts        JSON   ← 现有 4 个开关 + 字号/页边距/答案页另起/留白高度
  sections    JSON   ← 分区：[{"title":"第 Ⅰ 卷（选择题）","from":1,"to":8}, ...]
  score_plan  JSON   ← 分值：{"default":5, "by_section":[5,5,10]}
  layout      JSON   ← 版面：单/双栏、英文字体、标题样式
  header_note TEXT   ← 抬头：「本卷满分 150 分，考试时间 120 分钟」
  is_builtin / sort_order / owner_id / created_at
```

内置四套（名字先占住，参数按你实际用法定）：

| kind | 抬头 | 分区 | 版面 | 特点 |
|---|---|---|---|---|
| 高考数学 | 满分 150 分 / 120 分钟 | 第 Ⅰ 卷（选择）/ 第 Ⅱ 卷（非选择） | 单栏 | 中文题号 `1.` `（2）` |
| 中考数学 | 满分 120 分 / 120 分钟 | 一、选择题 / 二、填空题 / 三、解答题 | 单栏 | 题号带「、」 |
| **DSE 数学** | Paper 1 / Paper 2 | Section A / Section B | **双栏** | 英文题号 `1` `(a)` `(i)`；Section B 题型固定 |
| **A-Level 数学** | 按 paper 抬头 | Section A / Section B | **双栏** | `Question 1` / `(a)` / `(i)`；公式极密 |

⚠️ DSE / A-Level 的两个真实难点（`docs/外部方案吸收建议.md` §4.6 已点出）：
1. **题号规则不同** —— 中文卷 `1.` `2、` `（3）`；英文卷 `1` `(a)` `(i)` `Question 1`。
   现在的预切正则是中文口径，**必须按卷种分档**（一个 `profile` 参数），不能一套正则硬吃。
2. **双栏阅读顺序** —— 现在按 y 坐标排序，双栏卷会把左右两栏**串着读**。
   这是接英文卷之前必须解决的，否则拆出来的题是乱的。

**§3.3.3 分值：题级可选、模版兜底**

`docs/出卷模版方案.md` §4 指出「题库里没有分值字段，分值只能靠模版给」。
本次做法：`questions` 新增 `score`（可空），导出时**题级分值优先，否则用模版 `score_plan` 默认值**。
→ 老师不填也能出卷（走模版默认），个别题要特殊分值也能单独设。

**§3.3.4 题号重排**

分区模版下，题号要跨分区连续编号（第 Ⅰ 卷 1–8，第 Ⅱ 卷从 9 开始）。
现有的 `items` 是前端传序、`enumerate(..., start=1)` 编号 —— 加分区后要在
渲染层按 `sections` 插入分区标题并**维持连续编号**。

**§3.3.5 落地结果（2026-10-05 已实施；与上面设计有几处偏差，以本节为准）**

1. **不设 `score_plan`。** 看过四套真卷后改了主意：分值不该由模版给一个默认值 ——
   那会印出一个老师没确认过的数字，比不印更糟。改成 `questions.score` 可空，
   **没填就不标**；中文卷的分值写进分区说明（「本题共 N 小题，每小题 5 分」），
   英文卷逐题标 `(N marks)`（西文括号 + 空格，与真题一致）。
2. **`paper_templates` 只有三块 JSON**（`paper` / `style` / `sections`），没拆成二十个列。
   字段名与默认值集中在 `app/services/paper_style.py`，**解析 / 接口 / 种子 / 渲染共用一份**
   —— 三处各写一遍迟早对不上，而症状是「导出的卷子排版悄悄变了」，不报错、最难查。
3. **分区支持两个匹配维度**：`qtypes`（题型，中文卷）与 `difficulties`（难度，
   DSE 的 A(1)/A(2)/B 就是难度阶梯）。两个都给了就要**同时命中**。
   **空分区不渲染**（否则会印出「一、选择题　本题共 0 小题，共 0 分」的空标题）；
   没被任何分区匹配走的题落**兜底组**（无标题）—— 一道都不丢。
4. **题号跨分区连续编号**，与原设计一致。实测 DSE 真卷题号是**顶格数字**（不是
   `Question N`），所以 DSE 用 `1.`、A-Level 用 `Question N`。
5. **PDF 也吃同一份样式**（页边距 / 字号 / 抬头 / 分区）。原来三个格式各写各的边距，
   同一份卷子「预览」和「下载」的留白本来就对不上；这次统一由模版给
   —— 这是**有意的行为变化**，不是回归。
6. **不选模版 = 与加样式之前完全一致**，有回归测试钉住这一条。
7. 接口：`GET/POST /paper-templates`、`POST /paper-templates/copy`、
   `PATCH/DELETE /paper-templates/{id}`；导出加 `template_id` 参数。
   内置四套**可改不可删**（删了下次启动种子会建回来，反而让人以为删不掉）。
   改样式请先「复制」再改 —— 复制的副本 `code` 为空，日后升级内置取值时不会互相污染。
8. 测试：`backend/test_paper_style.py`（纯函数 + 三格式渲染，不起服务）。
   样式对比页：`样式预览/index.html`（同一批题套四套样式的并排预览）。

### 3.4 自动凑题 —— 这是唯一推翻既有红线的地方

**§3.4.1 先摆清楚冲突**

`docs/学生画像与推题出卷方案.md` §5 明确写过项目红线：

> **不做推荐算法 / 自动挑题 / 自动排序，内容由老师挑。**

`docs/出卷模版方案.md` §6 也重申「不做按考试大纲自动组卷——那是替老师决定考什么」。

**本次需求（"再加自动凑题"）直接推翻了这一条。** 这是你的决定，方案照办，
但要把**实现形态**设计对，否则会踩两个真实的坑：

**§3.4.2 两个真实的坑**

| 坑 | 为什么危险 |
|---|---|
| 题库是老师**自己录的**，质量与难度标注参差 | 一键成卷可能凑出一份「看着像高考卷、实际难度乱跳」的卷子，发出去才发现 |
| 全自动 = 老师失去对整卷的把控 | 与「打印出来线下发」的实际形态冲突：发出去的卷子代表老师水平 |

**§3.4.3 采用的形态：约束内的候选推荐（三档可切）**

```
模版给结构约束          系统按约束筛候选           老师定稿
────────────────      ───────────────────      ──────────
8 选择 + 4 填空 + 6 解答  →  每个空位给 3–5 个     →  点选 / 换 / 调序
各题分值、覆盖知识点          符合条件的候选            （也可一键全填后逐题换）
难度分布（易:中:难 = 5:3:2）
```

| 档位 | 行为 | 默认 |
|---|---|---|
| **A. 候选点选** | 每个空位列出候选，老师逐个点 | ✅ **默认** |
| B. 一键按约束填充 | 系统自动填满，老师逐题过一遍、想换就换 | 可选开关 |
| C. 完全手动 | 就是现在的方式 | 保留 |

**关键设计**：不论哪一档，**凑题的依据都来自你的知识树与题库字段**
（`qtype` / `difficulty` / `knowledge_points` / `tags` / 新加的 `score`），
**不引入外部大纲、不让 AI 编题**。系统只做「按条件筛」，不做「判断考什么」。

**§3.4.4 顺带解决一个真问题：组卷去重**

`questions.usage_count` / `last_used_at` 两个字段的注释写着「为『组卷去重』留的」，
但一直没用上。自动凑题正好有了消费方：**最近用过的题降低优先级**，
避免凑出一份跟上周作业重合 80% 的卷子。这是纯增量，收益直接。

### 3.6 录题形态：文本与图片双存，出卷时选一个（2026-10-05 追加，已完成）

**起因**（用户 2026-10-05 提的）：录题页的「题目预览」是只读渲染区 —— 识别错了不方便改，
得先入库再回头改；而且 PDF 分界线选段自动填的是**文字层**抽出来的文本，公式会散成乱字符
（§2 已实测过，文字层对公式是废的）。

**改动**：

| 项 | 内容 |
|---|---|
| 预览区 | 文本「上渲染（Markdown + KaTeX）/ 下源码」并排，改源码上面立刻变；图片另占一块，各带标签 |
| 答案 | 与题干同一套能力（用户明确要求「答案导入也要有」） |
| 入库 | 存的仍是 `content` / `answer` **源码**，Markdown 与公式只在展示层渲染 |
| 出卷 | 新增 `questions.render_prefer`（`auto`/`text`/`image`，**迁移 0018**）+ 导出接口 `render_mode` 整卷覆盖；整卷压过单题 |
| 退回规则 | 缺哪种形态自动退回另一种，**绝不印空白题** |
| AI 按钮 | 文案改成「图片 → Markdown」；PDF 分界线选段也自动出原貌图 —— 以前只有 Word 会出图，于是按钮永远灰着，这就是「点不了」的根因 |
| 识别模式 | `vision.PROMPTS` 新增 `answer`（保住换行与步骤顺序，和 `question` 不是一回事） |
| 选区指纹 | `lastSelKey`：选区没变就不重建文本，否则用户手改的题干一选区就被冲掉 |

**有意的行为变化**：出卷从「题干文字 + 原貌图都印」改为二选一。老题都落在 `auto`，
有文本的会改成只印文本 —— 那批文本格式乱的，在出卷页把整卷切「全部用图片」即可。

**测试**：`test_render_prefer.py`（打 8000，自造图自删）、`test_entry_page.py`（前端静态自检，不需要服务）。

### 3.7 删除文档（2026-10-05 追加，已完成）

**起因**（用户 2026-10-05 提的）：录题页能删单道题，却**没有删文档的能力** ——
接口和界面都没有。传错的卷子只能永远留在下拉列表里；磁盘上的原件、Word 转换件、
页面图缓存更没人清（散在 `uploads/` 的三个子目录里）。

**做法**：

| 项 | 内容 |
|---|---|
| 影响预演 | `GET /api/documents/{id}/delete-impact` —— 纯读取，报出「题目数 / 可回收截图数 / 将删的文件及大小」。前端确认框显示的数字全部来自它，**不在前端估算**：这里算错就等于骗用户点确认 |
| 真删除 | `DELETE /api/documents/{id}?with_questions=false` |
| 清文件 | 原件、`converted/{doc_id}.pdf`、`pages/{doc_id}/` 一次清干净；**库先改、文件后删**，中途失败也不会留下「文件没了、记录还在」的空壳 |
| 截图回收 | 按引用计数（`services/crops.py`，与 `delete_question` 共用一份）。同一张图可能被别处当答案图用着 —— 实测确认过：删到最后一个引用消失时才真的抹掉 |
| 题目归属 | **默认不删题**（`with_questions=false`）。题目是独立资产：有自己的文本、截图，可能已经出过卷。保留时清空 `document_id`、留 `doc_filename`，题库里仍看得出它出自哪份卷子 |
| 安全网 | 删记录前自动 `backup_db("del-doc")` —— 文件删了回不来，至少让「当时哪几道题挂在它下面」有据可查（设置 → 数据备份，超出保留份数自动清最旧的） |

**顺带的整理**：原先 `_crop_files` / `_all_crop_refs` 是 `questions.py` 里的私有函数，
删文档要用同一套判断 —— 与其让路由互相 import 私有函数，抽成了 `services/crops.py`。

**测试**：`test_doc_delete.py`（打 8000，自造 PDF 与截图、跑完自清）。
其中「共享截图不误伤」与「最后一个引用消失才回收」是两条最容易写错的用例。

其余测试也一并复核：`test_entry_page.py` 加了删除入口 / 预演 / 勾选框 / 删后复位四项存在性检查
（外加 `el-dialog` 等标签配对）—— 零构建前端没有打包器挡语法错误，这道闸不能省。

### 3.8 P3 批量入库 —— 实际落地的形态（2026-10-05 追加，已完成）

**起因**（用户 2026-10-05 提的，原话）：

> 这个是单独入库，还需要批量入库功能：批量入库根据目前入库功能做一些变化，
> **全部通过图像的方式处理**，即也可人工画分割线和截图，但是是**一次性分割完**，
> 然后**并行**发给 ai 进行识图，再返回 **latex代码 \ 题型 \ 难度 \ 体系 \ 知识点 \ 标签**。
> 可以见得，关键是对大模型返回值的限制，提示词中要限制返回格式，以及内容。

**开工前四项确认**（问题 → 用户选择）：

| 问题 | 选择 |
|---|---|
| 体系与知识点谁定 | **体系整批设置一次**（一份卷子一个体系）；**知识点由 AI 给出** |
| 怎么切题 | **连续画横线，线之间自动成题块**（不是一块一块框） |
| 一步做完还是分两步 | **分两步：先批量分割 + 并行识别** —— 本轮**不做审核工作台**（P4 仍独立） |
| 这一轮识别到什么程度 | **先只识别题干与元数据**（题干 + 题型/难度/知识点/标签），**不做答案** |

#### 与 §3.2 原计划的差异（都是有意改的）

| 项 | 原计划 | 实际 | 为什么 |
|---|---|---|---|
| 内容来源 | 文字层原文 + AI 兜底 | **一律走图像**（视觉模型） | §3.1.6 实测：电子版卷子的文字层对公式是废的（散落单字符、顺序乱、正负号丢失），拿它垫底只会让老师改得更多。全图路线反而少一层不确定性 |
| 表名 | `import_jobs` / `import_items` | **`batch_jobs` / `batch_items`** | `import` 是 Python 关键字，写起来到处要绕；改成 `batch`，模块 `services/batch_import.py` / `routers/batches.py` |
| 条目字段 | `raw_text` / `ai_latex` / `final_latex` | **`content`（只一份，模型出的 + 老师改的都写它）+ `raw`（原样留档，截 2000 字）** | 老师改完还得自己决定「最终版」放哪，等于让他管版本。只保留一份 = 库里永远是"当前内容"；原始返回留在 `raw` 里，出问题能回头看 |
| 切题粒度 | 一个矩形 = 一个题块 | **一个块 = 一串矩形**（`blocks[].regions[]`） | 跨页题在真卷里很常见（尤其解答题），而题目只有一个 `image` 字段。多条 region 竖拼成一张，模型不用做加法、数据模型不用加字段 |
| 后台任务 | `threading.Thread` 消费者 | 同左 + **识别并行 / 写库串行** + `PER_ITEM_TIMEOUT=90` + 单条重试 1 次 | SQLite 单写者：N 个线程各写各的会撞 `database is locked`。瓶颈是等网络那几秒，写库只有几十微秒 —— 并行识别、串行落盘，两边都拿到 |
| 审核入口 | 独立工作台页 | **就挂在批量页第二个 tab**（题块 / 待审） | 本轮不做 P4 的键盘流工作台，但「通过才进题库」这条红线一开始就得立住，不能先落进 `questions` 再补救 |

#### 对大模型返回值的限制 —— 这是这批功能的关键（用户点名的）

模型返回的是一段**自由文本**，而脏数据是**静默**流进待审列表的（接口全返 200），
所以做了三层，少一层都会漏：

| 层 | 做法 | 具体在哪 |
|---|---|---|
| ① **提示词** | 固定七个字段（一个不少）、枚举取值**原样列出**、标签 0–4 个每个 2–6 字、**只输出一个 JSON 对象**、附一个输出示例、四条硬要求（照抄枚举 / 不许省字段 / 不许非法转义 / 只描述这一道题） | `batch_import._FIELD_RULES` |
| ② **请求参数** | `temperature=0` + `response_format={"type":"json_object"}`；服务商不认这个参数 → **自动去掉重试一次**（别家回 400 时不至于整批挂掉） | `batch_import.recognize_fields` |
| ③ **后端解析** | 剥代码围栏 → 取第一个 `{` 到最后一个 `}`（模型爱先来一句"好的，这是识别结果："）→ 修尾随逗号；仍解不出就给一份**永远可入库**的默认值 + `flags` | `batch_import.parse_fields` |

`flags`：`bad_json` / `json_repaired` / `empty_stem` / `qtype_fallback` /
`difficulty_fallback` / `confidence_fallback`。审核界面把每个翻成人话标签，
老师一眼看出"这是兜底的，得自己看"。

**`parse_fields()` 永不抛异常** —— 一条脏结果不该让整批任务失败，也不该让它悄悄写进题库；
正确做法是标成异常项放进待审，由人决定。（这是 §3.2.1「待审与正式题库分离」的自然延伸。）

⚠️ **提示词里的 LaTeX 反斜杠必须写双份**（`"\\frac{}{}"`）。写单份会被 Python 吃掉：
`\f` → 换页符、`\t` → 制表符。而模型照样有输出，只是公式规范变差 —— **从任何日志上都看不出来**。
`test_batch_fields.py` 直接断言整份提示词里没有控制字符，专门守这一条。

#### 提示词的角色为什么不复用 `vision.PROMPTS["question"]`

那一份要的是「**把题转录成一段文本**」，这一份要的是「**填一张结构化表单**」。
共用一份角色描述会让模型在两件事之间摇摆（实测：明说了"只输出 JSON"，它仍然给出
带小标题的转录稿）。所以 `_ROLE` 单独写。

#### 知识点：模型给名字，服务端挂到知识树

模型给的是**自由文本的名字**，不是 `node_id`。挂在去哪个节点由服务端决定
（`services/knowledge.py`，从 `routers/questions.py` 抽出来的）：

```
完全同名 → 归一化后同名 → 归一化后互相包含（取名字最长/最具体的那个）
```

归一化只抹**噪声字符**（空白、标点、`的/和/与/及`），**刻意不做同义词表**：
把「函数」猜成「函数的概念与表示」是替老师做主，猜错的代价是题目挂错考点、
出卷按考点筛题时漏掉它。

> 实测：`函数零点` → `函数/函数的应用/函数零点与方程的根`（node 23）；
> `三角函数的图像与性质` → node 27（靠"三角函数 ⊂ 三角函数的图像与性质"这一档）。
> ⚠️ 种子树里用的是「图像」（node 17/20/32/33），不是「图象」；「图象」那种写法
> 归一化后仍不相等，得靠包含关系捡回来。

**模糊匹配只给批量开**（`resolve_kp(fuzzy=True)`）：手动录题时老师是从下拉里挑的，
名字对不上就是他自己敲的新词，那时不该猜。默认保持既有行为。

知识点名字的取值唯一出处是 `app/taxonomy.py`（题型/难度/置信度/标签限制），
同时被**提示词**、**后端校验回落**、**前端下拉**三处消费 —— 前端再写一份就会出现
「下拉里没有的值」这种不报错的错位。所以新页面走 `GET /api/batch/options`。
（⚠️ 已知重复：`frontend/entry.html` 的录题表单里仍有一份自己的拷贝，改的时候两边一起改。）

#### 前端

- 独立页 `frontend/batch.html`（约 1000 行，单文件，与 entry.html 同一套本地化的 vendor）
- 左栏：一次性分割（✂️ 画横线 / 📷 框选两种工具、自动识别题号铺线、清空、吸附到行间空隙、
  块数统计）；块列表支持 **删块 / 并入上一块（跨页）/ 恢复页顶**
- 右栏：体系下拉 + 「识别这 N 块」；两个 tab（题块 / 待审）；历史任务卡片
- 待审条目逐条编辑（题干上下并排：渲染 / 源码；题型 / 难度 / 知识点 / 标签 / 置信度），
  通过 / 驳回 / 退回 / 全部通过
- 轮询 1.5 秒一次；**合并服务端结果时只保留用户可能正在编辑的四个字段**，
  其余以服务端为准 —— 否则 1.5 秒盖一次，用户刚敲的字会被吞掉

#### ★ 踩到的坑：in-DOM 模板里 `/>` 不自闭合（整页白屏）

`entry.html` / `batch.html` 是**没有构建步骤**的 HTML，根模板走**浏览器 HTML 解析器**这条路。
这条路上：

```
<el-alert v-else-if="..." />     ← 浏览器忽略自定义元素结尾的 `/`，把它当开标签
<div v-else>…</div>              ← 于是被吞成它的子节点
                                 ← 再于是 `v-else` 找不到相邻的 `v-if`
                                 ← Vue 抛 compiler-30 → mount 不执行 → 永远白屏
```

**症状特别难查**：`<div id="app">` 是空的，控制台只有一句报错链接；
而**所有接口测试全绿**（后端毫无问题）。`entry.html` 里也有一处同样的写法，
它后面跟的 `.hint`（"删前会自动备份一次数据库"那段提示）其实一直被吞在 alert 里。

**修法与防线**：

- 组件一律写 `></el-alert>`，不写 `/>`（HTML 空元素如 `br`/`img` 不受影响）
- `test_batch_page.py` ⑤ 固化两条守卫：① 自定义组件不得自闭合；② `v-else`/`v-else-if`
  必须有相邻的 `v-if`（用一个小 HTML 分词器建树后查兄弟关系，**刻意模拟浏览器的
  「忽略非空元素的 `/`」行为** —— 按 Vue 字符串模板语义解析就复现不出这个 bug 了）。
  守卫自己先拿一段"已知会白屏"的模板自检，证明探测器是灵的
- 单文件里的字符串模板（`frontend/src/views/*.js`）**没这问题** —— 那条路走 Vue 自己的
  解析器，`/>` 是认的，不用查

#### 上线后按反馈改的三处（2026-10-05 深夜）

上线当天就收到三条反馈，全是**接口全绿、页面却不能用**的那种 —— 正好印证了
「批量入库的难点不在接口，在页面与机器的交互」。

**① 「报错捕获了，但是程序也访问不了了」**

复现出来是这个：库里那份 46 页的《中央财经大学李丰.pdf》（PPT 导出的横版 PDF，453×255pt）。
`loadDoc` 里有句 `if (!this.doc.scanned) this.autoSegment(true)` —— 无条件自动铺线，
而当时的题号正则是 `/^\s*\d{1,3}\s*[.、．]|[（(]\s*\d{1,3}\s*[)）]/`：
`|` 的优先级让整个表达式变成「行首数字」**或**「行内任意 `(1)`」，
于是英文文献里的 `160(1)`、表格里的 `1.6~3.3`、参考文献编号全部命中。

结果：**46 页铺出上百个题块**。左栏要同时渲染 46 张 3 倍分辨率图（解码后几百 MB 位图），
右栏上百个卡片 —— 浏览器与服务端一起被拖死。一点「识别这 N 块」就是上百次 AI 调用。

三处一起改：

- **题号判定收紧**：要求行首是题号，且**题号后不能紧跟数字**（`(?!\d)`）。
  那份 PDF 的命中数 **295 → 1**；高考真题 44 → 22（剩下的正是真题 + 考试说明）；
  专项卷 10 → 10（全对）
- **自动铺线上限**：整份超过 `AUTO_MAX_TOTAL = 40` 条时，切文档自动跑（silent）**整份跳过**
  并说明原因；老师自己点按钮仍可强制铺，但会先确认。提交侧加 `SUBMIT_MAX = 30` 提醒，
  后端 `create_job` 再加 `MAX_JOB_ITEMS = 80` 硬上限
- **左栏懒加载**：页面盒用 `aspect-ratio` 撑住高度，图交给 `IntersectionObserver`
  按需加载（视口 ±900px）。数据层（分界线、色带）完全不变，只是不再一次解码几十张图

**② 「划线要鼠标点哪就在哪，别随便取消上一条」**

旧 `onPageDown` 一个函数兼了两件事：点空白处加线、**点在已有线 2.5% 页高以内就删掉它**
（A4 上约 7mm）。更糟的是加线用的是**吸附后**的 y、判定删除用的是**原始** y —— 两个坐标系不一致。
再叠上默认开启的吸附（候选里还带着 `0` 与 `pg.height`，点在页首附近会被吸到页顶），
就成了「点哪不在哪，还老把刚画的删掉」。

改法很直接：**点击只加线，删除只走线上的 ×**；吸附默认关闭，开启后也只认
「相邻两行之间的空隙」、且距离超过 `SNAP_LIMIT = 14pt` 就不吸；拖动线时显示精确读数。

**③ 「对于我换了个文档会显示读不到页面信息」**

`loadDoc` 里三处缺陷叠在一起：`Promise.all` 拉 N 页 lines **没有任何逐页容错**（一页失败整份失败）；
失败分支只弹一句提示、**不重置 `pv`**，于是旧文档的 `pages` 配着新 `doc.id` 继续用；
而 `rebuild()` / `bandStyle()` 里 `pg.width` 是裸访问，`pg` 为 `undefined` 时直接抛异常 →
渲染函数炸 → 整页点不动（这就是「程序也访问不了了」的第二条路径）。

改成：进文档先清空全部状态 → 逐页 `catch`（单页失败只提示「这页请用框选」）→
几何缺失时返回 `null` / 空样式而不是抛错 → 加 `app.config.errorHandler` 兜底。
另外 Word 文档没有页面图时直接给指引，**不在这个请求里触发 Word 转换**
（那是同步调用 Word，会卡几十秒，看起来像没反应）。

顺带补了**服务日志落盘**：`backend/data/logs/shike.log`（2 MB 轮转）。
没有它就只能永远靠猜「当时发生了什么」。

#### 题干配图 + 题块缩略图（2026-10-06 追加，已完成，迁移 0020）

上线第二天又收到两条反馈，本节记录这两处的来龙去脉与取舍。

**① 「带图像的题目，图像没有录入」**

根因不是识别丢图，而是**结构性的**：批量入库存的 `image` 是**整道题的原貌图**，
出卷走**文本**形态时它整张不印 —— 题干里那句「如图，在四棱锥 P-ABCD 中…」的图
就跟着没了，而且**丢了没有任何环节会发现**。

解法是加一条独立的链路，AI 初判 + 人工兜底 + 手工框选：

| 环节 | 做法 |
|---|---|
| AI 初判 | 提示词从七个字段加到**九个**：`needs_figure`（布尔）+ `figure_note`（一句话说明这图是什么）。**拿不准时给 `true`** —— 漏判的代价是那幅图永远没人补，多判的取消一下就好 |
| 容错 | `_as_bool()` 返回**三态** `True / False / None`。⚠️ `None ≠ False`：空串、`null`、字段缺失、说了句看不懂的话，全都算「没判出来」→ 落 `figure_unknown` flag。**空串刻意不在 `_FALSE_WORDS` 里**（这是故意的：当成 `false` 会让该复核的条目静默过审） |
| 人工判断 | 待审卡上一个勾选框「这题有配图」，默认值是模型给的，**以人勾的为准**（用户点名要的人工逻辑） |
| 提醒 | 两种「不静默通过」：题干命中「如图 / 图象 / 图中 / 曲线 / 示意」等词却没勾 → 黄字提醒复核；模型没判出来 → 提醒自行确认。关键词表在 `taxonomy.FIGURE_KEYWORDS`，由 `/api/batch/options` 下发，**只作提醒不作判定** |
| 手工框选 | 审核页「框选配图」→ 原卷整页图上拖矩形（可翻页、多段竖拼）。`POST /api/batches/items/{id}/figure-crop`；替换时回收旧图、顺手 `needs_figure=1` |
| 入库 | `approve` 时 `figure_image` 单独一列进 `questions`（与整块原貌图分开存，因为消费时机完全不同） |
| 出卷 | `paper_export` 的 `figure_path()`：**只有文本形态**在题干下补印这幅图；图片形态不印（原貌图里本来就有，印两遍是重复）。HTML / DOCX / PDF 三条路都接了 |

**② 「两个分割线要自动成截图才行，目前分割线间无法自动判断为待选题块」**

实测发现机制本身**一直是好的**（纯 DOM 探针点一次线：色带 +1、右栏块卡 +1、页标 +1）。
真正缺的是**肉眼凭据**：块卡片里只有一句「约 42% 版面」，两条线之间到底切出了什么、
切没切到页脚，看不出来 —— 得等提交（每次都是一次 AI 调用）才发现切错。

解法是 `GET /api/documents/{id}/region-image?spec=&zoom=`：

- **只读、现渲染、不落盘**。这条是硬约束：`data/uploads/crops/` 是**资产**目录
  （每张图有数据库行引用、删除靠引用计数），预览图落盘就攒成没人引用的垃圾 ——
  实测踩过「题库 0 行、盘上 92 张图」
- 前端 `previewUrl()` 是**纯字符串拼装**，不出现 `this.api(...)` —— 地址直接当
  `<img src>` 用，浏览器才肯替我们做缓存 / 懒加载（`loading="lazy"`）/ 并发控制
- `zoom=1.2`：缩略图看的是「切得对不对」，不是印刷质量
- 多段（跨页块）全带上，服务端 `render_region_png` 竖拼成一张
- `spec` 形如 `1:40,90,550,300`，跨页 `;` 连接；写错 422 并指出是哪一段

**引用计数从四处算**（`services/crops.py`，漏任何一处都会静默删掉老师在用的图）：
`questions.image / answer_image / figure_image` + `batch_items.image / figure_image`。

## 5. 边界与不做

- ❌ **不做全局待审积压队列** —— 只在批量导入路径引入（§3.2.1 已论证）
- ❌ **不做 L3/L4 语义查重**（embedding / LLM）—— 量级不够，L1/L2 足够
  （fingerprint 查重本次**也不做**，等批量导入真的产生重复问题再说）
- ❌ **不让 AI 编题** —— 凑题只从你自己的题库里筛
- ❌ **不引入 Celery / Redis** —— 单机自用，线程 + 轮询够用
- ❌ **不做自动断页优化 / 在线答题 / 自动批改**
- ⚠️ **不追求 100% 自动拆题** —— 一律「机器出草稿 + 人工确认」
- ❌ **不做传统 OCR 前置**（PaddleOCR / Pix2Text 那类）—— 实测视觉模型直读印刷体扫描件
  整页全对，且自动忽略作答横线/条形码/页眉页脚；多一层 OCR 只会多一层错误传递
  （选型过程见 `docs/版面识别方案调研.md`）
- ❌ **批量识别不做答案（本轮范围）** —— 先把「题干 + 题型/难度/知识点/标签」跑通；
  答案仍走逐题录入页第 ② 步或事后「补答案」模式
- ❌ **不给 `questions` 加 `status` 字段** —— 待审条目单独一张表，`questions` 的语义
  保持「已确认可用」，下游（出卷/作业/反馈/笔记插题）一行都不用改（§3.2.1）
- ❌ **不让 AI 决定知识点挂到哪个节点** —— 它只给**名字**，挂载由服务端按
  归一化 + 包含关系判定；判不出来就留空 `node_id` 并保留原话，**不猜**（§3.8）
