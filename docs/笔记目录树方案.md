# 笔记目录树（分组 → 目录… → 笔记）

> 需求提出：2026-09-28。**状态：已实现**（迁移 `0014`；一级分组解绑体系见 `0015` / 2026-09-29）。
> 用户原话：「① 针对不同题型能够进行笔记归总，树结构：体系→笔记，例如 DSE→笔记；
> ② 笔记目录能够自由调整层级关系。」
> 2026-09-29 修正：「笔记部分的命名完全没必要用跟其他功能强绑定……要留更多拓展空间」
> —— 把顶层从「体系」改成「笔记自己的分组」（见 1.2）。

## 0. 一句话结论

笔记原来是一列平铺（标题 + 摘要 + 置顶），没有任何归档维度。现在长成一棵树：

```
DSE 数学                  ← 一级分组（笔记自己的分类，跟体系无关，随便建/改/删/排序）
 ├─ 一、有理数              ← 目录，可任意嵌套
 │   ├─ 1.1 认识有理数        ← 目录里还能是目录
 │   └─ 有理数运算错题         ← 笔记（永远是叶子）
 └─ 直接挂在分组下的笔记       ← 允许
IB 数学                    ← 再加一个分组：不用先去建体系
未归档                    ← 兜底容器：新建笔记没选目录时落这，固定排最后
```

## 1. 三个关键决定（改之前先读这节）

### 1.1 目录树**自己建一棵**，不复用题库的 `nodes`

`nodes` 是官方大纲（体系→模块→节→知识点→考点，还带大纲编号），学习路径是**定死的**；
而笔记目录是老师**自己的整理习惯**（「一、有理数 / 1.1 认识有理数」），要能随手拖。
两件事塞进一棵树，结果就是两边都不能动：动 `nodes` 会影响题库筛选，不动又满足不了笔记。

代价是同一个体系在库里有两个"树"，可以接受 —— 它们回答的是不同问题
（题目归哪个考纲 vs 这份笔记我想放哪）。

### 1.2 一级分组**跟体系解绑**（2026-09-29 改，这是本节最重要的决定）

初版把顶层直接定成「每个体系一行根」，名字从 `curricula` 现取。那等于给笔记加了个
它并不需要的约束（用户提出后改掉了）：

  · 想加一个「IB 数学」得先去**建体系**，而建体系会连带影响题库筛选与学生页；
  · 给分组改个名，题库与学生页的体系名也跟着变；
  · 而这个关联在笔记模块里**没有任何实际用处** —— 不筛题、不连课、不出卷，
    只决定「树上那一行叫什么」。

现在的规矩：

  · 一级分组是**笔记自己的东西**：能建、能改名、能删、能排序，名字只存在 `note_folders.name`；
  · `curriculum_id` 保留但降为**可选关联**（默认为空、不参与命名、不决定树的形状）——
    将来真要「按学生体系找笔记」还有抓手，只是现在不用它；
  · **系统不再自动补齐分组**：库里只有一个「未归档」（兜底容器）。
    想看哪个体系就去建一个同名分组，那是用户自己的选择；
  · 「未归档」固定排最后，不能改名/移动/删除 —— 新建笔记没选目录时落它，删分组的内容也去它。

### 1.2.1 为什么需要一个 `is_unfiled` 标记

以前「未归档」是靠「`is_root=1` 且 `curriculum_id IS NULL`」认出来的 —— 那个认法依赖
「一级节点必然来自体系」。解绑之后普通一级分组的 `curriculum_id` 也是空的，两者就分不出来了：
分不出来就分不出「新建笔记该落哪」「哪个不能删」。

所以迁移 `0015` 把这个身份**显式**写成一个字段（只有「未归档」一行 = 1）。
**能写出来的事实就别靠推断** —— 推断错的代价是把用户的分组当成兜底容器（或反过来）。

### 1.3 跨体系拖动不再存在

初版 1.2 讨论过「把一棵子树拖到别的体系下」怎么同步。解绑之后这个问题自动消失了：
一级分组不是任何别处数据的投影，跨分组拖动就是「换了个父节点」。

## 2. 数据模型（迁移 `0014` + `0015`）

```
note_folders
  id, owner_id
  curriculum_id  → curricula.id  ON DELETE SET NULL   -- 可选关联，只有老数据带着值
  parent_id      → note_folders.id ON DELETE CASCADE  -- NULL = 一级分组
  name, is_root, sort_order, is_unfiled, created_at

notes
  + folder_id → note_folders.id ON DELETE SET NULL    -- 可空只是安全网，应用层一律写值
  + sort_order                                        -- 同一目录里的手排顺序
```

- `is_root=1` = 顶层那一行（它的 `parent_id` 为空）；`is_unfiled=1` 只有「未归档」一行。
- `notes.folder_id` 可空**只是安全网**：万一目录行被别的路径删掉，笔记退回「未归档」而不是消失。
- 顺手把排序也统一了：`pinned desc, sort_order asc, updated_at desc`。
  老数据 `sort_order` 全是 0，靠 `updated_at` 兜底，所以**现有笔记的相对顺序没变**。

### SQLite 的三个坑（迁移里都踩过，别再踩）

1. `op.add_column` 加**带外键**的列会报「No support for ALTER of constraints in SQLite dialect」
   —— 必须走 `op.batch_alter_table`（内部是重建表）。
2. batch 模式里**外键必须起名字**（匿名外键报「Constraint must have a name」）。
3. batch 的"重建表"是**延迟到 with 退出时**才做的，所以 `create_index` 必须写在 batch **块里面**：
   写在外面会建在旧表上，旧表一换索引就没了（现象：列都在、`idx_notes_updated` 也在，
   只有新建的那个索引不见了）。

还有一个环境级的坑：**SQLite 的 DDL 不是事务性的**。迁移跑一半抛异常，前面建好的表和列会留着，
而 `alembic_version` 还停在上一版 → 下次启动撞「already exists」，看着像库坏了。
所以迁移要在**干净库**上先跑通：`backend/test_migration_0014.py` 就是干这个的（用 `SHIKE_DB_PATH`
指向临时库，正反各跑一遍，不碰真库）。

## 3. 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/note-folders/tree` | 整棵树 + 每个目录下的笔记（轻量字段）。**必须声明在任何 `/{fid}` 之前** |
| POST | `/api/note-folders` | `{name}`（**不传 `parent_id` = 建一级分组**）或 `{parent_id, name}`（建子目录） |
| PATCH | `/api/note-folders/{id}` | 改名 / 移动 / 排序共用：`{name?}`、`{parent_id?, position?}` |
| DELETE | `/api/note-folders/{id}` | **不删内容**：子目录与笔记上移（目录→父目录；分组→未归档），返回移了几样 |
| GET | `/api/notes?keyword=&folder_id=` | 平铺列表（搜索用），每条带 `path` |
| POST | `/api/notes` | 可带 `folder_id`；不传就落「未归档」 |
| PATCH | `/api/notes/{id}` | 多了 `folder_id` + `position`（拖动） |

`position` 是**"放在第几位"**，不是 `sort_order` 的值：客户端不需要知道序号是多少，
服务端把同级 `sort_order` 整段重写成 `0..n`（序号只要参与比较就会被插坏：两个 1.5 之间插不进第三个）。

## 4. 会拖坏树的三种操作，服务端必须自己挡

前端也判了一遍，但那只是体验 —— 请求可以绕过界面：

1. **把目录拖进自己的后代** → 那棵子树从根上断掉（数据还在，界面上整段消失）。
   `_is_ancestor()` 沿着 `parent_id` 往上走，带 `visited` 防脏数据绕圈。
2. **把目录拖进自己** / **把一级分组放进目录** / **改、排、删「未归档」** → 422。
   （一级分组的祖上链为空，一旦允许它变成子目录，「拖进自己的后代」这条断树的路就又多一个入口。）
3. **笔记传 `folder_id: null`** → 422。不做「传 null 就回未归档」——
   那会让一次写错的请求静默搬走笔记。

**删目录/删分组绝不删内容**：子目录与笔记一律上移（目录→父目录；分组→「未归档」），
并在返回里给出 `moved_folders/moved_notes`，让界面能把这句话说出来（「3 篇笔记已移到上一级」）。
静默删内容最不可原谅；静默搬走而不说，也让人以为东西没了。

## 5. 界面（`views/Notes.js` 左栏）

- **树一次拿全**，再在本地**摊成一维行**渲染。递归模板不好写、更不好拖；
  摊平之后拖拽只要算行号，落点提示也只是给某一行加个 class。
- 每个目录里**先列子目录、再列笔记**：两串 `sort_order` 互不干扰，拖动只在同类之间重排，
  不会出现「目录的 0/1/2 和笔记的 0/1/2 交错」这种没法解释的顺序。
- **笔记是叶子**：不能往里放东西。这样拖拽规则永远只有一条。
- 落点提示分三种：上沿一条线（插在前）、下沿一条线（插在后）、整行描边（放进去）。
- 拖拽用**浏览器原生**的（不引第三方库，跟项目零依赖一致）；每行「⋯」菜单里有
  重命名 / 上移 / 下移 / 删除，作为触控板拖不准时的兜底。
  菜单用 `fixed` 定位并**夹进视口**：行靠近窗口底部时菜单会掉到屏幕外，
  最后两项就点不到了（窄窗口里必现，实测 300×500 时踩到）。
  菜单高度按项数算（`8 + items.length * 28`），加项不用回来改常数。
- 一级分组的拖拽：分组只能在**分组之间**排前后（不能嵌套、不能插到目录之间）；
  「未归档」不可拖、也不能被当作插入点（它固定最后）。工具栏有「新建分组」，
  输入行渲染在**树的最上面**，而新分组也确实建在最前面 —— 所见即所得。
- 展开状态记在 `localStorage`；首次进来只展开**有内容的**分组（空分组收着，免得一屏全是空目录）。
- 搜索时**切成平铺结果 + 每行的路径**（「未归档 / 测试目录甲 / 1.1 认识有理数」）——
  在树里高亮反而难找，同名笔记也分不出是哪个「1.1」。路径**取分组自己的名字**，
  不再从体系现取（解绑后两者可以不同名）。
- 新建笔记/目录落在**选中的目录**里；没选就落「未归档」，永远不会没归属。
- **笔记/目录/分组都能重命名**（`⋯` → 重命名，原地变输入框）。几个容易做错的地方：
  - 笔记改的是**标题**，不是正文；`PATCH /api/notes/{id}` 只提交 `title` 一个字段，
    绝不顺手动正在自动保存队列里的 content/ink。
  - 改的正好是**当前打开着的那篇**时，要同步 `cur.title`，否则树上是新名字、顶部标题框还是旧的。
  - **行可能根本不在屏幕上**：目录收起时子行不渲染、搜索时整棵树被平铺结果取代。
    所以起改名之前先 `expandTo(笔记所在目录)`，并且**搜索列表里也渲染一份输入框**
    （两边共用同一份 `editing` 状态）。少了这一步，点了菜单像没反应。
  - `editing` 因此有个 `kind: 'folder' | 'note' | 'root'` —— 模板里的判断条件一样，
    但提交要去不同的接口（笔记走 `/api/notes`，目录与分组走 `/api/note-folders`）。
  - **一级分组改名不再波及别处**（解绑后它只是笔记这边一个名字）——
    初版那句「会影响题库/学生页」的确认弹框已删掉。

## 6. 待办 / 明确没做

- **题型分类**：用户最早说的「不同题型」当时按「体系」理解（例子是 DSE→笔记）。
  解绑之后「再开一个维度」已经不用改代码 —— 想按题型分就建几个分组。
  如果哪天要的是「**一篇笔记同时属于好几个维度**」（交叉分类），那就该上**标签**
  （跟树并存、一篇可以贴多个），数据结构上留了余地（加一张表 + 关联表，不动现有树）。
- **一篇笔记挂多个目录**：不做。会出现「我改的是哪一份」的问题，收益不值。
- **把已有子目录提升成一级分组**（反向操作）：不做。要的话得先想清楚它的 `curriculum_id`
  跟谁走 —— 现在只能新建分组再拖进去。
- **AI 自动归类**（按正文推荐目录）：等有需要再说，先把人工整理这条路走顺。
- **树上的拖拽没有做"多选批量移动"** —— 现在一次一个。
- **体系名本身的修改入口**：设置页现在只能**添加**体系、不能改名。
  笔记这边的改名已经跟体系脱钩（不会再连带改体系），所以这两件事互不影响。
