# 派发与留痕 → 笔记里插题 → 学生版 / 教师版

> 需求提出：2026-09-29。**状态：只有分析，未排期、未实施**。
> 用户原话：「每个学生既然建档了，后续可以根据学生作业完成情况、知识掌握情况，
> 给学生推笔记、题库练习；后续笔记中也可插入筛选题库中题目插入（包括题目和答案），
> 能够自动出学生版（不含答案）和教师版（含答案）。」
>
> **同一天的澄清（很重要，本文按这个写）**：
> 「我不是要做推荐算法，这里的推是**老师人为将要推的推到学生面板，统一记录**，
> 后续看学生情况时候就一目了然了。」
>
> 也就是说：**系统不选内容、不排序、不猜**；老师挑，系统负责**记下来、摆出来**。
> 相邻的一份想法记录是 [学生记忆与Agent方案.md](学生记忆与Agent方案.md)（讲记忆怎么分层与检索），
> 本文是「把发出去的东西留痕」这一层。

## 0. 一句话结论

**现在这套系统只有「收」，没有「发」。**

收到的都记得很细：每次课的反馈、每次作业交没交、五维评分、原件、配图、
`uploads/students/u<id>_<姓名>/<日期>/` 归档。但**「我发给他什么」一个字都没记** ——
发过哪套题、哪篇笔记、什么时候发的、他做没做，全靠老师脑子记和翻微信。

所以这件事的本质不是「智能」，是**一张派发台账**，挂在学生详情页上：

```
学生详情 → 派发记录
  09-20  一套题《一元二次方程专项 12 题》  学生版PDF  已发 → 已交回
  09-22  笔记《幂的运算法则整理》           学生版PDF  已发 → 还没动
  09-25  一套题《因式分解巩固 8 题》        学生版PDF  已发 → 做了一半
```

一眼能看到「我给过什么、他做了没」，这就是「一目了然」。

顺带说清：**「学生版 / 教师版」是这件事的前置能力** —— 派发总得有个能发出去的东西。
而这块在试卷那一层**已经实现了**（见 1），只是没做成两个明确的按钮。

## 1. 现状盘点（对着代码核过的）

| 能力 | 在哪 | 状态 |
|---|---|---|
| 学生建档 | `students` + `student_curricula` | ✅ |
| 每节课讲了哪些知识点 | `lessons.node_ids` | ✅ |
| 课堂表现 5 维评分 | `ability_dims` / `ability_scores`（人工打） | ✅ |
| **收**：作业状态 + 5 维评分 + 原件 | `homeworks` / `homework_scores` / `lesson_files` | ✅ |
| **收**：每节课的反馈（四段 + 整篇 + 配图 + 能力分） | `feedbacks` | ✅ |
| 学生归档目录（学生/日期） | `uploads/students/u<id>_<姓名>/<日期>/` | ✅ |
| 题库：题干/答案(文本)/答案图/知识点/标签/题型/用过几次 | `questions` | ✅ |
| 按知识点筛题（含同名节点整棵子树） | `GET /api/questions/search?kp=` | ✅ |
| 组卷导出，**末尾附答案** | `GET /api/papers/export?...&show_answer=`（html/docx/pdf） | ✅ |
| 笔记（Markdown + 公式 + 配图 + 目录树） | `notes` / `note_folders` | ✅ |
| 笔记导出 Word/PDF，**公式是真公式**（OMML） | `services/notes_export.py` | ✅ |
| **发**：我给他派了什么、他做没做 | —— | ❌ **完全没有** |
| 笔记里插入题库题目 | —— | ❌ 没有 |
| 题库截图进笔记导出 | `notes_export.add_picture` 只认 `/api/notes/files/nb_*` | ❌ 现在不认 `/api/crops/up_*` |

两个值得单独指出的发现：

**① 「学生版 / 教师版」在试卷这一层其实已经实现了。**
`papers/export` 的 `show_answer`（默认 true，界面上是「附参考答案」那个 chip）就是它，
答案统一附在卷尾。缺的只是**没把它当回事**：没有「学生版 / 教师版」两个明确的按钮，
没有「答案集中放卷尾还是紧跟题目」的选择，导出的文件名也不区分版本
（两份同名文件，发错是迟早的事）。

**② 「题目插进笔记再导出」，顺手能解决一个老限制。**
出卷的 Word/PDF 里公式是**原文**（服务端没有 LaTeX 引擎，要公式排版只能出 HTML —— 已知限制）；
而**笔记导出**有 OMML 那条路，Word 里是真公式。所以「题目 → 笔记 → 导出」得到的 Word
比「题目 → 直接出卷」**更好**。这不是碰巧，是笔记导出那条管线当初做得更认真。

## 2. 四个关键判断

### 2.1 派发与「作业」是**方向相反**的两件事，但要在**同一条时间轴**上

- `homeworks` 是 **inbound**：一节课一条（`UniqueConstraint(lesson_id)`），
  语义是「他交回来的 + 我对它的评价」，状态是 `submitted / late / missing`。
- 派发是 **outbound**：我发出去的东西，状态是「发了 / 他做了 / 交了 / 还没动」。

这两件事**不能揉进同一张表**：`homeworks` 有「一课一条」的唯一约束，
语义也是「收回来」的；把派发塞进去，会让「这次课的作业」这个概念变味，
而且派发不一定挂在某节课上（微信里随手发一套题是常态）。

但**在学生详情页上要摆在一起** —— 老师的心智模型是「这条时间线上发生了什么」。
现在的时间轴（上课记录）每条挂反馈与作业，派发应该成为同一条线上的第三种条目。
两个割裂的区块会让人来回对照，那就不叫「一目了然」了。

### 2.2 派发要能留下**可发的东西**，产物进已有的归档目录

派发不是「记一笔『我发了题』」就完了 —— 三个月后要能回答「当时发的是哪几题」。
所以：

- 记录里存**引用的内容**（哪些题目 id / 哪篇笔记 id / 哪份卷子）；
- 而**发出去的成品文件**（学生版 PDF）顺手落到**已有的** `students/u<id>_<姓名>/<日期>/`
  归档目录里 —— 那才是学生当时真正拿到的东西，也是最不会骗人的证据。
  归档布局早就在了（写反馈时就在往里存），不需要新机制。

### 2.3 状态只允许**人工更新**，系统不做任何推断

「他做了没」只能老师点。系统不看着作业照片判断有没有做，
也不用 AI 推断态度（项目里已有红线：AI 不给作业打分 —— 图片作业连题目都读不全）。
默认值是「已发」，老师只点要改的那几条，这样才有人愿意记。

### 2.4 快照 vs 引用，两个地方各有各的答案

- **派发台账**：引用就够了（它是一条「我发了什么」的日志，题目内容变了不影响日志的意义）。
- **笔记里插的题**：**必须存快照**。`delete_question` 会按引用计数删掉 `/api/crops/` 的截图
  —— 笔记里只留 URL 的话，老师删一道题，**学生讲义里的图会静默消失**。
  正确做法：插图时把题干/答案文本与图片**复制进笔记自己的资源目录**（`nb_` 前缀，
  受笔记的引用计数保护），同时记下 `qid` 以便溯源。
  这和「备份包要留人读副本」「作业原件改名后要能自解释」是同一条取向：
  **存下来的东西要能活过产生它的程序状态**。

## 3. 分期建议

### 阶段 0：把「学生版 / 教师版」做成两个明确按钮（很小，立刻有用）

- 出卷页那两个 chip（「附参考答案」「答案带解析」）改成 **出学生版** / **出教师版**。
- 加一个「答案位置」：集中卷尾 / 紧跟题目。
- **文件名带版本**：`高二专项_学生版.pdf` / `高二专项_教师版.pdf` ——
  同名两份是发错版本的头号原因。
- 学生版**生成时就不写入答案**（现在 `show_answer=false` 就是不渲染，已经是对的，
  别退化成「写进去再隐藏」—— docx 是个 zip，藏不住）。

**收益**：今天就能用（其实现在也能用，只是没人知道那个 chip 是干这个的）。

### 阶段 1：派发台账 + 学生面板上的一栏（这件事的核心）

- 新增一张 `assignments`：`student_id`、可选的 `lesson_id`、`kind`（笔记 / 题目集 / 卷子 / 文件）、
  内容引用（`note_id` / 题目 ids / 文件路径）、`sent_at`、`status`、备注。
- 入口做在**老师已经要发东西的地方**：出卷页「导出并记一笔」、笔记页「派发这篇」、
  学生详情页「派发（挑内容）」。
- 学生详情页：时间轴上多一种条目；**另外单独一栏**「派发记录（从新到旧，共 N 条）」，
  状态用一个词 + 颜色（已发 / 已交回 / 做了一半 / 还没动）。
- 状态由老师点（见 2.3）。

**收益**：这是你说的「一目了然」本身。**成本**：一张表 + 一处面板 + 两三个入口。

### 阶段 2：笔记里插入题库题目（讲课材料 = 讲解 + 练习）

- 正文里放一个**可识别的题目块**（如 `<!--q:qid-->`），预览与导出时展开成题号 + 题干 +
  （教师版才有的）答案。这样**一份笔记两种版本**，不会出现「学生版改了、教师版忘了改」的漂移。
- 存快照（见 2.4）；导出时把题库截图内嵌（`notes_export.add_picture` 要认新的资源副本）。
- 公式白拿：题目里的 `$...$` 走笔记导出的 OMML 管线，Word 里是真公式。
- 题目来源：复用出卷页已有的筛选与勾选逻辑，加一个「加入当前笔记」。

**收益**：派发的内容形态变丰富（讲义 + 练习一份材料），学生版/教师版复用阶段 0。

### 阶段 3（可选）：题目级结果

真要回答「这套题他做对了几道」，才需要记到题目级（现在是作业级的 5 维人工评分）。
先做**错题本**（只记错的是哪几题）比逐题三态现实得多，而且它本身就有用，不依赖任何推荐。

## 4. 难处（说实在的）

- **记录这件事本身没有回报，就不会有人记。** 所以阶段 1 的默认值要「点一下就走」：
  默认「已发」、只要点要改的；状态词要少（4 个以内）。
- **派发记录会腐烂**：内容被删了怎么办（笔记删了、题删了）。
  台账里要保留**发送时的标题快照**（「《因式分解巩固 8 题》（内容已删）」），
  而不是空着一格让人猜。
- **一次生成、两版不同**是这类功能的经典事故源。唯一的办法是同一份内容渲染两次，
  绝不允许存在两份正文。

## 5. 明确不做

- **推荐算法 / 自动挑题 / 自动排序**：按澄清，老师自己挑（见 0）。
- **AI 判断「他做了没 / 他会不会」**：沿用既有红线，状态只由老师点（见 2.3）。
- **学生端账号 / 云端推送**：本机工具，没有外网也没有学生账号；
  现实形态是「生成学生版 PDF → 打印或微信发」。
- **「综合能力分」**：已经有能力雷达（课堂 + 作业两套维度），别再合成分数（见下）。

## 6. 需要你拍板的四件事

1. **课本/微信里随手发的题，也要记吗？** 还是只记「系统里生成的那份」？
   只记生成的：入口自然（导出时就顺手记）；都要记：得允许「手工填一条」。
2. **派发记录要不要挂课时**（哪节课之后发的）？挂了能在时间轴上跟课程对齐；
   不挂更自由（微信里发的东西不一定属于某节课）。
3. **「他做了没」你愿意点到多细**？四态（已发 / 做了一半 / 已交回 / 还没动）/
   三态（已发 / 已交回 / 还没动）/ 只标「已交回」。
4. **学生版要不要连答案文件一起给**（老师手里两份，拿错风险），
   还是**学生版根本不出答案文件**（要答案只能出教师版）。
