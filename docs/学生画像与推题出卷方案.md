# 课后补充材料（挑题/挑笔记 → 下节课打印）

> 需求提出：2026-09-29。**状态：只有分析，未排期、未实施**。
>
> 用户的三次说明（第三遍才是完整流程，本文按它写）：
> 1. 「每个学生既然建档了，后续可以根据学生作业完成情况、知识掌握情况，给学生推笔记、题库练习；
>    后续笔记中也可插入筛选题库中题目插入（包括题目和答案），能够自动出学生版（不含答案）
>    和教师版（含答案）。」
> 2. 「我不是要做推荐算法，这里的推是**老师人为将要推的推到学生面板，统一记录**，
>    后续看学生情况时候就一目了然了。」
> 3. **「比如我今天上课了，学生提交了作业，我觉得他某部分掌握不好，就在题库和笔记中
>    找对应题目和笔记推给他，这些显示在**学生今天的情况**当中，后续上课我就能直接打印给线下学生。」**
>
> 相邻的想法记录：[学生记忆与Agent方案.md](学生记忆与Agent方案.md)（记忆分层与检索，未排期）。

## 0. 场景（照用户的话走一遍）

```
今天上完课
  → 学生详情，今天那条课
      ├─ 写反馈        （已有）
      ├─ 交作业        （已有：状态 + 五维 + 原件）
      └─ 课后补充 ← 老师觉得「他因式分解这块不行」
            从题库挑 3 道题（按知识点筛，已有）
            从笔记挑 1 篇（树里选，已有）
            保存 → 就挂在**今天这条课**里
下次上课前打开这个学生
  → 看到上次那条「课后补充：3 题 + 1 篇笔记（还没给）」
  → 点「打印学生版」→ 线下发给他
```

**所以这件事的本质：在既有的「一节课」记录里加第三块 —— 我准备下次给他的材料。**
不是一个新的「派发中心」，也不是推荐算法（用户已明确）。系统只干两件事：
**把挑好的东西存下来、下次能一键打印**。

## 2. 关键判断

### 2.1 它挂**课时**，一课可以有好几次 —— 所以「统一记录」是自然结果

用户说「显示在学生**今天**的情况当中」→ 数据上就是 `lesson_id`（今天那节课）。
而「先发 3 题、晚上又想加 2 题」也是常态，所以一课可以有好**几批**：

```
lesson（今天这节课）
  └─ 课后补充 ① 09-20 20:10   3 题 + 1 篇笔记   [已给]
  └─ 课后补充 ② 09-20 22:40   2 题               [待打印]
```

结构上就是两层：**一批**（挂 `lesson_id`、带提交时间与状态）+ **条目**（题目 / 笔记，各带引用 id
与标题快照）。不把条目直接挂课时：否则「哪几题是那次挑的」就分不出来，
而且状态只能整条课共用一个。

挂在课时上的直接好处：学生详情页那条时间轴本来就按课排，**补进去就不用另开一栏**，
「后续看学生情况一目了然」自动成立 —— 不需要发明一个新的浏览入口。

### 2.2 与「作业」方向相反，所以是同一条课里的**两块**，不是一块

- `homeworks` 是**收**：他交回来的 + 我对它的评价（`submitted / late / missing`）。
- 课后补充是**发**：我准备下次给他的（`待打印 / 已给 / 已交回`）。

两块并列在「今天这条课」里，正好对上老师的动作顺序：
**改作业 → 发现他哪块不行 → 顺手挑题**。第 3 步是第 1、2 步的延续，
所以入口就放在「交作业 / 改作业」旁边。

### 2.3 目的决定了一个状态：「还没打印」必须能冒出来

用户的原话是「**后续**上课我就能直接打印」——**打印发生在下一次**，
中间隔着几天。所以一批材料要能看出「走到哪一步了」：

```
挑好了（还没打印） → 打印出来给他了（已给） → 他把做好的交回来了（已交回）
```

- 意义就是：下次打开这个学生时，一眼能看出**哪些还没给**。
  不记这个，你只知道「上节课我准备了点东西」，但不知道到底给没给 —— 那就还得去翻纸。
- 顺手的地方：**点「打印」后自动置成「已给」**（已定，也可以手动改回来），
  老师只点要改的那几个。
- **关键**：下次打开这个学生时，**「上次留了 3 题还没给」要主动冒出来**（放学生详情页）。
  不然这条记录会像很多备忘一样，记了没人回头看 —— 那「统一记录」就白做了。
  这是本需求里最值得做的一个小设计。

### 2.4 打印需要「学生版」，所以那是最小的前置

给线下学生打印的东西**不能含答案**。出卷导出已经有 `show_answer` 开关
（默认 true，界面上是「附参考答案」那个 chip），`show_answer=false` 时答案**根本不渲染** ——
这件事其实已经是对的，只差把它变成明确的「**学生版 / 教师版**」两个按钮：

- 文件名带版本（`…_学生版.pdf` / `…_教师版.pdf`）—— 两份同名文件是发错版本的头号原因；
- 千万别退化成「答案写进去再隐藏」（docx 是个 zip，藏不住）。

### 2.5 打印是**两份纸**（已定）

「3 道题 + 1 篇笔记」打印时是**分别导**：题目走出卷 → 学生版 PDF；
笔记走笔记导出 → PDF。老师自己订起来。
两条管线都是现成的，不需要另做「合并打印件」；真用起来嫌麻烦再加。

### 2.6 每批记一句「针对什么」+ 可以写备注（已定）

一批材料除了「哪几题、哪篇笔记」，还要能看出**为什么挑它**。两个字段就够：

- **针对的知识点**（`focus`，一个词条）：复用题库已有的「知识点一律用名字」那套
  （`GET /api/questions/knowledge-points` 给「用过的」清单，也允许手写新的），
  不引入第二套知识点体系。
  - **默认从挑中的题目自动带出**（题目自己就有 `knowledge_points`），老师不改也能存。
  - 它带来的价值不是「推荐」，是**计数**：以后能看出「因式分解练过 3 次，最近一次 09-25」——
    仍然是可核对的事实，不是判断。
- **备注**（`note`，一句话，可空）：比如「这两题是课本 P42 的变式」。

两者都**可选**：不填也能存，「挑完就走」这条不能破（见 4）。

## 3. 分期建议（都很小，加起来也不大）

### 阶段 0：学生版 / 教师版（顺手的，今天就能用）

出卷页两个 chip 改成明确按钮 + 文件名带版本（见 2.4）。**成本**：前端两处。

### 阶段 1：课后补充（本需求的主体）

- 两张表：**批次**（`lesson_id` / `created_at` / `status` / **`focus` 知识点** / **`note` 备注**）
  + **条目**（`batch_id` / 类型（题目 / 笔记）/ 引用 id / **标题快照** / `sort_order`）。
- 入口：「学生详情 → 今天那条课」和「今日工作台 → 今日课程」里，
  在「交作业」旁边加「**课后补充**」；弹窗里两个页签：**挑题**（复用出卷页的筛选与勾选）/
  **挑笔记**（复用笔记树）；一天可以点多次，每次就是一批。
- 显示：就在这条课里，跟反馈、作业并列；一批一行，带状态标记。

### 阶段 2：下次上课时把它捞出来

- **学生详情页**上给提示：「有 2 批课后补充还没给（共 5 题）」。
- 「打印学生版」：题目拼成一次出卷导出（`show_answer=false`）→ 一份 PDF；
  笔记用笔记导出 → 另一份 PDF。**两份纸**，老师自己订。
- 打印后自动把这批置成「已给」（可手动改回）；
- 导出件顺手落进**已有的** `uploads/students/u<id>_<姓名>/<日期>/`
  —— 「我当时到底给了他哪份」有文件可查，不需要新机制。

### 阶段 3（可选，另一条线）

笔记正文里插入题库题目（讲义 + 练习合成一份材料）+ 一份笔记出两版（学生版/教师版）。
这块比上面大，且它解决的是「出讲义」而不是「课后补充」，可以后放。

## 4. 难处（说实在的）

- **记录没有回报就没人记**。所以阶段 1 必须「挑完就走」：默认状态、不填必填项
  （备注可留空）、挑题就是勾选。
- **被删的题/笔记**：记录里存引用，但**显示要自解释** ——
  存标题快照，删了就显示「《因式分解巩固 8 题》（内容已删）」而不是一片空白。
- **不主动提醒就一定忘**（见 2.3）。这条是本需求成败的关键，不是锦上添花。
- **打印件里的图**：题目截图在 `/api/crops/` 下，删题会被清理（`delete_question` 按引用计数删）。
  出卷导出是**导出时**把图抓进文件里，所以**已经导出的 PDF 不受影响**；
  但**记录本身别只指望图片 URL 还能用** —— 快照的是标题与文字，图要重新从题库取（取不到就标明）。

## 5. 不做

- **推荐算法 / 自动挑题 / 自动排序**：用户已明确，内容由老师挑。
- **AI 判断「他哪块不会」**：沿用既有红线（AI 不给作业打分）。
  老师凭上课与作业觉得「这块不行」，系统只负责把挑好的东西记下来。
- **学生端账号 / 云端推送**：本机工具，没有外网也没有学生账号；
  现实形态就是「打印出来线下发」——正是用户描述的方式。
- **「综合能力分」**：已有能力雷达（课堂 + 作业两套维度），别再合成分数。

## 6. 已定（用户 2026-09-29 全部确认）

1. **一课可以有好几次**：每次是一批（批次 + 条目两层，见 2.1）。
2. **状态三个词**：还没打印 / 已给 / 已交回；**点打印就自动置成「已给」**（可手动改回，见 2.3）。
3. **打印是两份纸**：题目走学生版 PDF，笔记走笔记导出的 PDF，老师自己订（见 2.5）。
4. **提醒放学生详情页**（不放今日工作台）。
5. **每批记「针对哪个知识点」**：默认从挑中的题目自动带出，可改、可不填（见 2.6）。
6. **有备注框**：可空（见 2.6）。

## 7. 以后再说

- **合并打印件**（题目 + 笔记合成一份 PDF）：现在两份纸，真嫌麻烦再加。
- **在今日工作台上统一提醒**（「今天有 2 个学生上次留的材料还没给」）：
  提醒先放学生详情页，用起来觉得会漏再加。
- **按知识点聚合看历史**（「因式分解练过 3 次」）：数据现成（`focus` 字段），
  先不急做界面。
- **笔记正文里插入题库题目**（讲义 + 练习一份材料 / 一份笔记出两版）：
  那是「出讲义」，不是「课后补充」，另开一轮（见原本的阶段 3）。
