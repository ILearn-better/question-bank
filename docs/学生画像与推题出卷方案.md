# 课后补充材料（挑题/挑笔记 → 下节课打印）

> 需求提出：2026-09-29。**状态：只有分析，未排期、未实施**。
>
> 用户的三次说明（第三遍才是完整流程，本文按它写）：
> 1. 「每个学生既然建档了，后续可以根据学生作业完成情况、知识掌握情况，给学生推笔记、题库练习；
>    后续笔记中也可插入筛选题库中题目插入（包括题目和答案），能够自动出学生版（不含答案）
>    和教师版（含答案）。」
> 2. 「我不是要做推荐算法，这里的推是**老师人为将要推的推到学生面板，统一记录**，
>    后续看学生情况时候就一目了然了。」
> 3. **「比如我今天上课了，学生提交了作业，我觉得他某部分掌握不好，就在题库和笔记中
>    找对应题目和笔记推给他，这些显示在**学生今天的情况**当中，后续上课我就能直接打印给线下学生。」**
>
> 相邻的想法记录：[学生记忆与Agent方案.md](学生记忆与Agent方案.md)（记忆分层与检索，未排期）。

## 0. 场景（照用户的话走一遍）

```
今天上完课
  → 学生详情，今天那条课
      ├─ 写反馈        （已有）
      ├─ 交作业        （已有：状态 + 五维 + 原件）
      └─ 课后补充 ← 老师觉得「他因式分解这块不行」
            从题库挑 3 道题（按知识点筛，已有）
            从笔记挑 1 篇（树里选，已有）
            保存 → 就挂在**今天这条课**里
下次上课前打开这个学生
  → 看到上次那条「课后补充：3 题 + 1 篇笔记（还没给）」
  → 点「打印学生版」→ 线下发给他
```

**所以这件事的本质：在既有的「一节课」记录里加第三块 —— 我准备下次给他的材料。**
不是一个新的「派发中心」，也不是推荐算法（用户已明确）。系统只干两件事：
**把挑好的东西存下来、下次能一键打印**。

## 2. 关键判断

### 2.1 它挂**课时**，一课可以有好几次 —— 所以「统一记录」是自然结果

用户说「显示在学生**今天**的情况当中」→ 数据上就是 `lesson_id`（今天那节课）。
而「先发 3 题、晚上又想加 2 题」也是常态，所以一课可以有好**几批**：

```
lesson（今天这节课）
  └─ 课后补充 ① 09-20 20:10   3 题 + 1 篇笔记   [已给]
  └─ 课后补充 ② 09-20 22:40   2 题               [待打印]
```

结构上就是两层：**一批**（挂 `lesson_id`、带提交时间与状态）+ **条目**（题目 / 笔记，各带引用 id
与标题快照）。不把条目直接挂课时：否则「哪几题是那次挑的」就分不出来，
而且状态只能整条课共用一个。

挂在课时上的直接好处：学生详情页那条时间轴本来就按课排，**补进去就不用另开一栏**，
「后续看学生情况一目了然」自动成立 —— 不需要发明一个新的浏览入口。

### 2.2 与「作业」方向相反，所以是同一条课里的**两块**，不是一块

- `homeworks` 是**收**：他交回来的 + 我对它的评价（`submitted / late / missing`）。
- 课后补充是**发**：我准备下次给他的（`待打印 / 已给 / 已交回`）。

两块并列在「今天这条课」里，正好对上老师的动作顺序：
**改作业 → 发现他哪块不行 → 顺手挑题**。第 3 步是第 1、2 步的延续，
所以入口就放在「交作业 / 改作业」旁边。

### 2.3 目的决定了一个状态：「还没打印」必须能冒出来

用户的原话是「**后续**上课我就能直接打印」——**打印发生在下一次**，
中间隔着几天。所以一批材料要能看出「走到哪一步了」：

```
挑好了（还没打印） → 打印出来给他了（已给） → 他把做好的交回来了（已交回）
```

- 意义就是：下次打开这个学生时，一眼能看出**哪些还没给**。
  不记这个，你只知道「上节课我准备了点东西」，但不知道到底给没给 —— 那就还得去翻纸。
- 顺手的地方：**点「打印」后自动置成「已给」**（已定，也可以手动改回来），
  老师只点要改的那几个。
- **关键**：下次打开这个学生时，**「上次留了 3 题还没给」要主动冒出来**（放学生详情页）。
  不然这条记录会像很多备忘一样，记了没人回头看 —— 那「统一记录」就白做了。
  这是本需求里最值得做的一个小设计。

### 2.4 打印需要「学生版」，所以那是最小的前置

给线下学生打印的东西**不能含答案**。出卷导出已经有 `show_answer` 开关
（默认 true，界面上是「附参考答案」那个 chip），`show_answer=false` 时答案**根本不渲染** ——
这件事其实已经是对的，只差把它变成明确的「**学生版 / 教师版**」两个按钮：

- 文件名带版本（`…_学生版.pdf` / `…_教师版.pdf`）—— 两份同名文件是发错版本的头号原因；
- 千万别退化成「答案写进去再隐藏」（docx 是个 zip，藏不住）。

### 2.5 打印是**两份纸**（已定）

「3 道题 + 1 篇笔记」打印时是**分别导**：题目走出卷 → 学生版 PDF；
笔记走笔记导出 → PDF。老师自己订起来。
两条管线都是现成的，不需要另做「合并打印件」；真用起来嫌麻烦再加。

### 2.6 每批记一句「针对什么」+ 可以写备注（已定）

一批材料除了「哪几题、哪篇笔记」，还要能看出**为什么挑它**。两个字段就够：

- **针对的知识点**（`focus`，一个词条）：复用题库已有的「知识点一律用名字」那套
  （`GET /api/questions/knowledge-points` 给「用过的」清单，也允许手写新的），
  不引入第二套知识点体系。
  - **默认从挑中的题目自动带出**（题目自己就有 `knowledge_points`），老师不改也能存。
  - 它带来的价值不是「推荐」，是**计数**：以后能看出「因式分解练过 3 次，最近一次 09-25」——
    仍然是可核对的事实，不是判断。
- **备注**（`note`，一句话，可空）：比如「这两题是课本 P42 的变式」。

两者都**可选**：不填也能存，「挑完就走」这条不能破（见 4）。

## 3. 分期建议（都很小，加起来也不大）

### 阶段 0：学生版 / 教师版（**已实施** 2026-09-29）

出卷页的「附参考答案」那个 chip 换成了两个明确的版本按钮：
**学生版（不含答案）** / **教师版（含答案）**；导出文件名带版本
（`…_学生版.pdf` / `…_教师版.pdf`）；导出按钮上也写着当前版本
（「预览 / 打印（学生版）」）；切到学生版时「答案带解析」自动置灰。

🔴 **顺手修了一个真 bug**：前端原来是 `show_answer: opts.show_answer ? true : undefined` ——
关掉时不发这个参数，而服务端默认值是 `true`，于是所谓「学生版」**其实带着答案**
（而且是真写进文件里的，不是隐藏）。现在一律显式传 `"false"`。

实测：`show_answer=false` 时答案确实不在文件里（学生版 HTML 里搜不到答案文本）、
教师版带答案、两份文件名不同；浏览器里拦下 `window.open` 核对过请求参数。

### 阶段 1：课后补充（**已实施** 2026-09-29，迁移 0016）

- 两张表：**批次**（`lesson_supplements`：`lesson_id` / `created_at` / `status` / `focus` / `note`）
  + **条目**（`lesson_supplement_items`：`kind` / `ref_id` / **`title` 标题快照** / `sort_order`）。
- 入口：「学生详情 → 那一节课」的「课后补充」按钮（就在「交作业」旁边），
  弹窗两个页签：**题库挑题**（关键词 + 标签 + 知识点，复用 `/api/questions/search`）/
  **挑笔记**（关键词，复用 `/api/notes`，带路径）。一天点几次就是几批。
- 显示：就在这条课里，跟反馈、作业并列；一批一行，带状态、时间、知识点、备注。
- 「还没打印」看橙色；每条都有「标为已给 / 已交回 / 删」。
- 知识点**默认从挑中的题目自动带出**（老师改过就不再动）。

### 阶段 2：下次上课时把它捞出来（**已实施** 2026-09-29）

- 学生详情页顶部出现提醒：「**有 N 批课后补充还没给**」（`GET /api/students/{sid}/supplements/pending`）。
- 每批一个「**打印学生版**」按钮：`POST /api/supplements/{id}/print` →
  排出**不含答案**的 PDF → 落进学生的归档目录（`students/u<id>_<姓名>/<日期>/…_课后补充_学生版.pdf`）
  → 状态自动置成「已给」→ 顺手把这几题的 `usage_count` +1（跟组卷同一个口径）。
- 笔记不在这一份里（用户定的「两份纸」）：去笔记页导出即可。

两个踩到的坑（都写进注释了）：
  · **HTTP 头只能是 latin-1**：归档路径里有中文学生姓名，直接塞进 `X-Supplement-Archived`
    会抛 `UnicodeEncodeError` → 整个接口 500。现在百分号编码。
  · **`download()` 默认是 GET**，而这个打印接口是 POST（它会写库）→ 404。现在 `download()` 收 method。

### 阶段 3：笔记里插题库的题（**已实施** 2026-09-29）

笔记正文里插入题库题目（讲义 + 练习合成一份材料）+ 一份笔记出两版（学生版/教师版）。
实现要点见下（动手前读，实际做的时候就是照这个来的）。

#### 阶段 3 的实现要点

- 正文里存一个**可识别的题目块**，而不是一段死文本：这样**一份笔记两种版本**，
  不会出现「学生版改了、教师版忘了改」的漂移（同一条道理：作业原件与反馈是两条线，
  一旦复制就一定会不同步）。
- **必须存快照**：`delete_question` 会按引用计数删掉 `/api/crops/` 里的截图 ——
  笔记里只留 URL 的话，老师删一道题，**学生讲义里的图会静默消失**。
  插图时把题干/答案文本与图片**复制进笔记自己的资源目录**（`nb_` 前缀，
  受笔记的引用计数保护），同时记下 `qid` 以便溯源。
  顺带的好处：图片变成 `nb_` 之后，`notes_export.add_picture()` 直接就能内嵌
  （它现在只认 `/api/notes/files/nb_*`）。
- **导出用预处理，不动 `notes_export`**：导出前把题目块注释替换成正文、
  学生版则整段删掉答案区 —— 已有的 Markdown → docx/pdf 管线一行不用改。
- 公式白拿：题目里的 `$...$` 走笔记导出那条 OMML 管线，Word 里是**真公式**。
- 搜索按用户说的：**标签 + 关键字**（`/api/questions/search` 两样都有），知识点也一并给了。

#### 实际做成的样子

块语法（三段注释，`services/note_questions.py` 里一份定义，插入/导出共用）：

```
<!--q:sq1-->              ← 引用的是哪道题（可溯源）
**练习 1**：解方程 …        ← 题干（可含公式与图片）
<!--qa-->                 ← 答案从这里开始
x=3 或 x=4
<!--qe-->
```

- 注释在 Markdown 预览里是**不显示**的（marked 会剥掉），所以老师看到的就是正常内容。
- 学生版是**从文件里删掉**答案那一整段，不是渲染时隐藏 —— docx 是个 zip，写进去再藏是藏不住的。
- 接口：`POST /api/notes/question-block {qid, index}` → 返回块文本（图顺手复制成 `nb_*`）。
- 导出：`GET /api/notes/{id}/export?with_answer=false`（学生版，标题自动带「（学生版）」，
  文件名也是 `…_学生版.docx`）；`frontend` 的导出弹窗里默认是教师版，正文里有题块时才显示这个开关。
- 前端：工具栏「插入题目」→ 弹窗（关键字 / 标签 / 知识点）→ 勾选 → 插到光标处，
  序号按正文里已有的题块数自动往上加。

实现时踩到的两个坑（都写进代码注释了）：
  · **中文紧跟 `**` 时加粗不生效**：`**练习 1：**解方程` 会渲染成字面的星号，
    得写成 `**练习 1**：解方程`（收尾的 `**` 后面跟标点才算合法收尾）。浏览器里实测到的。
  · **`Notes.js` 里有两个同名 `doExport`**（一篇笔记导出 / 全部笔记备份）：
    同一作用域里后声明的那个赢 —— 「导出 Word」按钮实际去下备份包，**不报错、看不出异常**。
    备份那个已改名 `exportBackup`。这个 bug 在功能加之前就存在。


## 4. 难处（说实在的）

- **记录没有回报就没人记**。所以阶段 1 必须「挑完就走」：默认状态、不填必填项
  （备注可留空）、挑题就是勾选。
- **被删的题/笔记**：记录里存引用，但**显示要自解释** ——
  存标题快照，删了就显示「《因式分解巩固 8 题》（内容已删）」而不是一片空白。
- **不主动提醒就一定忘**（见 2.3）。这条是本需求成败的关键，不是锦上添花。
- **打印件里的图**：题目截图在 `/api/crops/` 下，删题会被清理（`delete_question` 按引用计数删）。
  出卷导出是**导出时**把图抓进文件里，所以**已经导出的 PDF 不受影响**；
  但**记录本身别只指望图片 URL 还能用** —— 快照的是标题与文字，图要重新从题库取（取不到就标明）。

## 5. 不做

- **推荐算法 / 自动挑题 / 自动排序**：用户已明确，内容由老师挑。
- **AI 判断「他哪块不会」**：沿用既有红线（AI 不给作业打分）。
  老师凭上课与作业觉得「这块不行」，系统只负责把挑好的东西记下来。
- **学生端账号 / 云端推送**：本机工具，没有外网也没有学生账号；
  现实形态就是「打印出来线下发」——正是用户描述的方式。
- **「综合能力分」**：已有能力雷达（课堂 + 作业两套维度），别再合成分数。

## 6. 已定（用户 2026-09-29 全部确认）

1. **一课可以有好几次**：每次是一批（批次 + 条目两层，见 2.1）。
2. **状态三个词**：还没打印 / 已给 / 已交回；**点打印就自动置成「已给」**（可手动改回，见 2.3）。
3. **打印是两份纸**：题目走学生版 PDF，笔记走笔记导出的 PDF，老师自己订（见 2.5）。
4. **提醒放学生详情页**（不放今日工作台）。
5. **每批记「针对哪个知识点」**：默认从挑中的题目自动带出，可改、可不填（见 2.6）。
6. **有备注框**：可空（见 2.6）。

## 7. 以后再说

- **在今日工作台上统一提醒**（「今天有 2 个学生上次留的材料还没给」）：
  提醒先放学生详情页，用起来觉得会漏再加。
- **按知识点聚合看历史**（「因式分解练过 3 次」）：数据现成（`focus` 字段），
  先不急做界面。

  那是「出讲义」，不是「课后补充」，另开一轮（见原本的阶段 3）。
