# 学生画像 → 推笔记推题 → 讲义插题 → 学生版 / 教师版

> 需求提出：2026-09-29。**状态：只有分析，未排期、未实施**。
> 用户原话：「每个学生既然建档了，后续可以根据学生作业完成情况、知识掌握情况，
> 给学生推笔记、题库练习；后续笔记中也可插入筛选题库中题目插入（包括题目和答案），
> 能够自动出学生版（不含答案）和教师版（含答案）。」
>
> 这份文档只回答三件事：**现在已经有什么、缺的那块地基是什么、按什么顺序做最划算**。
> 相邻的一份想法记录是 [学生记忆与Agent方案.md](学生记忆与Agent方案.md)（讲「记忆怎么分层与检索」），
> 本文是它的下游落地（拿记忆去**出东西**）。

## 0. 一句话结论

这条链路里**已经有一半是现成的**（题库筛选、试卷导出、笔记导出公式都是真的），
缺的不是「AI 会不会推荐」，而是一个**最土的数据：这道题他到底做对没有**。
没有它，所谓「掌握情况」只能靠老师手工打分，推荐就只能推个大概。

所以顺序建议是：**先把「学生版/教师版」这件现成的事界面化（阶段 0）→ 再让笔记能插题（阶段 1）
→ 然后才开始记题目级结果（阶段 2）→ 最后才是推荐（阶段 3/4）**。
反过来先做推荐，会因为没数据而做成一个看起来聪明、实际靠猜的按钮。

## 1. 现状盘点（对着代码核过的）

| 能力 | 在哪 | 状态 |
|---|---|---|
| 学生建档 | `students` + `student_curricula` | ✅ 有 |
| 每节课讲了哪些**知识点** | `lessons.node_ids`（JSON 数组） | ✅ 有（且已经在用了） |
| 课堂表现 5 维评分 | `ability_dims` + `ability_scores`（按课时，人工打） | ✅ 有 |
| 作业：状态 + 5 维评分 + 原件 | `homeworks` / `homework_dims` / `homework_scores` / `lesson_files` | ✅ 有 |
| 题库：题干/答案/答案图/知识点/标签/难度/题型/用过几次 | `questions`（`answer` 是文本、`answer_image` 是图） | ✅ 有 |
| 按知识点筛题（含同名节点整棵子树） | `GET /api/questions/search?kp=` | ✅ 有 |
| 组卷 + 导出，**末尾附答案** | `GET /api/papers/export?...&show_answer=`（html/docx/pdf） | ✅ 有 |
| 笔记（Markdown + 公式 + 配图 + 目录树） | `notes` / `note_folders` | ✅ 有 |
| 笔记导出 Word/PDF，**公式是真公式**（KaTeX→MathML→OMML） | `services/notes_export.py` | ✅ 有 |
| **每题对错记录** | —— | ❌ **没有** |
| **知识点级掌握度** | —— | ❌ 没有（现在只有 5 个泛维度） |
| 笔记 ↔ 知识点 的关联 | —— | ❌ 没有（笔记只有目录） |
| 笔记里插入题库题目 | —— | ❌ 没有 |
| 题库截图进笔记导出 | `notes_export.add_picture` 只认 `/api/notes/files/nb_*` | ❌ 现在不认 `/api/crops/up_*` |

两个值得单独指出的发现：

**① 「学生版 / 教师版」在试卷这一层其实已经实现了。**
`papers/export` 的 `show_answer`（默认 true，界面是「附参考答案」那个 chip）就是它，
答案统一附在卷尾。缺的只是**没把它当回事**：没有「学生版/教师版」两个明确的按钮，
没有「答案紧跟题目 vs 集中放卷尾」的选择，导出的文件名也不区分两版
（两份文件同名时，发错版本是迟早的事）。

**② 「题目插进笔记再导出」，顺手能解决一个老限制。**
出卷的 Word/PDF 里公式是**原文**（服务端没有 LaTeX 引擎，这是文档里写明的已知限制，
要公式排版只能出 HTML）；而**笔记导出**有 OMML 那条路，Word 里是真公式。
所以「题目 → 笔记 → 导出」这条路，得到的 Word 比「题目 → 直接出卷」**更好**。
这不是凑巧，是笔记导出那条管线当初做得更认真。

## 2. 四个关键判断（做之前先接受这几条）

### 2.1 「推」的落地形态：老师端一键生成，不做学生端

本系统是**老师电脑上的本机工具**：没有学生账号、没有外网、数据不出本机（依赖全落 vendor）。
所以「给学生推练习」的现实形态是：

```
系统给出「该练这几题、看这篇笔记」→ 老师点一下 → 生成【学生版 PDF】→ 课上打印或微信发给学生
```

不做：学生登录、推送通知、云端同步。真要连学生端，那是另一个产品的量级，
和「数据存在本机」这条定位直接冲突（当年拒掉 CDN、拒掉服务端下图，是同一条线）。

### 2.2 推荐必须**可解释**，不要一个黑箱分数

推荐列表里每一条都要能说清三件事：**命中哪个知识点**、**凭什么推它**
（「这题他没做过」/「上次这类错了 2 道」）、**他上次的表现**（带日期与课时号）。

沿用本项目在「学生记忆」里已经定下的调子：**可核查 > 聪明**。
一个说得出理由的清单，比一个「AI 认为他该练这个」有用得多 —— 后者老师不敢用。

### 2.3 掌握度只能用**可核对的事实**，且 AI 不参与判断

项目里已经有一条红线：**AI 不许给作业打分**（图片作业连题目都读不全，
凭笔迹/涂改推断「粗心」是伪科学，而且会被当真去误导家长）。

掌握度同理，只能由这些**事实**累计出来：做过/没做过、对/错、老师明确标的薄弱点。
AI 在这条链路上只配做两件事：**组织与措辞**（把清单写成一段话）、**整理**（把口述转成结构化）。
它不该出现在「他会不会」这个判断里。

### 2.4 别做出第二个总分

现在已经有「能力雷达」（5 个泛维度，人工打分，课堂 + 作业两套）。
知识点掌握度是**另一种东西**：它是计数事实（这个知识点做过 4 题、对 2 题、最近一次对），
不是评价。两者要**分开显示**，千万别合成一个「综合能力 78 分」——
已有的教训是：一个数字一旦出现，所有人都会只看那个数字。

## 3. 分期建议（按性价比排序）

### 阶段 0：把「学生版 / 教师版」界面化（很小，立刻有用）

- 出卷页那两个 chip 改成明确的两个按钮：**出学生版**（不含答案）/ **出教师版**（含答案）。
- 加一个选项：**答案位置**（集中卷尾 / 紧跟题目）。
- **导出文件名带版本**：`高二专项_学生版.pdf` / `高二专项_教师版.pdf`。
  同名两份是发错版本的头号原因。
- 顺手（可选）：让学生版的答案**真的不写进文件**（现在 `show_answer=false` 就是不渲染，已经是对的，
  别退化成「写进去再隐藏」——docx 是个 zip，藏不住）。

**收益**：今天就学生能用。**成本**：前端两个按钮 + 一处文案。

### 阶段 1：笔记里插入题库题目（讲义 + 练习合成一份材料）

这是这份需求里最实用的一块：老师写讲解、随手插几道题、一键出学生版。

要点（每一条都有代码层面的原因）：

- **正文里放一个可识别的题目块**，而不是一段死文本。例如正文里写
  `<!--q:qid-->`（或 `{{q:qid}}`），预览与导出时展开成题号 + 题干 + （教师版才有的）答案。
  这样**一份笔记两种版本**，不会出现「学生版改了、教师版忘了改」的漂移
  （同一个原因：作业的原件与反馈是两条线，一旦复制就一定会不同步）。
- **必须存快照，不能只存引用**。`delete_question` 会按引用计数删掉 `/api/crops/` 里的截图
  —— 笔记里只留 URL 的话，老师删一道题，**学生讲义里的图就一起没了**（而且是静默的）。
  正确做法：插图时把题干/答案文本与图片**复制进笔记自己的资源目录**（`nb_` 前缀，
  受笔记的引用计数保护），同时记下 `qid` 以便溯源。这条和「备份包要留人读副本」
  「作业原件改名后要能自解释」是同一种取向：**存下来的东西要能活过产生它的程序状态**。
- **导出要把题库截图内嵌**：`notes_export.add_picture()` 现在只认 `/api/notes/files/nb_*`，
  要扩成「也认笔记资源目录里的副本」（因为快照就是 `nb_` 的，所以复制完其实自动就解决了）。
- **公式白拿**：题目里的 `$...$` 会走笔记导出那条 OMML 管线，Word 里是真公式。
- 题目来源：复用出卷页已经有的筛选与选中逻辑（`questions/search` + 勾选），
  加一个「加入当前笔记」。

**收益**：老师从此能产「讲解 + 练习」一份材料，学生版/教师版复用阶段 0。
**成本**：中等（占位语法 + 渲染 + 图片复制 + 导出三格式各一处）。

### 阶段 2：记「每题做没做、对没错」（推荐的地基）

现在作业只记 5 个维度的人工评分，**没有任何一题一题的结果**。这就是「掌握情况」缺的原料。

原则是**顺手就能记**，否则没人记：

- 最轻的形态：在这份作业/这节课里**勾选本次涉及的题目**（从题库选，或从刚插进笔记的题带过来），
  每题三态：`对 / 错 / 部分对`，**默认「对」**，老师只点要改的那几个。
- 更轻的形态（可选）：**只记错题**（「本次错题：第 3、7 题」），掌握度就用「被列入错题」当负信号。
  这比要求老师逐题打勾现实得多。
- 数据落点：新增一张 `attempts`（`student_id`, `question_id`, `lesson_id`, `result`, `at`），
  不碰现有 5 维评分 —— 那是「评价」，这是「事实」，两码事。

**副产品**：**错题本**几乎免费就有了（按学生查 `result=错` 的题，按知识点分组）。
这件事本身就有独立价值，可以先只为它做。

### 阶段 3：按知识点出「针对性练习」

有了阶段 2 的数据，这一步就很直白：

```
学生的薄弱知识点（按错题计数 + 最近一次）→ 每个知识点取 N 题（优先没做过、usage_count 少的）
→ 复用 papers/export 出【学生版 PDF】→ 老师发出去
```

现成的东西：`?kp=知识点名` 筛题（含同名节点整棵子树）、`sort=usage`（少用的优先）、
`show_answer=false` 出学生版。要写的是「挑哪几题」的那点规则 —— **规则要写死、可解释**，
不要做成「AI 挑题」。

### 阶段 4：推笔记（最后做）

题目 ↔ 知识点已经有两条路（`questions.node_id` 与 `knowledge_points` 文本），
但**笔记 ↔ 知识点没有**。要么给笔记加知识点字段（老师手动挂，跟目录树是两套维度），
要么靠「笔记里插过的题」倒推。

最后做的理由：笔记的知识点关联比题目难自动获得，而它带来的价值（「这个知识点去看那篇笔记」）
在阶段 3 的练习材料面前是锦上添花。

### 阶段 5（可选）：AI 只做组织与措辞

比如把「该练的清单」写成一段给家长看的话，或把老师口述的错题整理成结构化记录。
仍然要过「会发出去什么」的预览（项目既有规矩），且**不参与判断**（见 2.3）。

## 4. 真正的难处（说实在的）

- **阶段 3/4 的上限由阶段 2 的数据密度决定**。老师不会为了推荐去逐题打勾，
  所以阶段 2 的设计目标不是「记得全」，而是「记了就有用」——先做错题本，让记录本身有回报。
- **「推」这件事在两三个学生身上看不出价值**。它要的是「几十节课 + 几百次做题」的积累。
  现阶段先用最土的方式（错题本 + 按知识点出练习）把数据攒起来，别急着做「智能」。
- **一次生成、两版不同**是这类功能的经典事故源（学生版改了、教师版没跟上）。
  唯一的办法是**同一份内容渲染两次**，绝不允许存在两份正文。

## 5. 明确不做

- **学生端账号 / 云端推送**：与本机工具的定位冲突（见 2.1）。
- **AI 判断掌握度 / 给作业打分**：与既有红线冲突（见 2.3）。
- **「综合能力分」**：会出现第二个总分，误导性强（见 2.4）。
- **笔记里存题目引用而不存快照**：删题会静默弄丢讲义里的图（见阶段 1）。

## 6. 需要你拍板的四件事

1. **「推」要不要留下「布置」记录**？（谁、哪天、发了哪几题 / 哪篇笔记）
   不记：老师自己心里有数，系统更轻。
   记：以后能回答「上周发的那份练了吗」，但要多一张表与一套界面。
2. **题目级结果愿意记到什么程度**？逐题三态 / 只记错题 / 先不记（只靠老师口头与评价）。
   这直接决定阶段 3 能不能做出「像样的针对性练习」。
3. **学生版要不要连答案文件一起给**（老师手里两份，发的时候容易拿错），
   还是**学生版根本不出答案文件**（要答案只能出教师版）。
4. **掌握度给谁看**：只老师自己 / 也给学生家长看。
   给家长看的话，措辞与颗粒度就是另一档要求（而且要防「拿还没学过的知识点说事」）。
