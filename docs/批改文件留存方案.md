# 批改文件留存（学生资料 → 上课记录 · 每节课下）

> ⚠️ 位置在实现过程中改过一次：最初放在独立的「改作业」卡片里，
> 2026-10-21 用户要求挂到「对应课下」，后来又把那张卡片整个去掉（见 5.2）。
> 下面第 3 节的需求原文保留原样，不代表现在的 UI 结构。

用户 2026-10-20 的需求：

> 批改后的文件按「学生 / 日期」目录保存……在「学生资料 → 改作业」中自动生成批改记录，
> 关联学生、日期、作业、批改人与文件；点开该记录即可预览学生本次作业的批改情况。

目标流程：

```
上交作业 → 批改作业 → 「导出到作业存档」 → 学生资料·上课记录·那节课下 → 点开预览
```

## 1. 目录布局

沿用 `services/storage.py` 已有的「学生 / 日期」归档，只多一层子目录：

```
data/uploads/students/
  u1_李芹旭/                    ← 与讲义、反馈配图同一个学生目录（带 id，重名不撞）
    2026-10-20/
      讲义.pdf                 ← 上课材料（既有）
      批改/                    ← 本模块
        批改_李芹旭_20261020.pdf
        批改_李芹旭_20261020_2.pdf   ← 同一天存第二版，加 _2（不覆盖）
```

两个决定：

- **日期用「批改那天」，不是「点存档那天」。** 目录是给人翻的：过两周要回顾
  「10 月 20 号那节课的作业」，按作业日期分才找得到；按存档日期分会出现
  「同一节课的卷子散在好几天里」（`storage.py` 对这件事有同样的解释）。
  老师也可以手填一个日期补存上周的卷子。
- **多一层 `批改/`。** 那个日期格里已经躺着讲义、反馈配图、作业原件快照。
  批改存档也是 PDF，但它是**一次批改的产物**，混进去「这格里有几份东西」就说不清了。

## 2. 数据模型：`grade_archives`（迁移 0032）

| 字段 | 说明 |
|---|---|
| `student_id` | FK students，CASCADE（学生删了，他的存档也没意义） |
| `grade_id` | FK homework_grades，**可空 + SET NULL** |
| `lesson_id` | 冗余，便于按课时找（批改被清理了还留得住） |
| `archived_on` | `YYYY-MM-DD`，**与目录名同一个值** |
| `name` / `stored_name` | 老师看到的原名 / 避重后的真名 |
| `rel_path` | 相对 `UPLOAD_DIR` 的路径（不存绝对路径） |
| `kind` / `size_bytes` | 预览能力与体积 |
| `source` | `grade`（从批改导出）/ `upload`（手传） |
| `grader` / `note` | 批改人、备注 |
| `owner_id` | 与全库一致，将来接登录只改这一处 |

**为什么不加在 `homework_grades` 上**：

1. 一份批改可以存多次（存完发现漏看一页，改完再存）—— 加列只能留最新一次；
2. 也可以完全没有批改（线下批好的卷子直接拍照传进来），那种记录没有 grade 可挂；
3. 批改任务是可清理的中间产物，存档是**另一份工作成果**，生命周期不该绑在一起。

## 3. 接口（`routers/grade_archives.py`）

| 方法 | 路径 | 作用 |
|---|---|---|
| POST | `/api/grade-archives/generate` | 从批改导出带笔迹的 PDF 并归档（body 只需 `grade_id`） |
| POST | `/api/grade-archives/upload` | 老师手传一份（multipart） |
| GET | `/api/students/{sid}/grade-archives` | 这个学生的存档列表 |
| GET | `/api/grade-archives/{aid}` | 详情（含判定分布） |
| GET | `/api/grade-archives/{aid}/raw?inline=1` | 取原件（图片/PDF 可内嵌） |
| DELETE | `/api/grade-archives/{aid}` | 删记录**连文件** |

`generate` 由**后端自己出 PDF**（复用 `grade_export.export_grade`），前端只发一个
`{grade_id}`。刻意不做「前端先下载再上传」：一份 14 页的卷子 PDF 有 20MB 上下，
在浏览器里过一遍要几秒，而服务端本来就有渲染能力。

## 4. 校验与权限

- **类型走白名单**：pdf / png / jpg / webp / gif / bmp / doc / docx / xls / xlsx / ppt / pptx / txt / md / zip。
  没有 svg / html —— 它们会被浏览器执行，而这个功能支持内嵌预览，等于开一个 XSS 口子。
- **上限 60MB**、**0 字节拒**（空文件点开是一张白纸，比报错更迷惑）。
- **同名加 `_2`**，且先写临时文件再 rename（中途失败不留半截文件）。
- **文件名过 `storage.safe_token`**：`../../evil.pdf` 落不到归档目录外面去。
- **读回只认库里的 `rel_path`**，经 `storage.safe_join`，越界一律返回 None。
- **`owner_id` 过滤**：别人的记录读不到，返回 404 而不是 403（不泄露存在性）。
- **`grade_id` 必须属于同一个学生**，否则 422 —— 不能把 A 的批改静默挂到 B 的资料里。

## 5. 页面改动点

| 页面 | 改动 |
|---|---|
| `frontend/workbench.html`（批改工作台） | 顶栏加「导出到作业存档」；`archiveGrade()` 先 `flushPending()` 再调接口 |
| `frontend/src/views/HomeworkGrade.js`（A 路线） | 同上，按钮在导出按钮旁 |
| `frontend/src/views/StudentDetail.js` | 「上课记录」每节课下逐行列这节课的存档（预览弹窗 + 查看/下载/删）；**不再有**「改作业」平铺总览卡片（见 5.2） |
| `frontend/src/api.js` | `gradeApi.archive` + `archiveApi` |
| `frontend/app.css` | `.archive-line`（课下/孤儿行一组样式） |

⚠️ **两处批改页都必须先 `flushPending()`**：导出读的是**服务端**标注，刚画的几笔还在
本机队列里。不冲的话存出来的 PDF 少了那些笔迹，而屏幕上看着是完整的。

### 5.1 存档挂到「对应课下」（2026-10-21）

归档的落点是「学生资料 → 改作业」，但老师的心智模型是**「这次课的作业」**（跟 `homeworks`
一节课一条同一个道理），所以存档还要出现在那节课下面：

| 位置 | 内容 |
|---|---|
| 学生资料 →「上课记录」每节课 | 这节课的存档逐行列（`批改存档 · 文件名 · 存档于日期 · 大小`），带「查看」「下载」 |
| 学生资料 →「上课记录」顶部（条件） | 没挂到课时的存档（删过课 → `lesson_id` 变 NULL）单独提示一行，**正常 0 条、完全不出现** |

口径只有一条：`lesson_id`。

- 从批改导出的存档自带 `lesson_id`（= `grade.lesson_id`，非空外键）；
- 没挂课的（课被删 → 迁移里是 SET NULL）落到 `orphanArchives` 那一行，
  不因为没分组就在页面上「凭空消失」（磁盘上文件还在，找不到才是最糟的）；
- 手传入口已随总览卡片一起去掉（见 5.2），线下卷子走批改台「上传文件」→ 批完导出。

分组在前端做（`computed archivesByLesson`）：`list_for_student` 本来就一次返回全量
（一个学生一年几百条摘要，很轻），再加一个「按课查」的接口只会多一套要维护的口径。

### 5.2 「改作业」总览卡片去掉（2026-10-21）

存档挂到课下之后，那张平铺卡片就只是**同一批数据出现两次**（改一处对不上另一处），
用户点名去掉。一并去掉的：`＋ 上传存档` 按钮 + 隐藏 `input[type=file]` +
`pickArchiveFile/onArchiveFile`、`app.css` 里的 `.archive-row/-main/-head`。

- `POST /api/grade-archives/upload` **后端保留**（同一套校验/落盘，将来或脚本仍可用），只是没有页面入口；
- 孤儿行不是「总览卡片复活」：没有上传入口、不单独占一张卡、空的时候连标题都没有。

## 6. 预览规则

- 图片 → `<img>`；PDF → `<iframe>`（浏览器内置阅读器，不执行脚本，安全）。
- Word / Excel / 压缩包 → **只给下载**。拖进 iframe 只会是白屏或乱码，比给个按钮糟得多。
- 判断结果由后端给（`can_preview`），前端不按后缀自己猜 —— 两处规则迟早会不一致。

## 7. 已知取舍

- 存档**不做版本管理**：同一份批改存两次就是两条记录、两个文件，界面上平铺。
  「这是第几版」靠文件名里的 `_2` 与时间区分，没有 diff。
- 一个学生的存档列表默认最多 200 条（`limit`），按日期倒序。攒够一年会有几百条，
  届时该做年份折叠，现在先不加（列表只给摘要，200 条很轻）。
- **页面不再有手传入口**（2026-10-21 随总览卡片一起去掉）：接口还在，线下卷子走
  批改台「上传文件」→ 批完导出这条路。若将来想恢复成「上传时选哪节课」，
  只需在上传表单加一个下拉并给 `archive_store.create` 传 `lesson` —— 它已经能收
  `grade` 之外的存档，改的只是「lesson_id 从哪来」。
- 降级（`alembic downgrade`）**只删表、不删磁盘文件** —— 那些是老师的劳动成果，
  降级一次就抹掉不可接受；要清文件得在界面上逐条删（会真删）。
