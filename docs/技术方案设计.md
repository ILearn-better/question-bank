> 版本：v1.0 | 日期：2026-08-15 | 场景：个人教师自用 · 理科（数理化） · Web 应用

## 一、技术选型

### 1.1 总览

| 层级 | 技术选型 | 选型理由 |
|------|---------|---------|
| 前端框架 | Vue 3 + Vite | 生态成熟，中文社区强，Ant Design Vue 组件丰富 |
| UI 组件库 | Ant Design Vue 4.x | 表单/表格/树形组件齐全，适合管理后台 |
| 公式渲染 | KaTeX | 比 MathJax 快 100 倍，渲染即时，支持 LaTeX 语法 |
| 富文本编辑 | TipTap 2.x | 模块化架构，可自定义 LaTeX 节点，支持图片嵌入 |
| 状态管理 | Pinia | Vue 3 官方推荐，API 简洁 |
| 后端框架 | Python FastAPI | 自动生成 OpenAPI 文档，异步支持好，Python 生态适合 OCR/AI |
| ORM | SQLAlchemy 2.0 + Alembic | 类型安全，迁移管理成熟 |
| 数据库 | PostgreSQL 16 | JSONB 存储题目内容，GIN 索引支持标签快速查询 |
| 文件存储 | 本地文件系统（MVP）→ MinIO/对象存储（V2） | 个人自用阶段本地足够，后续可平滑迁移 |
| OCR（文字） | 百度OCR 通用文字识别 API | 中文识别率高，免费额度够用 |
| OCR（公式） | pix2tex（本地部署）→ Mathpix API（付费升级） | pix2tex 免费开源，Mathpix 精度最高 |

### 1.2 为什么选 PostgreSQL 而不是 MySQL

- **JSONB 字段**：题目内容（题干+选项+答案+解析）结构不固定，JSONB 比 MySQL JSON 性能更好
- **GIN 索引**：可以对标签数组建索引，多标签筛选查询性能优异
- **数组类型**：知识点 ID 数组可以直接用原生数组类型存储

### 1.3 为什么选 FastAPI 而不是 Node.js

- **OCR/AI 生态**：pix2tex、PaddleOCR 等 OCR 库都是 Python 原生，Node.js 调用需要子进程，体验差
- **自动文档**：FastAPI 自动生成 Swagger UI，前端可以直接看 API 文档
- **异步性能**：FastAPI 基于 Starlette，异步性能不输 Node.js

## 三、数据库设计

### 3.1 核心表结构

#### questions（题目表）

```sql
CREATE TABLE questions (
    id              SERIAL PRIMARY KEY,
    subject         VARCHAR(20) NOT NULL,        -- 学科: physics/math/chemistry
    type            VARCHAR(20) NOT NULL,        -- 题型: choice/multi_choice/fill/calculation/experiment
    difficulty      SMALLINT DEFAULT 2,          -- 难度: 1基础 2中档 3拔高
    stem            JSONB NOT NULL,              -- 题干 {type: "text|latex|image", content: "..."}
    options         JSONB,                       -- 选项 (选择题) [{"key":"A","content":...}]
    answer          JSONB,                       -- 标准答案
    analysis        JSONB,                       -- 解题步骤/解析
    score           DECIMAL(5,1) DEFAULT 5.0,    -- 默认分值
    source          VARCHAR(200),                -- 来源: "2024高考全国卷"
    cognitive_level VARCHAR(20),                 -- 认知层次: remember/understand/apply/analyze
    image_urls      TEXT[],                      -- 题目配图路径数组
    created_at      TIMESTAMP DEFAULT NOW(),
    updated_at      TIMESTAMP DEFAULT NOW()
);

-- 全文搜索 + JSONB 查询索引
CREATE INDEX idx_questions_subject_type ON questions(subject, type);
CREATE INDEX idx_questions_difficulty ON questions(difficulty);
CREATE INDEX idx_questions_stem_gin ON questions USING GIN (stem);
```

#### knowledge_points（知识点树）

```sql
CREATE TABLE knowledge_points (
    id          SERIAL PRIMARY KEY,
    parent_id   INTEGER REFERENCES knowledge_points(id) ON DELETE CASCADE,
    subject     VARCHAR(20) NOT NULL,
    name        VARCHAR(100) NOT NULL,
    level       SMALLINT NOT NULL,        -- 0=学科 1=章 2=节 3=知识点 4=细分考点
    sort_order  INTEGER DEFAULT 0,
    created_at  TIMESTAMP DEFAULT NOW()
);

CREATE INDEX idx_kp_parent ON knowledge_points(parent_id);
CREATE INDEX idx_kp_subject ON knowledge_points(subject);
```

#### question_knowledge_points（题目-知识点关联）

```sql
CREATE TABLE question_knowledge_points (
    question_id          INTEGER REFERENCES questions(id) ON DELETE CASCADE,
    knowledge_point_id   INTEGER REFERENCES knowledge_points(id) ON DELETE CASCADE,
    PRIMARY KEY (question_id, knowledge_point_id)
);

CREATE INDEX idx_qkp_kp ON question_knowledge_points(knowledge_point_id);
```

#### tags（标签表）

```sql
CREATE TABLE tags (
    id      SERIAL PRIMARY KEY,
    name    VARCHAR(50) NOT NULL,
    type    VARCHAR(30) NOT NULL,    -- difficulty/question_type/source/cognitive/custom
    UNIQUE(name, type)
);
```

#### question_tags（题目-标签关联）

```sql
CREATE TABLE question_tags (
    question_id  INTEGER REFERENCES questions(id) ON DELETE CASCADE,
    tag_id       INTEGER REFERENCES tags(id) ON DELETE CASCADE,
    PRIMARY KEY (question_id, tag_id)
);

CREATE INDEX idx_qt_tag ON question_tags(tag_id);
```

#### students（学生表）

```sql
CREATE TABLE students (
    id          SERIAL PRIMARY KEY,
    name        VARCHAR(50) NOT NULL,
    class_name  VARCHAR(50),
    remark      TEXT,
    created_at  TIMESTAMP DEFAULT NOW()
);
```

#### assignments（作业表）

```sql
CREATE TABLE assignments (
    id           SERIAL PRIMARY KEY,
    title        VARCHAR(200) NOT NULL,
    description  TEXT,
    deadline     TIMESTAMP,
    status       VARCHAR(20) DEFAULT 'draft',   -- draft/published/closed
    created_at   TIMESTAMP DEFAULT NOW(),
    updated_at   TIMESTAMP DEFAULT NOW()
);
```

#### assignment_questions（作业-题目关联）

```sql
CREATE TABLE assignment_questions (
    assignment_id  INTEGER REFERENCES assignments(id) ON DELETE CASCADE,
    question_id    INTEGER REFERENCES questions(id),
    sort_order     INTEGER DEFAULT 0,
    score          DECIMAL(5,1) NOT NULL,
    PRIMARY KEY (assignment_id, question_id)
);
```

#### student_assignments（学生作业记录）

```sql
CREATE TABLE student_assignments (
    id             SERIAL PRIMARY KEY,
    student_id     INTEGER REFERENCES students(id) ON DELETE CASCADE,
    assignment_id  INTEGER REFERENCES assignments(id) ON DELETE CASCADE,
    status         VARCHAR(20) DEFAULT 'pending',  -- pending/submitted/graded
    total_score    DECIMAL(5,1),
    submitted_at   TIMESTAMP,
    graded_at      TIMESTAMP,
    UNIQUE(student_id, assignment_id)
);
```

#### student_answers（学生答题记录）

```sql
CREATE TABLE student_answers (
    id                     SERIAL PRIMARY KEY,
    student_assignment_id  INTEGER REFERENCES student_assignments(id) ON DELETE CASCADE,
    question_id            INTEGER REFERENCES questions(id),
    answer                 JSONB,               -- 学生答案
    is_correct             BOOLEAN,             -- 判分结果
    score                  DECIMAL(5,1),        -- 得分
    graded_by              VARCHAR(20),         -- auto/manual
    graded_at              TIMESTAMP,
    created_at             TIMESTAMP DEFAULT NOW()
);
```

#### exam_templates（组卷模板）

```sql
CREATE TABLE exam_templates (
    id           SERIAL PRIMARY KEY,
    name         VARCHAR(100) NOT NULL,
    rules        JSONB NOT NULL,    -- 组卷规则
    created_at   TIMESTAMP DEFAULT NOW()
);

-- rules 示例:
-- {
--   "total_score": 100,
--   "sections": [
--     {"name": "选择题", "type": "choice", "count": 10, "score_per": 4, "difficulty": [1,2]},
--     {"name": "计算题", "type": "calculation", "count": 3, "score_per": 20, "difficulty": [2,3]}
--   ],
--   "knowledge_points": [12, 15, 23],
--   "avoid_recent": true
-- }
```

### 3.2 ER 关系概览

```
knowledge_points (1) ──< question_knowledge_points >── (N) questions
tags (1) ──< question_tags >── (N) questions
questions (1) ──< assignment_questions >── (N) assignments
students (1) ──< student_assignments >── (N) assignments
student_assignments (1) ──< (N) student_answers >── (1) questions
```

## 五、OCR 管线设计

### 5.1 整体流程

```
物理试卷 → 拍照/扫描 → 图片预处理 → 文字OCR + 公式OCR → 题目拆分 → 人工校对 → 入库
```

### 5.2 详细步骤

**Step 1: 图片预处理**
- 去噪、二值化、透视矫正（OpenCV）
- 如果是整张试卷，先按题号分割区域

**Step 2: 双通道 OCR**
- 文字通道：百度OCR API 识别普通文字
- 公式通道：pix2tex 本地模型识别数学公式，输出 LaTeX
- 合并：按位置坐标将文字和公式拼接为完整题干

**Step 3: 题目自动拆分**
- 规则：识别题号模式（"1."、"2."、"（1）"等）
- 按题号分割为独立题目
- 自动判断题型（含选项→选择题，含"求/计算"→计算题）

**Step 4: 人工校对界面**
- 左侧：原图预览
- 右侧：识别结果编辑器（TipTap + KaTeX）
- 公式部分高亮显示，可一键修正
- 校对完成后确认入库

### 5.3 OCR 方案对比

| 方案 | 文字识别 | 公式识别 | 成本 | 推荐阶段 |
|------|---------|---------|------|---------|
| 百度OCR + pix2tex | 好 | 中等 | 免费（ pix2tex 本地部署） | MVP |
| Mathpix API | 极好 | 极好 | ~$0.01/张 | V1.5（预算允许时升级） |
| PaddleOCR（全本地） | 中等 | 不支持 | 免费 | 备选（离线场景） |

## 六、核心技术难点与方案

### 6.1 题目内容结构化存储

**问题**：一道物理题可能包含文字、公式、图片、表格，结构不固定。

**方案**：使用 JSONB 存储富文本结构化数据，前端用 TipTap 编辑器渲染。

```json
{
  "stem": {
    "type": "doc",
    "content": [
      {"type": "paragraph", "content": [
        {"type": "text", "text": "一质量为 "},
        {"type": "math", "latex": "m = 2\\text{kg}"},
        {"type": "text", "text": "的小球从高 "},
        {"type": "math", "latex": "h = 5\\text{m}"},
        {"type": "text", "text": "处自由下落，求落地时的速度。"}
      ]},
      {"type": "image", "src": "/uploads/q123_fig1.png"}
    ]
  }
}
```

### 6.2 多标签筛选查询

**问题**：老师需要按"知识点 + 难度 + 题型 + 来源"多维度交叉筛选。

**方案**：后端动态构建 SQL JOIN 查询，利用 PostgreSQL GIN 索引加速。

```sql
SELECT q.* FROM questions q
JOIN question_knowledge_points qkp ON q.id = qkp.question_id AND qkp.knowledge_point_id IN (15, 23)
JOIN question_tags qt ON q.id = qt.question_id AND qt.tag_id IN (3, 7)
WHERE q.subject = 'physics'
  AND q.difficulty = 2
  AND q.type = 'choice'
GROUP BY q.id
HAVING COUNT(DISTINCT qkp.knowledge_point_id) = 2
   AND COUNT(DISTINCT qt.tag_id) = 2;
```

### 6.3 智能组卷算法

**问题**：给定知识点分布、难度比例、总分，自动从题库中选题组卷。

**方案**：贪心 + 回溯算法。

1. 按规则计算每个"题块"需要几道题（如：选择题10道×4分=40分）
2. 对每个题块，按知识点+难度筛选候选题池
3. 贪心选题：优先选未被近期使用过的题目
4. 若候选不足，放宽条件（降低一个难度档）
5. 校验总分是否匹配，不匹配则回溯替换

### 6.4 客观题自动批改

**问题**：选择题、填空题需要自动判分。

**方案**：
- 选择题：直接比对选项字母
- 填空题：字符串标准化（去空格、统一大小写）后比对，支持多个可接受答案
- 主观题：标记为"待手动批改"，老师在批改界面打分

## 七、开发计划

### Phase 1: MVP（核心闭环，约 4-6 周）

| 周次 | 交付内容 |
|------|---------|
| W1 | 项目搭建：Vue 3 + FastAPI + PostgreSQL 脚手架，数据库建表 |
| W2 | 题库 CRUD + 手动录入（TipTap + KaTeX 编辑器） |
| W3 | 知识点树管理 + 标签体系 + 多标签筛选 |
| W4 | 组卷引擎（手动选题 + 作业创建发布） |
| W5 | 学生管理 + 作业提交 + 客观题自动批改 |
| W6 | 联调测试 + 界面优化 + 部署上线 |

**MVP 验收标准：**
- 老师能手动录入题目，打知识点标签
- 能按标签筛选题目，手动组卷发作业
- 学生能在线作答，客观题自动批改
- 老师能查看学生成绩

### Phase 2: V1.5（OCR + 学情分析，约 3-4 周）

- OCR 扫描录入（百度OCR + pix2tex）
- 试卷自动拆题
- 学情统计看板（成绩曲线、知识点掌握度雷达图）
- 作业模板保存与复用

### Phase 3: V2（智能化，约 3-4 周）

- 智能组卷算法（按规则自动生成）
- 错题本（自动收录 + 复习推荐）
- 薄弱知识点智能推题
- 数据导出（Excel 成绩单）

## 八、部署方案

### MVP 阶段（单机部署）

```
服务器（个人电脑 / 云服务器）
├── Nginx (反向代理 + 静态文件)
├── FastAPI (uvicorn, 端口 8000)
├── PostgreSQL (端口 5432)
└── 本地文件存储 (/data/uploads/)
```

- 前端 `npm run build` 生成静态文件，Nginx 托管
- 后端 uvicorn 启动，Nginx 反向代理 `/api/*`
- 数据库本地安装，定期 pg_dump 备份

### V2 阶段（如需扩展）

- Docker Compose 容器化部署
- MinIO 替代本地文件存储
- 如有公网访问需求，加 HTTPS 证书
