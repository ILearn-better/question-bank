> `GradeMarkLayer.js`（两页共用的画笔层）、`StudentDetail.js`（批改后作业查看）的全量阅读。
> 本文只定**范围与约束**，不含实现代码。

## 一、一个技术前提（决定实现方式，不能跳过）

**卷面是位图（PNG/JPG），不存在「Google 文档查看器那种 iframe 嵌入」。**

- 「批改后作业查看」的嵌入观感来自 `StudentDetail.js:847-850`：
  一个 `<iframe height:72vh>`，里面是 **Chrome/Edge 自带的 pdf.js 阅读器** ——
  灰色工具条、页码、缩放、旋转、下载、打印**全部是浏览器提供的**，`app.css` 控制不到，也抽不出来复用。
- 同一文件 `:845-846` 图片走的是 `<img style="max-width:100%">`，`:245` 的注释写明
  「Word/Excel/压缩包一律只给下载 —— 拖进 iframe 只会是白屏」。
- 全仓库 `requestFullscreen` / 自研 `zoom` 零命中 → **项目没有任何自研缩放/翻页/全屏能力**。

**所以「类似嵌入」的准确含义只能是**：把卷面放进一个**自带视口、自带滚动的查看器面板**里，
呈「灰底 + 居中的一页 + 面板自己滚」的文档观感；工具栏在面板**外面**。
这恰好和「修工具栏滚走」是同一个结构问题，可以一次做完。

⚠️ 不做的事（避免误期）：不给图片套 iframe；不引第三方文档查看器；不假装支持缩放倍率
（当前翻页是「换 URL」`HomeworkGrade.js:1787-1789 → :789`，不是滚动翻页）。

## 二、三个问题的根因（都定位到行）

### 2.1 工具栏滚走 —— 滚动容器套错层，不是 CSS 冲突

| 事实 | 位置 |
|---|---|
| `.grade-left` 同时是 `position:sticky` + `max-height:calc(100vh-24px)` + `overflow:auto` | `app.css:728` |
| 工具栏 `.grade-tools` 是纯 static，无 sticky/fixed | `app.css:859-867` |
| **工具栏和卷面是同一个滚动容器里的相邻兄弟节点** | 工具栏 `HomeworkGrade.js:1805`，卷面 `:1921` |
| 窄屏 ≤1180px 时 `.grade-left` 变 `overflow:visible`，工具栏彻底随整页滚走 | `app.css:840-843` |
| 祖先链（`.layout`/`.content`/`.card`/`.grade-wrap`）**没有** transform/filter/will-change → sticky 技术上可用 | 已排查，见 `app.css` |

**结论**：技术手段没问题，问题是结构 —— 工具栏被放进了它本该悬停其上的那个滚动区里。
对照 `workbench.html` 的做法就能看出差别：工具条在 `el-card` 的 `#header`（`:710-766`），
**只有页面堆**进 `max-height:70vh; overflow:auto` 的滚动框（`:815`），所以工具条天然不被滚走。

⚠️ 注意 `app.css:725-727` 的源码注释是硬约束：**不许给卷面图片设 max-height**
（标注层按容器等比铺，单独限高会让标注和卷面对不上）。高度只能管在**外层容器**上。

### 2.2 画笔闪烁 / 笔尖消失 / 精度不足

`GradeMarkLayer.js` 是两页**共用**的同一个组件（`HomeworkGrade.js:37/107/1925`、
`workbench.html:872-877`），所以这些毛病在两个页面**同时存在**。

| # | 机制 | 位置 |
|---|---|---|
| 1 | 每次 `pointermove` 都改组件级 `ref` → **整层 render 重跑**，`shapesFor(marks)` 每帧被调**两次**（SVG 列表 + 文字标签），每次全量重建**全页所有标注**的 points 字符串 | `draft` ref `:219`；move `:486`；两次调用 `:654` / `:708`；重建 `:157` |
| 2 | **没有 rAF 合帧、没有 `getCoalescedEvents()`** → 高采样率笔/120Hz 手写的中间点全丢，一帧只取最后一个点 | 全 `src/` 零命中 |
| 3 | 抽稀门槛 `MIN_STEP = 2.2` 用的是**归一化单位（0~1000）而非屏幕像素** → 各向异性（x/y 比例不同），且页图越大丢得越狠 | `:173` 判定在 `:484` |
| 4 | **落笔首点不渲染**（`v-if="draft.length > 1"`）→ 按下瞬间笔尖是空的 | `:701` |
| 5 | **超过 900 点后 move 直接丢弃** → 长笔画到后段「笔尖停住」 | `:485` |
| 6 | `pointercancel` 被当成抬手 → 掌托/系统手势介入时半条笔迹被提前收掉 | `:624 → :516` |
| 7 | **预览与成品线宽语义不同**：预览 `.gmark-draft` 没有 `vector-effect:non-scaling-stroke`（3 是 viewBox 用户单位，被非等比拉伸）；成品有（恒定 3 CSS px）→ 松手瞬间线宽变 | `app.css:1016-1019` vs `:746/1015` |
| 8 | **预览精度 0.1 单位，落库整数单位**（`Math.round`）→ 松手跳一下 | `:599`（r1）vs `markGeom.js:71-77` |
| 9 | 松手后 key 从 `mk-local:xxx` 变成 `mk-12345` → Vue **销毁旧节点、新建一个**，与 #7 #8 叠在同一帧 | `:134`、`HomeworkGrade.js:1200-1209` |
| 10 | 批改跑时每 2 秒 `load(true)` 整体替换 `detail` → 周期性整层重建 | `HomeworkGrade.js:45 / :1031 / :1049` |

**结论**：#1 是「抖」，#4 #5 #6 是「笔尖消失」的三个独立成因，#7 #8 #9 是「松手跳一下/线变粗」，
#3 是「细处不平滑」，#2 是「快写变成折线弦」。

### 2.3 快捷键

| 页面 | 现状 |
|---|---|
| `workbench.html` | 只有 `Ctrl/Cmd+S`（`:1884`，输入框里也拦，防浏览器弹「保存网页」）、`Ctrl/Cmd+Z`（`:1891`，输入框内让给浏览器 `:1890`）；`Ctrl+Shift+Z` **明确不做**（`:1892` 注释「重做还没做，别假装支持」）；无 `Ctrl+Y`、无 `Esc`、**无任何单键工具切换** |
| `HomeworkGrade.js` | **一个都没有** —— 全文件只有 textarea 上的 `@keydown.ctrl.enter`（`:2128`） |
| 撤销栈（仅 workbench） | 操作记录栈（`add` / `erase` 两种），上限 50（`:1869`），只管笔迹增删，**不管分割线/框选/拖动**；不持久化，切作业清空（`:2653`） |

**结论**：两个页面的快捷键覆盖是 2 : 0，且 workbench 的 `typing` 白名单（`:1876`）是可复用的正确做法。

### 2.4 顺带查实的现状：「查看模式」目前**不存在**

- `tool === 'view'` 只是一个**工具态**（`HomeworkGrade.js:145`），不是只读模式：
  工具栏**永远渲染**（`:1805-1826`，无 `v-if`、无 `:disabled`），只有「撤销/清空」按标注数量置灰。
- `grep "只读|readonly|readOnly"` 在 `HomeworkGrade.js` **零命中**；`addMark`/`eraseMarks` **不看** `detail.status`。
- 因此「查看模式下不许画」必须**新增**，不能靠现有开关。

### 2.5 文本框（第 4 条）：现在不是「框」，是一个不可调的单行标签

| 事实 | 位置 |
|---|---|
| 文字标注渲染成一个 `<span class="gmark-label">`，**纯 HTML 文本，不是 SVG** | `GradeMarkLayer.js:708-714` |
| 宽度靠内容撑：`white-space:nowrap` + `max-width:46%` + `overflow:hidden` + `text-overflow:ellipsis` → **超长直接被省略号截掉，看不见全部** | `app.css:756-762` |
| 定位只用**一个点**：`label: { left: pct(x), top: pct(y) }`，配 `transform: translate(0,-100%)` 让盒子浮在点上方 | `GradeMarkLayer.js:165`、`app.css:756` |
| 存库 `geo` 是**零面积点** `[x, y, x, y]` → 尺寸根本没进库 | `HomeworkGrade.js:1320` |
| 能拖位置（`MOVE_KINDS` 含 `'text'`、`MOVE_MODES = ['view','text']`），但**没有任何 resize 能力** | `GradeMarkLayer.js:176`、`:275` |
| 输入是点一下弹 3 行 textarea，`Ctrl+Enter` 放上去 | `HomeworkGrade.js:1310-1320`、`:2123-2133` |

**好消息：不用改表。** `geo` 本来就是 4 个 0~1000 整数，`geo=[x1,y1,x2,y2]`
天然能表示矩形，文本现在只是把后两点填成了和前面一样的点。
`grade_store.py:2486` 的 update 分支已支持改 `geo` → **零迁移、零新字段**。

⚠️ **不能拿 `width` 字段存框宽** —— 那个字段是**笔迹粗细**（`grade_store.py:2412` clamp 0~200，
`_item_dict` 里 `"width": float(m.width or 0)`），语义不同，混用会让笔迹粗细跟着一起坏。

**resize 用手柄还是 CSS `resize`？** 选手柄（右下角一个小方块，`setPointerCapture` 拖拽）：
① 宽高必须回写 `geo` 的 0~1000 单位，手柄能直接复用 `pagePoint`/`clampUnit` 口径；
② CSS 原生 `resize` 在 `absolute + transform: translate(0,-100%)` 的元素上行为不稳，
且它给的是 CSS px，还得再折回归一化坐标。

## 三、目标形态

```
┌─ 页面头部（不动）────────────────────────────────┐
├─ 状态卡 / 判定依据（不动）──────────────────────┤
└──────────────────────────────────────────────────┘
┌─ 卷面查看器（新增容器，固定视口）───────────────┐
│ ┌── 工具栏（sticky top:0，在滚动区之外）──────┐ │  ← 永远可见
│ │ 选择 画笔 橡皮 文字框 √ × 分割线 框题 | 颜色 | 撤销 │ │
│ └──────────────────────────────────────────────┘ │
│ ┌── 视口（灰底，自身 overflow:auto）──────────┐ │
│ │        ┌──────────────┐                    │ │  ← 只有这里滚
│ │        │  一页卷面    │  ← 图片 + 标注层   │ │
│ │        └──────────────┘                    │ │
│ └──────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────┘
```

- **查看器容器**：`position:relative; height: calc(100vh - 头部高度); background: 页背灰; overflow:auto`
- **页框**：`width:100%; height:auto`（沿用 `app.css:733`，**不改**），居中
- **标注层**：`.gmark-layer { position:absolute; inset:0 }` 相对**页框**（不是视口），沿用现状
- **工具栏**：移出滚动区，`position:sticky; top:0; z-index:20`（高于标注层）

## 四、改动范围（批改 / 查看 两种模式）

### 4.1 两种模式怎么定义（判据必须唯一出处）

新增**唯一判定**（建议放在 `src/gradeMode.js`，两页共用）：

| 模式 | 判定条件 | 表现 |
|---|---|---|
| **批改** | `status ∈ {queued, reviewing, failed}` 且 `!done`，或 URL 显式 `?edit=1` | 工具栏可用；标注层 `mode` 跟随 `tool`；可画/擦/撤销 |
| **查看** | 已确认（`done` / `confirmed` / 归档）或 URL 显式 `?view=1` | 工具栏**渲染但全部 disabled**（不隐藏，避免布局跳动）；标注层 `mode='view'`；一切写请求不发 |

> 为什么「禁用不隐藏」：隐藏会让视口高度突变、卷面跳位，且老师会以为功能没了。
> 为什么判据要一处：`HomeworkGrade.js:822-823` 已有 `setupEditable` 这种局部判断，
> 再散出第二个「能不能改」必然分叉。

## 五、交互一致性要求（硬约束，逐条可验收）

1. **组件唯一出处**：卷面渲染只走 `GradeMarkLayer.js`，**禁止**出现第二套画笔实现（现在已经是这样，必须保持）。
2. **预览 = 成品**：`.gmark-draft` 与 `.gmark .shape.ink` 必须同为 `vector-effect:non-scaling-stroke`，
   同一笔在松手前后**线宽不得变化**；精度不得在松手时从 0.1 单位降到整数（要么都整数、要么都保留 1 位）。
3. **坐标唯一出处**：`markGeom.pagePoint()` 是唯一换算口，x/y 分别按容器宽高归一化到 0~1000；
   两页、两模式都用它，**不许**在别处再写一遍 `(clientX-left)/width*1000`。
4. **快捷键一套表**：`gradeKeys.js` 是唯一出处，两个页面 `import` 同一份；
   **所有**按键必须先过 `typing` 白名单（`INPUT`/`TEXTAREA`/`contentEditable` 一律放行给浏览器），
   唯一的例外是 `Ctrl+S`（要拦，否则浏览器弹「保存网页」）—— 这条现在 workbench 就是这么做的，保持。
5. **工具栏同序同义**：两页的按钮顺序、图标、分组一致（分割类 → 手写类 → 颜色 → 撤销 → 粗细 → 保存）；
   同名单键在两页对应同一工具。
6. **撤销语义一致**：同为操作记录栈、上限 50、失败退栈、切作业清空；
   查看模式下撤销按钮 disabled 且不发请求。
7. **查看模式只禁写不禁看**：工具栏 disabled 而**非隐藏**；标注层 `mode='view'`；不发起任何 `POST/PATCH/DELETE`。
8. **只读判定唯一出处**：`gradeMode.js`；其它地方一律不许再用 `status` 自行推断「能不能改」。
9. **窄屏不退化**：≤1180px 时（现 `app.css:840-843` 会把 `.grade-left` 改成 `overflow:visible`），
   查看器与工具栏必须仍然成立，不能因为断点切换又回到「工具栏随整页滚走」。
10. **文本框尺寸两模式同源**：宽高只存在 `geo` 的四元组 `[x1,y1,x2,y2]`（0~1000），**不用 `width`**（那是笔粗）；
    批改模式可拖右下角改尺寸，查看模式按库里的 `geo` 原样渲染 —— 同一份标注在两处**宽高必须一致**。
11. **文本不得静默截断**：现在是 `white-space:nowrap` + `max-width:46%` + `ellipsis`，
    长批注会被省略号吃掉且无任何提示。改后要么换行显示完整，要么由老师调大框；
    **不许**再出现「存进去了但看不见全」而界面不提示的情况。

## 六、验收方式（按项目既有纪律）

- 新增 `frontend/grade_keys_check.js`：断言两页 `import` 同一份映射、`typing` 白名单覆盖三种元素、
  `Ctrl+Z` 在输入框内不被拦截。
- 扩展 `frontend/math_render_check.js` 之外另建 `frontend/grade_ui_check.js`：
  断言 `.gmark-draft` 与 `.gmark .shape.ink` 都带 `vector-effect`；断言工具栏不在滚动容器内（结构断言）；
  断言 ≤1180px 分支里没有把工具栏重新扔回 document 流。
- **反向断言**：故意去掉 `vector-effect` / 把工具栏挪回滚动容器 → 对应断言必须变红
  （本轮已确立的规矩：回归里必须有一个「能变红」的证明，否则全绿和空转长得一样）。
- 真浏览器验证（本机 Edge + CDP，零下载）：画一笔看松手前后线宽/位置是否跳；滚到页底看工具栏是否还在。

## 七、分期

| 期 | 内容 | 理由 |
|---|---|---|
| **P0** | 工具栏移出滚动容器 + 查看器容器；`.gmark-draft` 补 `vector-effect`；首点渲染；去 900 点上限；**文本框改可调宽高（复用 `geo`，加右下角手柄，去掉 `nowrap`+省略号）** | 全是小改、风险低、老师每天都能感知 |

**合帧这套的反向验证（6/6 必须红，事实也全红了）**：
① 退回「每次 move 就 flush」② 抽稀退回归一化单位 ③ 松手不 `flushDraft`（尾巴断）
④ `onCancel` 把 `resetInk()` 挪到清草稿之后 ⑤ 去掉 `getCoalescedEvents` ⑥ `shapesFor` 去缓存。

### 三件必须记住的（都踩过）

1. **`resetInk()` 的调用点比它的实现重要**：只有实现不接线，松手后 rAF 还在飞，
   下一笔会把上一笔的残留点一起画出来；`onCancel` 里顺序反了（先清草稿再掐 rAF）则
   残留笔迹会在下一帧「自己冒回来」。两处调用点各有一条断言守着。
2. **`onUp` 必须先 `flushDraft()` 再 `emit`**：合帧意味着松手那一刻最后一帧的点还躺在
   `pendingPts` 里，直接清 = 每一笔尾巴都缺一小截。
3. **`inkLastPx` 不清会吃掉下一笔的起手**：老师连着写两个字，第二笔第一点往往离
   上一笔收笔处不到 1.6px，会被判成「太近」丢掉 → 看着像「起笔不显形」。
