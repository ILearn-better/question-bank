# shike-doc · 文档转 Markdown

三件事按"目标"分岔，别混：

| 用户想要 | 走哪条 |
|---|---|
| 只看内容 / 存成一个 `.md` 文件 | **本地直调** `doc_to_note.to_markdown()`，不用起服务 |
| 存成拾课里的一篇笔记（带原件、能在笔记里检索/标注） | `POST /api/notes/import-doc` |
| 把这份卷子变成题库里的题 | 不是本 skill → `shike-ingest` |

---

## 1. 什么时候用我

- 「把这个 docx 转成 markdown，我看看内容」
- 「这份 PDF 的文字提出来给我」
- 「这份备课资料导进拾课的笔记里」
- 「PPT 里的提纲转成文字，我要改一版」
- 「帮我看看这份讲义都讲了什么」（读 + 摘要，不落盘）

## 2. 什么时候别用我

| 用户其实想要 | 该去哪 |
|---|---|
| 这份卷子的题要进题库、以后能出卷 | `shike-ingest`（识别成题 + 知识点挂树 + 出卷可用） |
| 按条件组一份新卷子 | `shike-paper` |
| 只想看某张图片里的内容 | 本 skill 不支持图片（`422`）；让用户把图贴进笔记，或走 `shike-ingest`（视觉模型能读图） |

**一句话分清**：转 md 只是"拿到文字"，**不入库、不拆题、不挂知识点、不能出卷**。
同样一份卷子，要"能出卷"就必须走 `shike-ingest`，走我这边拿到的只是文字稿。

## 3. 输入

| 项 | 必填 | 缺了怎么办 |
|---|---|---|
| 文件路径 | ✅ | 缺了问；只有文件名就问完整路径 |
| 目标（看 / 存 .md / 存笔记） | ✅ | 缺了问一句：「只是看看，还是存成笔记？」—— 这决定走哪条路 |
| 笔记目录 folder_id | ⭕ | 存笔记时不传就落「未归档」 |

支持的扩展名（`file_text.KINDS`）：
`.pdf` `.docx` `.doc` `.rtf` `.pptx` `.ppt` `.txt` `.md` `.html` `.htm`
- `.doc` / `.rtf` / `.ppt`（旧格式）→ 需要**本机装了 Word**（先用 Word 转 PDF 再抽）；没装就报错，
  让用户「在 Word 里另存为 .docx / .pptx」。
- **图片（png/jpg/…）不行** → `422`「图片请直接贴进笔记」。这不是失败，是这种文件没有文字层。

## 4. 调用步骤

### 路 A：只看内容 / 存成 .md（不起服务，推荐）

```bash
cd "<仓库>/backend"
.venv/Scripts/python.exe -c "
import sys, json
sys.path.insert(0, '.')
from pathlib import Path
from app.services import doc_to_note

src = Path(r'D:/讲义/第三章.docx')
r = doc_to_note.to_markdown(src, src.name)
md = r['markdown']
out = Path(r'D:/讲义/第三章.md')
out.write_text(md, encoding='utf-8')

print('类型:', r['kind_cn'], '字数:', r['chars'], '图片:', r.get('images', 0),
      '页数:', r.get('pages'), '扫描件:', r.get('scanned', False))
print('警告:', r['warnings'] or '无')
print('落盘:', out)
"
```

返回结构（**这就是全部可信信息，别自己猜**）：

| 字段 | 含义 |
|---|---|
| `markdown` | 转出来的正文（Markdown） |
| `kind_cn` | `Word` / `PDF` / `PDF（扫描件）` / `PPT` / `HTML` / `文本` / `Markdown` |
| `chars` | 正文字数（**不是原文字数**） |
| `images` | 落进笔记资源目录的图片张数 |
| `warnings` | **失真清单，必须原样念给用户**（见第 6 节） |
| `pages` | PDF/PPT 的页数（有才有） |
| `scanned` | `true` = 扫描件，正文其实是"每页一张图" |

> ⚠️ 这条路会**把文档里的图片写进 `backend/data/uploads/notes/`**（`nb_xxxx.png`）。
> 纯文字文档没有副作用；带图 / 扫描件会留下图片文件，但不会有笔记引用它们。
> 如果用户在意"别往库里塞东西"，就走路 B（笔记是这些图片的主人），或者提前说清这一点。

### 路 B：存成拾课笔记（带原件）

```bash
# multipart 上传，单文件上限 60MB。folder_id 可选（不传落「未归档」）
curl -X POST "$SHIKE_BASE/api/notes/import-doc?folder_id=3" \
  -F "file=@D:/讲义/第三章.docx"
```

```json
{"id":"238498a37d2e","title":"第三章导数","folder_id":3,"chars":902,
 "original":"nb_5132cf0c7170.docx","images":0,"warnings":[],"kind_cn":"Word"}
```

- 笔记正文 = 一段「来源 + 失真警告」引用块 + 转出来的 Markdown。原件也存下来了
  （`/api/notes/files/nb_xxx.docx`），Markdown 是"能读的那部分"，原件是"一定没丢的那部分"。
- 服务没起 → 同 `shike-ingest` 第 0 步探端口；**不要自己起服务**。这条路必须服务在跑。

## 5. 输出（给用户看什么）

```
《第三章导数.docx》已转成 markdown：902 字，0 张图，无失真警告。
文件：D:\讲义\第三章.md
（1 处表格已转成 Markdown 表格；公式保留为文字形式，没有转成 $…$ ）
```

或（扫描件）：

```
《扫描版样例卷.pdf》：这份 PDF 没有文字层（扫描件），已按页转成图片（1 页）。
→ 拿到的不是文字，是图片：不能搜索、不能复制，但能在笔记上直接标注。
警告原文：这份 PDF 没有文字层（扫描件或图片导出），已按页转成图片存进笔记 ——
         图片不能搜索/不能复制文字，但可以直接用画笔在上面标注
```

**规矩：`warnings` 一条都不能省，也不能只报"成功"。** 用户拿这份 md 去做别的事，
不知道哪里失真就会踩坑。

## 6. 失败怎么报（以及失真怎么说）

### 失真（不是失败，但必须说）

| `warnings` 里的原文 | 什么意思 | 怎么跟用户说 |
|---|---|---|
| 文档里有 N 处公式，只保留了它的文字形式，没有转成可编辑的公式 | Word 的 OMML 公式**没有转成 `$…$`**（反向 XSLT 没做） | 「N 处公式只剩文字，符号可能残缺；要能用的公式得走入库那条路（视觉模型会输出 LaTeX）」 |
| 文档里有 N 张外链图片没有存进来（本机不联网） | Word 里引用的是网络图片 | 「N 张网络图没取回来，重要的请手动截图」 |
| 页面里有 N 张外链图片没取回来（本机不联网），已保留成链接 | HTML 里的图只留了 URL | 同上 |
| 有 N 页没有文字层（图片页），这些页的内容没有转成文字 | PDF 混排（部分页是扫描的） | 「第 X 页这类图片页只留了空白/跳过，那几页的题要单独处理」 |
| 这份 PDF 没有文字层… 已按页转成图片存进笔记 | 整份是扫描件 | 说清"你拿到的是图，不是字" |
| 共 N 页，只转了前 40 页 | 扫描件上限 40 页 | 「后面 N 页没转，需要的话分成几个文件」 |
| 内容太长，已截断到 30 万字 | 超过 `MAX_CHARS=300000` | 「正文被截到 30 万字，后面的没进来」 |
| 旧格式（.doc/.rtf）先由本机 Word 转成 PDF 再导入 | 走了 Word COM | 顺带说明：排版会按 PDF 走 |

### 失败

| 现象 | 该说的话 | 下一步 |
|---|---|---|
| `422 这篇笔记暂时不能从这种文件导入（.png）` | 「图片不能用这个入口。把图直接贴进笔记（Ctrl+V），或者要读图里的题就走入库」 | 换路 |
| `422 文件太大了（超过 60MB）` | 「超过 60MB 了」 | 拆分/压缩 |
| `DocImportError: 这个 Word 文档里没有文字（内容可能全是图片截图）` | 「这份 Word 是纯图片，没有文字层」 | 走入库（视觉模型）或另存 PDF 再看 |
| `这个 .docx 里找不到正文（文件可能损坏）` / `不是有效的 .docx` | 「文件可能损坏或没下载完整」 | 重新导出 |
| `读不了这个旧格式文件：…` | 「这台机器没有 Word，旧格式转不了」 | 让用户另存为 .docx |
| `这个 PDF 里没有内容` | 「PDF 打开后一页都没有」 | 换个文件 |
| 扫描件转出来只有图片 | 见上文 | — |

## 7. 边界与陷阱

**不做**：不识别题目、不拆题、不挂知识点、不生成 `$LaTeX$` 公式、不 OCR 图片（没有 OCR 引擎）、
不能读图片文件本身。

**已知坑（都实测过）**

1. **电子版 PDF 的文字层对公式是废的 —— 这条必须对用户说清。**
   实测 2025 高考数学 PDF：`$\{x \mid x<9\}$` 被抽成 `\uf07b … \uf07d … U x x` 这种私有区字符
   （Symbol 字体映射丢失），分数和根号的内容顺序也乱了。**看起来"有文字"，但公式全是坏的。**
   → 要公式就得走 `shike-ingest`（视觉模型按页识别，输出 `$…$` LaTeX），或者人工校。
2. **Word 的 OMML 公式只留文字**（`warnings` 会写「N 处公式…只保留了它的文字形式」）。
   这就是 `doc_to_note` 与"入库识别"的本质区别。
3. **`file_text` 不是给这个用的。** 它是"给 AI 看的纯文字"：上限 `MAX_CHARS=20000`、
   无结构、无 `warnings`、连表格加粗都丢。要做 md 一律用 `doc_to_note`（上限 30 万字、有警告）。
4. **图片文件会被拒**（`422`），不是静默当空文档 —— 图片本来就没有文字层。
5. **扫描件是多页图片**：`images` = 页数，`chars` 只有那点"第 N 页"的字，别把 `chars` 当内容长度报给用户。
6. **旧格式（.doc/.rtf/.ppt）依赖本机 Word**，而且转成 PDF 后走 PDF 那条路 —— 公式同样是坏的文字层。
7. **电子表格 / Excel 不支持**（不在 `KINDS` 里）。
8. `.html` 走的是"够用子集"转换器：`<script>/<style>` 丢掉、`<table>` 转 md 表格、列表转 `-`/`1.`；
   复杂 CSS 布局（多栏、浮动）**还原不了**，顺序可能与网页上看到的观感不同。
9. 路 A 的脚本必须 `cd backend` 再跑（`config.NOTES_DIR` 是相对 backend 解析的），
   并且用 `backend/.venv/Scripts/python.exe`（依赖 `lxml` / `pymupdf` 都在这个 venv 里）。
