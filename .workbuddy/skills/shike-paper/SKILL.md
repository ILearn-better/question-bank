# shike-paper · 组卷 / 出讲义

**没有"按条件自动选题"的接口。** 组卷 = 我先检索出候选 → 人确认 → 再用 id 列表导出。
这条顺序不能省：`GET /api/papers/export` 只吃 `ids`，它不知道"导数"是什么。

---

## 1. 什么时候用我

- 「按这份要求组一份高二期中卷，导数为主，选择 8 道、解答 4 道」
- 「找 10 道中档的解析几何题出一张卷子」
- 「把这些题排成一份学生版，明天印」
- 「做一份讲义，导数应用的，带答案」
- 「上次那份卷子再出一版，换掉最后两道」

## 2. 什么时候别用我

| 用户其实想要 | 该去哪 |
|---|---|
| 把这些题录进库 | `shike-ingest` |
| 只想看看到底有哪些题（不出卷） | 只跑本文第 3 步的检索，把清单给他，**不要导出** |
| 只想看某道题的完整内容 | `GET /api/questions/{id}`（或 `/questions/search?keyword=`） |
| 想把题贴进笔记里 | 笔记页的「插入题目」（`POST /api/notes/question-block`） |

## 3. 输入

| 项 | 必填 | 缺了怎么办 |
|---|---|---|
| 知识点 / 范围 | ✅ | 缺了问：「这份卷子考哪几章 / 哪几个知识点？」 |
| 题数与题型 | ✅ | 缺了问：「选择几道、填空几道、解答几道？」—— 或者只给总数，那我按 6:2:2 提议、**要人点头** |
| 难度配比 | ⭕ | 缺了默认「基础:中档:拔高 = 3:5:2」，但要在清单里说明这是默认 |
| 用途（月考/期末/讲义/作业） | ⭕ | 影响标题与是否留作答空白；缺了问一句 |
| 输出格式 | ⭕ | 默认先出 **HTML**（预览最快、公式最好看），要打印再转 PDF |
| 卷种模板 | ⭕ | 默认不套模板（朴素卷面）。用户说"像高考卷那样"→ 用 `template_id=1` |
| 学生版 / 教师版 | ✅ | **默认教师版（带答案）**。要给学生印必须显式确认 → `show_answer=false` |

**知识点名要用库里真有的写法**，别自己造。先看两个接口的真实取值：

```bash
curl "$SHIKE_BASE/api/questions/knowledge-points?curriculum_id=3"   # 题库里实际用过的知识点 + 次数
curl "$SHIKE_BASE/api/questions/tags?curriculum_id=3"              # 实际用过的标签 + 次数
curl "$SHIKE_BASE/api/tree?curriculum_id=3"                       # 该体系的知识树（label 是层级路径）
```

用户说的"导数"如果不在上面，就别硬搜 —— 告诉他库里没有这个知识点，问要不要用相近的（并说清是哪个）。

## 4. 调用步骤

### 第 0 步：探服务

同 `shike-ingest` 第 0 步（`ProxyHandler({})` 探 8000 / 8010，或直接用 `SHIKE_BASE`）。
服务没起 → 「拾课没起，双击「启动拾课.bat」」；**不要自己起服务**。

### 第 1 步：检索候选（每个题型/难度分别查，凑够数）

```
GET /api/questions/search
  keyword=        题干/答案/来源/文件名 模糊匹配
  curriculum_id=  体系 id（3 = 国内高中数学）
  node_id=        知识树节点 id（自动含整棵子树）
  kp=             知识点**名字**（子串匹配，也会带上同名节点的子树）
  qtype=          选择题 / 填空题 / 解答题 / 判断题 / 证明题 / 应用题 / 图片题（**精确匹配**）
  difficulty=     基础 / 中档 / 拔高（**精确匹配**）
  tags=           逗号分隔，**任一命中**即算
  has_image=      true/false
  with_answer=    true/false（有没有答案）
  sort=           created（默认，最新在前）/ oldest / usage（**少用的排前面** —— 组卷首选）
  limit=          1..200，默认 50
  offset=         分页
```

返回 `{"total": N, "items": [...]}`，每项关键字段：`id`、`content`（题干，`$…$` 是 LaTeX）、`qtype`、
`difficulty`、`knowledge_points`、`tags`、`score`、`answer`、`image` / `figure_image`、`usage_count`、`doc_filename`。

```bash
curl -G "$SHIKE_BASE/api/questions/search" \
  --data-urlencode "curriculum_id=3" \
  --data-urlencode "kp=导数" \
  --data-urlencode "qtype=解答题" \
  --data-urlencode "difficulty=中档" \
  --data-urlencode "sort=usage" --data-urlencode "limit=20"
```

**语义要记住的三条**（实测）：

- `qtype` / `difficulty` 是**精确相等**：`qtype=选择` 返回 0 条，且不报错 —— 别以为"没有题"。
- `kp` 是**子串 LIKE**：`kp=导` 会把"导数"的题也带出来；同时会并入同名知识树节点的整棵子树。
- `sort=usage` 把出卷次数**少**的排前面，组卷去重就该用它。

`usage_count` **相同的题**之间，返回顺序不保证（`order_by(usage_count asc, created_at desc)`，
而 `created_at` 精度到秒，同一秒建的题会并列）。**要判断某题出过几次，直接读它的
`usage_count` 字段；不要根据「它排第几」去推断"没用过"还是"用得少"。**
否则你会跟老师说出一句看起来有依据、其实没有的话 —— 比如「这五道都是没出过的，我按使用次数从少到多给你排好了」，后半句是编的。

`limit>200` → 422（detail 是数组，不是字符串）。

### 第 2 步：把候选清单给用户确认（**不许跳过**）

按题型分组，每条一行，**必须带 id**（后面要用）：

```
一、选择题（8 道，缺 2 道）
 1. de6841132570  已知集合 A={1,3,5}，求元素个数    集合·基础·未用过
 2. ...
（库里「导数·选择题·中档」只有 6 道，你要 8 道 —— 差 2 道。
  要我用「基础」补 2 道，还是减到 6 道？）
```

规矩：
- **题量不够就如实说差几道，绝不拿相近题凑数**（凑进去的题会印在卷子上，老师看不出哪道是凑的）。
- 清单里要说清每题是「基础/中档/拔高」、「用过几次」（`usage_count` 高的尽量别再出）。
- 用户改完（删/换/调顺序）再进下一步。**他调的顺序要原样保留**（分区内先后就看它，见第 3 步）。

### 第 3 步：排 ids 的顺序（**决定卷面先后**）

一句话：**ids 不用按题型预分组，但「同一分区内谁在前」完全由 ids 的顺序决定。**

套模板（`template_id`）时，服务端会按分区把题目归组（`一、选择题` → `二、填空题` → `三、解答题`），
归组后**按最终渲染顺序重新从 1 连续编号**（**跨分区连着数，不按分区重新起号** ——
第二个分区的第一题接上一个分区的最后一个号往下排）。所以：

- **不必**先按题型把 ids 排好；
- 但**分区内的相对顺序**仍是你传 ids 的顺序 —— 想让「解答题 A 在 D 前面」，ids 里 A 就得在 D 前面；
- 不套模板（不传 `template_id`）→ 不分区，ids 顺序原样印，用户的排序直接生效。

算一遍就清楚（模板分区是 选择→填空→解答）：

```
ids = [解答题A, 选择B, 填空C, 解答题D]
卷面 = 一、选择题   1. 选择B
      二、填空题   2. 填空C
      三、解答题   3. 解答题A       ← A 在 D 前面，因为 ids 里 A 在 D 前面
                   4. 解答题D
```

所以**别把这句话理解成「顺序无所谓」**：分区内还是听 ids 的。用户用「上移/下移」调过的顺序，
原样传进 ids 即可，不要自己按题型重排一遍（重排会打乱他刚调好的分区内顺序）。

分区顺序和归属看 `GET /api/paper-templates` 里那套模板的 `sections[].qtypes` / `.difficulties`。

### 第 4 步：导出

```
GET /api/papers/export
  ids=           逗号分隔，**最多 200 个**（必填）。顺序决定**分区内**先后，题号由服务端重编（见第 3 步）
  format=        html（默认，浏览器直接预览）/ docx / pdf
  title=         卷名（会进文件名，非法字符自动替换）
  template_id=   卷种样式 id；不传 = 朴素卷面
  show_answer=   true（默认）/ false
  show_analysis= false（默认，答案里带不带解析）
  show_tags=     true（默认，题号后标「题型·难度」）
  show_meta=     true（默认，姓名/班级/日期栏）
  render_mode=   auto（默认，文本优先）/ text / image（用原卷截图）
```

```bash
curl -o "导数专项_学生版.pdf" -G "$SHIKE_BASE/api/papers/export" \
  --data-urlencode "ids=f24dca6bb392,de6841132570,4435b112d45f" \
  --data-urlencode "format=pdf" \
  --data-urlencode "title=导数专项练习" \
  --data-urlencode "show_answer=false"
```

- 是 **GET 返回二进制**，所以必须 `curl -o` / `urllib` 写文件，别 `| head`。
- 文件名在 `Content-Disposition`（RFC 5987，中文可读），形如 `导数专项练习_学生版.pdf`。
- 导出会顺带把选中题的 `usage_count + 1`、写 `last_used_at`（供以后 `sort=usage` 去重）。
  → **反复试导会污染"用过几次"**，确认后再导。

卷种模板（`GET /api/paper-templates`，内置四套）：

| id | 名称 | 分区 |
|---|---|---|
| 1 | 高考数学（全国卷） | 一、选择题 / 二、填空题 / 三、解答题（含证明、应用）；带登分表与注意事项 |
| 2 | 中考数学 | 同三段，小题分值 3 分 |
| 3 | DSE 数学（英文卷） | Section A(1)/A(2)/B —— 按**难度**分（基础/中档/拔高） |
| 4 | A-Level 数学（英文卷） | 两个 Section |

模板里有 `paper`（副标题、考试说明、注意事项、姓名栏、登分表）、`style`（字号、行距、页边距、
题号形态、是否标分值、解答题留白行数）、`sections`（分区标题 + 匹配规则）。想改就复制一份再改：
`POST /api/paper-templates/copy {"source_id":1,"name":"XX 中学月考"}`（内置的不能删、能改）。

## 5. 输出（给用户看什么）

1. **候选清单**（第 2 步那张表）—— 这是给人做决定的，必须列 id。
2. 导出成功后：

```
《导数专项练习》学生版 · PDF · 12 道（选择 8、填空 2、解答 2）· 共 60 分
文件：D:\出卷\导数专项练习_学生版.pdf
预览（HTML 版，公式正常显示）：http://127.0.0.1:8000/api/papers/export?ids=…&format=html
```

格式怎么选，直接讲清（这三种不是同一份东西导三遍）：

| 格式 | 什么时候选 | 要提前说清的代价 |
|---|---|---|
| `html` | 预览、Ctrl+P 存 PDF、发给别人看 | 公式靠 CDN 的 KaTeX 渲染，**离线时 `$…$` 会原样显示**；图片已 base64 内嵌，单文件自包含 |
| `docx` | 老师要改题干、套学校抬头 | **公式不排版，`$…$` 原样印出来**（服务端没有 LaTeX 引擎） |
| `pdf` | 直接打印 | 同上，公式原样；图片会降采样到约 150dpi 控制体积 |

`show_answer=false` → 文件名带「_学生版」；`true` → 「_教师版」。**默认是教师版**，给学生印前必须确认。

## 6. 失败怎么报

| 现象 | 该说的话 | 下一步 |
|---|---|---|
| 服务没起 | 「拾课没起，双击「启动拾课.bat」」 | 不起服务 |
| `422 没有选中任何题目` | 内部错误（ids 拼空了） | 检查 ids |
| `404 有 N 道题不存在（可能已被删除）` | 「选中的题里有 N 道已经被删了，我重新拉一遍清单」 | 重跑检索、重新确认 |
| `422 一次最多导出 200 道题` | 「一份卷子最多 200 道，要不要拆成两套？」 | 拆 |
| `422 不支持的格式 doc` | 「只能出 html / docx / pdf」 | 改 |
| `422 不支持的呈现方式 pic` | 「render_mode 只能是 auto / text / image」 | 改 |
| `404 卷种样式模板不存在` | 「这套模板被删了，我列一下现在有哪几套」 | 重列模板 |
| 检索回来 `total=0` | **先怀疑筛选词写错**：`qtype`/`difficulty` 必须精确；`kp` 用库里真实名字（先查 `/questions/knowledge-points`） | 放宽条件重查，别直接说"库里没题" |
| 题量不够 | 「库里符合条件的只有 X 道，差 Y 道」 | 让人选：放宽条件 / 减题数 / 先入库新题（→ shike-ingest） |

## 7. 边界与陷阱

**不做**：不替用户决定选哪几道题、不生成新题（没有出题能力）、不修改题的内容
（要改题用 `PATCH /api/questions/{id}`）、不排版（没有分栏 / 页眉页脚 —— 真要这些请在 Word 里改）。

**已知坑（都实测过）**

1. **没有"自动组卷"接口。** 任何"按知识点自动挑 10 道"的说法，实际都是"我先检索、再让你确认、再导 ids"。
   别假装有一个 `?kp=导数&n=10` 的接口。
2. **题号由服务端按最终卷面顺序重编，不是你传的第几个。** 套分区模板时，ids 的第 3 个可能在卷面上是
   第 1 题（因为它属于「一、选择题」）。→ 想核对卷面顺序，看导出的 HTML 里 `<b>n.</b>` 后面跟的题干，
   别用 ids 的下标去对题号。反过来，**分区内的先后**完全由 ids 决定（第 3 步），这点不会自动帮你排。
3. **`show_answer` 默认 true。** 忘了关就印出教师版给学生（文件名会写着「教师版」，但没人会看文件名）。
4. **PDF / DOCX 里公式是原样的 `$…$`。** 实测导出的 PDF 文本就是 `1. 已知 $f(x)=x^3-3x$，求单调区间。`。
   要公式好看只能出 HTML 再打印；或者把题目改成图片形态（`render_mode=image`，用原卷截图）。
5. **`render_mode=image` 需要题有原貌图**（`image` 字段）。缺那种形态会自动退回另一种，不会印空白题 ——
   但"我选了图片怎么还是文字"就是这个原因。
6. **`usage_count` 会被每次导出 +1**，包括你为了确认效果多导的那几次。
7. **200 道上限**，超了是 422，不是静默截断（好在如此）。
8. **`limit>200` 的 422 结构不同**（`detail` 是数组），解析错误信息时别假设 `detail` 一定是字符串。
9. 不套模板时**不印姓名栏？—— 会印**（`show_meta` 默认 true，`fill_fields` 默认 姓名/班级/日期）。
   讲义类如果不想留填写栏，传 `show_meta=false`。
10. 没有分栏、没有页眉页脚、没有"每题固定留 N 行"以外的版式能力；`answer_space` 只对
    `解答题/证明题/应用题` 生效（由模板的 `answer_space_types` 决定）。
