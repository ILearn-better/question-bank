# shike-question-md · 试卷 → 题库格式 md（含配图）

一份 44 页的卷子，一条命令变成一个文件夹的题目 md，图和题各自就位。

**和另外两个 skill 的分工**（选错就白干一遍）：

| 用户想要 | 走哪条 |
|---|---|
| 把题**先变成 md 文件**，自己改完再点同步进库 | **本 skill** |
| 直接把这份卷子**录进题库**（识别完就入库、给审核链接） | `shike-ingest` |
| 只想知道文件里写了什么 / 存成一篇笔记 | `shike-doc` |

---

## 1. 一条命令

```bash
cd "<仓库>/backend"
.venv/Scripts/python.exe "../.workbuddy/skills/shike-question-md/scripts/doc_to_md.py" "<文件绝对路径>"
```

默认产出：

- md → `backend/data/vault/题库/`（一题一个 `.md`）
- 图 → `backend/data/vault/附件/`（`<题干前 24 字>-p页号-序号-fig.png`）

老师下一步：题库页点**同步** → 这些题进库，图进「题干配图」列。

## 2. 常用参数

| 参数 | 用途 |
|---|---|
| `--pages 1-10,15` | 只处理这几页。**先跑 2 页给人看效果**，确认没问题再跑全部 |
| `--dry-run` | 只识别不写文件。看识别质量、估一下要多久 |
| `--out DIR` | md 写到别处（默认题库目录）。`--attach` 默认取 `DIR` 同级的 `附件/` |
| `--curriculum 名称` | 体系（默认国内高中数学）。决定知识点往哪棵树上挂 |
| `--limit N` | 最多出 N 道（调试用） |
| `--overwrite` | 同名 md 已存在就覆盖（默认**跳过**，见第 6 节） |
| `--fresh` | 不用识别缓存，重新调模型 |
| `--json` | 机器可读的完整报告 |
| `--no-kp-list` | 不把知识树清单交给模型（更快，但知识点不容易挂树） |

## 3. 退出码怎么用

| 码 | 含义 | 该说什么 |
|---|---|---|
| `0` | 全部生成，没有疑点 | 「N 道题都好了，去点同步」 |
| `2` | 生成了，但**有 N 条要人看**（图没定位到 / 跨页截断 / 模型自评不确定） | 把「要你看一眼的 N 条」原样转述，逐条说清是哪种问题 |
| `1` | 没跑起来（文件读不了 / AI 未配置 / 整份失败） | 照 stderr 最后一行的原因说，别自己猜 |

`2` 不是失败。它恰恰是这个 skill 最值钱的地方：**把机械活干完，把判断留给人**。

## 4. 产出长什么样

```markdown
---
shike: question
qtype: 选择题
difficulty: 中档
knowledge:
  - 抛物线的定义与标准方程
tags:
  - 焦点弦
---
已知抛物线 $C:y^2=6x$ 的焦点为 $F$……（题干原文）

![](<../附件/已知抛物线 的焦点为 ，过 的一条直线交 于 ， 两点，过-p02-05-fig.png>)
```

三条要点，改动前先读：

1. **没有 `shike_id`**。这道题还没入库，不该有 id —— 同步时看到非空 `shike_id` 会当成「已有题」，找不到就报警。第一次同步由拾课自己写进去。
2. **图片是标准 Markdown `![](<../附件/x.png>)`**，不是 Obsidian 的 `![[x.png]]`。后者只有 Obsidian 认，Typora / VSCode 里就是一段纯文本（老师报过「导出的 md 看不到图」）。`<>` 不能省：文件名里有空格/中文会被截断。
3. **`knowledge` 写的是知识树上的节点名**，不是模型随口叫的那个。见第 5 节。

## 5. 配图与知识点：两处最容易被做坏

### 配图：模型指路 + 几何定框

模型能指出「图在这一带」，但**它的框整体偏高约 1/8 页** —— 直接用就会把上半截裁掉（箭头、坐标轴标签全没了）。所以真正的边界由 PDF 里图形元素的精确坐标定（`batch_page.plan_page_figures`）。别把这一步换成「按模型框裁」，退回去就是那个错。

**两种情况故意不配图**，而且都在报告里说清理由：

- 模型给的区域占整页 20% 以上 → 多半是把题干框进来了
- 题干里已经有 Markdown 表格，而这块区域是模型估的 → 表格已经转成文字了，再配一张表图是重复

**图在下一页**（跨页题的上半段）时定位不到 → 报告里说「多半在下一页，自己去截一张」，不要瞎配一张。

### 知识点：把树上的名字交给模型

模型爱用「导数的几何意义」「空间线面位置关系」这类叫法，而树上是「导数的概念与几何意义」「点、直线、平面的位置关系」。对不上就挂不了树，那道题在「按知识点筛题」和「掌握度统计」里等于不存在，**而且不报错**。

所以默认把该体系的节点名清单塞进识别提示词，让它照抄。实测：挂树率从 6/11 提到 9/10（剩下那条是碎片题，已由跨页合并消掉）。`--no-kp-list` 可关掉。

体系里没有知识树（DSE / A-Level / 国内初中目前节点数为 0）时清单为空，知识点存成普通文字，这是正常的。

## 6. 跨页题、重跑、缓存

**跨页题自动拼回一道。** 判据两头都要硬：上一页那条确实是该页**最后一条**、并且说了截断；下一页那条确实是该页**第一条**、并且说了延续；后半段开头**不像一道新题**（不以 `1.` `（1）` `例3` `【` 开头）。缺一条就不拼 —— 把两道无关的题粘起来读起来"像一句话"，老师发现不了。

**重跑不会造第二份。** 同名 md 已存在就跳过（报告里计进「跳过」）。这一点是硬要求：vault 里同一道题两份 md，此后**每次同步都红一条**，而老师不知道那份哪来的。要覆盖就加 `--overwrite`。

**识别结果有磁盘缓存**（`backend/data/uploads/mdconv/<源文件指纹>/pages/`）。同样的文件重跑几乎不花 AI 调用，可以放心反复调参数。改的是提示词（比如换了体系，知识树清单变了）会自动失效重认；`--fresh` 强制重认。

## 7. 报错怎么办

| 看到 | 是什么意思 | 怎么办 |
|---|---|---|
| `找不到拾课的 backend 目录` | 脚本没找到 `app/services/vault.py` | 加 `--backend "<仓库>/backend"` |
| `还没有配置 AI 接口` | 设置里没填 AI 地址/模型/密钥 | 让老师到「设置 → AI 润色」填，公式识别和整页识别共用这一份 |
| `模型返回了空内容` | 服务商不支持图片输入，或 max_tokens 被推理吃满 | 换支持识图的模型（DeepSeek 的 deepseek-flash 实测可用） |
| `这份 Word 转 PDF 失败` | 本机 WPS/Word 的 COM 打不开它 | 让老师用 WPS/Word 打开 → 另存为 PDF → 把 PDF 给过来。**不要改去解析 docx**：公式是 OMML 对象，取出来是乱码 |
| `AI 接口响应里没有找到正文` 后重试成功 | 偶发（多半是输出被推理吃掉） | 脚本已自动重试一次；连续两页都这样就换模型 |
| `[p07] 失败：…` | 这一页识别失败，其余照常 | 报告里会列出来。用 `--pages 7` 单独重跑那一页（有缓存，前面的页不重认） |

## 8. 交付时怎么说

跑完**不要**顺手去点同步、也不要改库。要说清三件事：

1. 生成了几道题、几张图，在哪个目录
2. 「要你看一眼的 N 条」逐条转述（这是老师真正需要的）
3. 下一步：题库页点**同步**（题数会 +N）；想先改就在 Obsidian 里打开 `题库/`，改完再同步

跑整份卷子前先 `--pages 1-2` 给人看一眼。44 页实测约 30 分钟（一页一次视觉模型请求），跑完才发现格式不对就白花了。

## 9. 还要注意

- **别拿真库试**。要验证「能不能入库」，用 `sqlite3.backup()` 出来的库副本 + `SHIKE_DB_PATH` / `SHIKE_DATA_DIR` / `SHIKE_VAULT` 指到临时目录（`copy2(shike.db)` 会丢 WAL 里未合并的提交）。
- 本机 `rm` 静默失效，清临时目录用 `shutil.rmtree(..., ignore_errors=True)`。
- 服务在跑不影响本 skill（它只读 AI 配置、不写库），但它跑的是哪份代码与本 skill 无关 —— 老师看到的「同步」结果取决于**服务有没有重启过**。
